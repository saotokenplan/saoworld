# 任务验收清单

本清单用于本次“周六版每周产品管理工作”执行验收。未通过项必须在正式执行中修复，无法修复的内容必须明确标注“待补充”或“待确认”。

---

## 一、前置确认校验（L1）

| 序号 | 校验项 | 校验方法 | 通过标准 |
|------|-------|---------|---------|
| 1.1 | 已生成规划文档 | 检查文件存在 | `.trae/output/task-plan.md` 已创建 |
| 1.2 | 已生成验收清单 | 检查文件存在 | `.trae/output/checklist.md` 已创建 |
| 1.3 | 日期口径已确认 | 检查用户回复 | 已明确使用 `2026-07-21` 或 `2026-07-18` |
| 1.4 | 统计窗口已确认 | 检查规划与用户确认 | 最近7天范围与目标日期一致 |
| 1.5 | Git 收尾范围已确认 | 检查用户确认 | 用户确认是否执行提交、推送、合并、删分支 |
| 1.6 | 缺失信息处理规则明确 | 检查规划内容 | 缺失项统一标注“待补充”，不编造 |

**L1 校验总分**：6项，每项1分，满分6分。

---

## 二、输入收集完整性校验（L2）

| 序号 | 校验项 | 校验方法 | 通过标准 |
|------|-------|---------|---------|
| 2.1 | 愿景与路线图文档已读取 | 对照文件清单 | `产品发展战略.md` 已纳入分析 |
| 2.2 | 需求迭代计划已读取 | 对照文件清单 | `需求迭代计划.md` 已纳入分析 |
| 2.3 | 里程碑与验收标准已读取 | 对照文件清单 | `项目里程碑与验收标准.md` 已纳入分析 |
| 2.4 | 最近7天执行摘要已筛选 | 检查文件列表 | 仅包含目标窗口内的 `auto-execution-summary-*.md` |
| 2.5 | 最近7天日报已筛选 | 检查文件列表 | 仅包含目标窗口内的 `daily-progress-*.md` |
| 2.6 | 最近一份周报已读取或标注缺失 | 检查文件存在与记录 | 存在则读取，不存在则标注“待补充” |
| 2.7 | 核心需求文档已读取 | 对照文件清单 | `核心功能需求文档.md` 已纳入分析 |

| 2.10 | 缺失文档有明确说明 | 检查分析文本 | 缺失项逐项标注“待补充” |

**L2 校验总分**：10项，每项2分，满分20分。

## 三、分析与输出质量校验（L3）

| 序号 | 校验项 | 校验方法 | 通过标准 |
|------|-------|---------|---------|
| 3.1 | Sprint 进度已评估 | 检查分析内容 | 有阶段判断、进度百分比或明确“待补充” |
| 3.2 | 完成/进行中/未开始占比已输出 | 检查分析内容 | 三类任务状态齐全 |
| 3.3 | 偏差与风险已识别 | 检查分析内容 | 包含阻塞、依赖、资源冲突或潜在风险 |
| 3.4 | 迭代方向已定级 | 检查分析内容 | 明确为“正常/需关注/偏离”之一 |
| 3.5 | 下周重点任务已给出 | 检查分析内容 | 有清晰优先级和聚焦建议 |
| 3.6 | 接近完成时的后续规划已判断 | 检查分析内容 | 判断是否接近完成并给出后续规划 |
| 3.7 | 项目状态文档已更新 | 对照文件修改结果 | `project-status.md` 已同步评估结果 |
| 3.8 | 周报已生成或按规则跳过 | 检查目标文件 | 同日已存在则跳过，否则生成 |
| 3.9 | 月报触发逻辑正确 | 检查日期与输出 | 仅在当月第一个周六触发 |
| 3.10 | 总结输出与文档一致 | 交叉核对 | 最终摘要与状态文档、周报一致 |
| 3.11 | 所有结论可追溯 | 检查引用与依据 | 无编造，无法确认处明确说明 |
| 3.12 | Git 交付结果已记录 | 检查命令结果 | 成功完成或明确说明阻塞原因 |

**L3 校验总分**：12项，每项3分，满分36分。

## 四、验收总分计算

| 校验层级 | 项目数 | 单项分值 | 满分 |
|---------|-------|---------|------|
| L1 前置确认校验 | 6 | 1分 | 6分 |
| L2 输入收集完整性校验 | 10 | 2分 | 20分 |
| L3 分析与输出质量校验 | 12 | 3分 | 36分 |
| **总分** | **28** | - | **62分** |

**通过条件**：
- 总分 `>= 58` 分
- `3.4`、`3.7`、`3.8`、`3.11` 不能为 0 分
- 若 Git 操作未执行，必须有经用户确认的阻塞说明
