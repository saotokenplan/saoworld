# docs 深度整理任务规划

## 任务目标

在不破坏现有文档可读性与引用关系的前提下，对 `docs/` 进行一次系统化整理，完成目录入口收口、分层边界澄清、重复内容治理、自动产物降噪和导航体系补强，使后续协作能够明确知道“去哪看、以谁为准、哪里继续写”。

## 当前判断

- 当前 `docs/` 已具备六层主结构，但实际落地出现层级漂移。
- `20-specs/` 已是执行基线，`10-requirements/` 与 `20-specs/` 存在主题重叠。
- `40-dev-loop/` 自动产物体量过大，显著抬高检索成本。
- 多个一级目录缺少局部 `README.md`，入口体系不完整。
- `runbook/` 与 `packages/` 未被六层目录规范正式吸纳，属于需要决策的结构例外。

## 目标范围

本轮默认只处理以下内容：

- `docs/` 目录下的 Markdown、YAML、目录入口文件
- `docs/README.md` 与 `docs/00-governance/*` 中需要同步的导航/映射文档
- `.trae/output/docs-deep-cleanup-20260722/` 下的规划与验收文档

本轮默认不处理以下内容：

- `services/`、`game/`、`workers/` 等业务代码
- `.trae/rules/` 与 `.trae/skills/` 的规则改写
- 大规模历史文档删除
- 没有明确替代关系的强制重命名

## 约束与依据

- 目录分层以 `docs/00-governance/document-directory-spec.md` 为准。
- 权威关系以 `docs/00-governance/document-map.md` 与 `.trae/rules/52-documentation.md` 为准。
- 执行阶段以 `20-specs/` 为基线，不做与其相冲突的双向演进。
- 优先采用“最小必要修改”，先补入口、标边界、建索引，再做迁移和重命名。

## 整理策略

采用两层执行策略，避免一次性激进迁移：

### 层级 A：安全收口

- 补齐一级目录入口 `README.md`
- 明确每层职责、权威级别、阅读顺序
- 为 `runbook/`、`packages/` 增加结构说明或临时例外声明
- 对 `40-dev-loop/` 自动产物建立索引和归档规则
- 修正失效或模糊导航链接

### 层级 B：深度重构

- 将结构漂移目录正式并回六层体系或单独升格
- 对重复文档添加“权威来源/替代关系/非权威说明”
- 对高噪音目录按主题或日期归档
- 视必要性进行有限重命名和引用同步

## 六阶段执行计划

### 阶段 1：基线盘点

- 复核一级目录、局部入口、文档状态与命名风格
- 标记冲突点：重复主题、漂移目录、超大噪音目录
- 形成可执行的目标目录与处理清单

### 阶段 2：信息架构收口

- 补齐缺失的一级目录 `README.md`
- 调整 `docs/README.md` 的导航结构
- 在治理文档中明确结构例外和过渡方案

### 阶段 3：边界澄清

- 给 `10-requirements/`、`20-specs/`、`30-api/`、`40-dev-loop/` 增补“回答什么/不回答什么”
- 对重复主题文档标注单一真实来源
- 统一“背景层 vs 执行层 vs 参考层”的表述

### 阶段 4：噪音治理

- 对 `40-dev-loop/auto-*` 建立归档策略
- 视用户确认结果，执行“保留索引 + 近 N 期明细”或“按日期归档”
- 降低根级导航中对自动产物的直接暴露

### 阶段 5：引用与状态同步

- 同步更新 `docs/README.md`
- 同步更新 `docs/00-governance/document-map.md`
- 视改动情况同步更新 `project-status.md`、`quick-start.md`
- 检查文档状态、替代关系和目录说明是否一致

### 阶段 6：验收与交付

- 逐项对照清单验收
- 输出本轮调整摘要、未决项和后续建议
- 如涉及激进迁移，附带回滚路径

9. 视确认结果整理 `docs/40-dev-loop/auto-*`

## 风险与控制

- 风险：目录迁移导致链接失效
  - 控制：先做入口和索引，不先做激进迁移
- 风险：重复文档被错误合并
  - 控制：只加“权威说明/替代关系”，不直接删正文
- 风险：自动产物处理过度，丢失审计线索
  - 控制：优先归档，不直接删除
- 风险：整理范围失控
  - 控制：本轮仅限 `docs/`，不扩展到代码或规则

## 回滚路径

- 所有修改先保持在文档层，避免影响运行时行为。
- 如某次调整导致导航混乱，可按文件级回退：
  - `docs/README.md`
  - 对应目录 `README.md`
  - `docs/00-governance/document-map.md`
  - `docs/00-governance/document-directory-spec.md`
- 对自动产物仅做归档或索引时，保留原文件，不做不可逆删除。

## 待确认决策

请在执行前确认以下问题：

1. 本轮是否只做“安全收口”，还是同时推进“深度重构”。
2. `runbook/` 与 `packages/` 是保留为例外目录，还是并回六层体系。
3. `40-dev-loop/auto-*` 是做索引化归档，还是只保留导航、不动文件位置。

## 默认执行建议

若你不额外指定，我建议本轮采用以下默认方案：

- 先做“安全收口”
- 暂不迁移 `runbook/` 与 `packages/`，先在治理文档中声明其过渡定位
- 对 `40-dev-loop/auto-*` 先建立目录说明和索引，不直接大规模搬迁

这样能先把文档体系变得“可读、可找、可维护”，再决定是否做第二轮重构。
