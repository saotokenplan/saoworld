# 任务循环规划文档

## 任务概述
- **任务名称**：最近 7 天 Git 提交、变更文件与热点目录分析
- **任务类型**：数据分析
- **预期产出**：`.trae/output/git-activity-analysis-2026-09-12/report.md`（中间产物，可选）与会话内中文分析结论
- **循环模式**：Plan

## 二、异常处理子流程

### 1. 循环溢出处理
- **触发条件**：Git 统计口径多次调整仍无法稳定收敛
- **处理流程**：
  1. 记录当前统计口径
  2. 缩小输出范围为“提交概览 + 热点目录”
  3. 标注其余部分为“待补充”

### 2. 数据错误处理
- **触发条件**：Git 命令输出为空、仓库状态异常、时间窗口无提交
- **处理流程**：
  1. 复核仓库根目录与当前分支
  2. 重新执行只读 Git 命令
  3. 若近 7 天无提交，明确返回“无有效提交数据”

### 3. 资料不足处理
- **触发条件**：目录或文件名不足以判断主题
- **处理流程**：
  1. 回看对应提交标题
  2. 必要时抽样读取核心文件
  3. 若仍无法判断，仅返回“主题待验证”

## 三、风险点识别与预防

| 风险类型 | 风险描述 | 预防措施 |
|---------|---------|---------|
| 时间口径偏差 | “最近 7 天”因时区或整点产生偏差 | 统一使用 `--since="7 days ago"` |
| 主题归类过度推断 | 仅凭文件路径得出过强结论 | 结合提交标题，无法确定时标注“待验证” |
| 热点夸大 | 少量大文件改动被误判为热点模块 | 同时统计提交次数、变更文件数、目录覆盖度 |
| 脏工作区干扰 | 未提交文件被误认为近期变更 | 仅分析 Git 提交历史中的已提交变更 |

## 四、规划确认清单

规划生成后，请用户确认以下内容：

- [ ] 分析范围固定为最近 7 天已提交 Git 历史
- [ ] 输出维度包括模块分布、核心文件、主要主题、潜在热点
- [ ] 允许使用只读 Git 命令与文件读取进行佐证
- [ ] 若发现主题无法从提交与文件直接判断，将标注“待验证”

**确认指令**：用户回复“确认规划，启动循环”后，开始执行实际统计。
