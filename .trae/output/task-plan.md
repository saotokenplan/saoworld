# 任务循环规划文档

## 任务概述
- **任务名称**：周六版每周产品管理工作执行
- **任务类型**：综合任务
- **预期产出**：
  - `docs/00-governance/project-status.md`
  - `docs/40-dev-loop/weekly-report-YYYY-MM-DD.md`
  - `docs/40-dev-loop/monthly-report-YYYY-MM-DD.md`（仅当触发月报条件时）
  - `.trae/output/verification-report.md`
- **循环模式**：Plan
- **执行日期基线**：当前系统日期为 `2026-07-21`

## 一、主循环阶段划分（6大标准阶段）

### 阶段1：输入收集与窗口确认
| 属性 | 配置 |
|------|------|
| 执行目标 | 读取本次周度产品管理所需输入文档，确认统计窗口、目标周报日期和月报触发条件 |
| 调用 Subagent | `stage-researcher` |
| 可用工具 | Read, Glob, Grep, LS |
| 可写文件范围 | `.trae/output/`, `.trae/loop-log/` |
| 输出产物 | `.trae/output/research-summary.md` |
| 最大迭代 | 6轮 |
| 校验标准 | 输入文档列表完整、最近7天文件筛选准确、缺失项明确标注“待补充” |

### 阶段2：Sprint 进度与偏差分析
| 属性 | 配置 |
|------|------|
| 执行目标 | 评估当前 Sprint 阶段、任务完成占比、偏差来源、风险与阻塞问题 |
| 调用 Subagent | `stage-writer` |
| 可用工具 | Read, Grep, SearchCodebase |
| 可写文件范围 | `.trae/output/`, `.trae/loop-log/` |
| 输出产物 | `.trae/output/analysis-summary.md` |
| 最大迭代 | 6轮 |
| 校验标准 | 结论均有来源支撑，完成/进行中/未开始任务占比可追溯，未编造缺失信息 |

### 阶段3：迭代方向复盘与后续规划
| 属性 | 配置 |
|------|------|
| 执行目标 | 判断当前迭代方向是否正常，输出纠偏建议、下周重点和接近完成时的后续迭代规划 |
| 调用 Subagent | `stage-writer` |
| 可用工具 | Read, Grep |
| 可写文件范围 | `.trae/output/`, `.trae/loop-log/` |
| 输出产物 | `.trae/output/next-iteration-plan.md` |
| 最大迭代 | 6轮 |
| 校验标准 | 方向评估为“正常/需关注/偏离”之一，判断依据清晰，建议与战略、路线图和里程碑一致 |

### 阶段4：文档更新与周报/月报生成
| 属性 | 配置 |
|------|------|
| 执行目标 | 更新项目状态文档，生成当周周报；若命中当月第一个周六，则额外生成月报 |
| 调用 Subagent | `stage-writer` |
| 可用工具 | Read, Glob, apply_patch |
| 可写文件范围 | `docs/00-governance/`, `docs/40-dev-loop/`, `.trae/output/` |
| 输出产物 | 更新后的状态文档与周报/月报文件 |
| 最大迭代 | 6轮 |
| 校验标准 | 文档内容与分析一致，缺失输入明确标注，已有同日周报存在时不重复生成 |

### 阶段5：自检校验与结果确认
| 属性 | 配置 |
|------|------|
| 执行目标 | 对照 checklist 对文档更新、日期口径、引用真实性和完成条件进行校验 |
| 调用 Subagent | `verifier` |
| 可用工具 | Read, Glob, Grep |
| 可写文件范围 | `.trae/output/verification-report.md`, `.trae/loop-log/` |
| 输出产物 | `.trae/output/verification-report.md` |
| 最大迭代 | 3轮 |
| 校验标准 | 所有强制项通过；若存在输入缺失、日期口径不确定或 Git 条件不满足，明确上报 |

### 阶段6：Git 交付与分支收尾
| 属性 | 配置 |
|------|------|
| 执行目标 | 提交本次文档变更、推送当前分支、合并到 `feature-prd`、删除临时分支 |
| 调用 Subagent | 手动执行 |
| 可用工具 | RunCommand |

| 最大迭代 | 3轮 |
| 校验标准 | 提交信息符合规范、推送成功、合并使用 `--no-ff`、删除分支前确认当前分支名称与远程状态 |

## 三、异常处理子流程

### 1. 输入文档缺失
- **触发条件**：指定文档不存在，或最近7天窗口内没有对应日报/摘要/周报文件
- **处理流程**：
  1. 记录缺失项到 `.trae/output/research-summary.md`
  2. 在分析与周报正文中标注“待补充”
  3. 不编造缺失结论，仅基于现有材料输出

### 2. 日期口径冲突
- **触发条件**：执行日期不是周六，但用户要求按周六版输出
- **处理流程**：
  1. 在规划阶段显式列出两套日期口径
  2. 等待用户确认后再进入正式执行
  3. 未确认前不更新正式状态文档和周报文件

### 3. Git 收尾风险
- **触发条件**：工作树存在意外改动、推送失败、`feature-prd` 分支拉取失败、合并冲突
- **处理流程**：
  1. 立即暂停 destructive 操作
  2. 输出当前 Git 状态与阻塞原因
  3. 等待用户确认后再继续

## 四、风险点识别与预防

| 风险类型 | 风险描述 | 预防措施 |
|---------|---------|---------|
| 日期误用风险 | 非周六执行导致周报日期、统计窗口与流程要求不一致 | 先确认日期口径，再执行正式文档更新 |
| 结论失真风险 | 摘要文件密集，容易遗漏关键已完成或阻塞事项 | 严格按最近7天筛选并交叉比对日报、周报、状态文档 |
| 信息编造风险 | 部分输入缺失时容易补全推断 | 缺失处统一标注“待补充”，不输出无来源结论 |
| 状态滞后风险 | `project-status.md` 与周报内容不一致 | 先完成分析摘要，再统一回写项目状态与周报 |
| Git 操作风险 | 合并或删分支误操作影响当前工作树 | 执行前检查分支名、工作树状态、远程同步状态 |
