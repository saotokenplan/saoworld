# 任务验收清单

本清单为本轮“每周代码审查与高价值低风险重构”唯一终止标准。若最近 7 天无实质代码改动，则以“分析、沉淀、同步完成且无编造”为达成标准，不强行实施代码修改。

---

## 一、事实采集校验

| 序号 | 校验项 | 通过标准 |
|------|--------|----------|
| 1.1 | 最近 7 天 Git 提交范围已核实 | 已获得 `git log --since='7 days ago'` 结论 |
| 1.2 | 最近一次提交时间已核实 | 已记录最近一次提交时间与分支 |
| 1.3 | 重点目录变更范围已核实 | `services/`、`workers/`、`game/`、`tools/`、`docs/` 至少完成一次范围确认 |
| 1.4 | 需求与规范输入已读取 | 至少读取用户指定文档与相关规则 |
| 1.5 | 项目状态文档已读取 | `docs/00-governance/project-status.md` 已核对 |
| 1.6 | 最新周报已读取 | 已确认并读取最新 `weekly-report-*.md` |
| 1.7 | 无编造 | 所有判断均可追溯到仓库文件或 Git 历史 |

---

## 二、分析完整性校验

| 序号 | 校验项 | 通过标准 |
|------|--------|----------|
| 2.1 | 本周改动概览完整 | 包含模块、目的、风险区域、结构性问题 |
| 2.2 | 六维分析完整 | 覆盖架构一致性、可读性、可靠性、稳定性、可测试性、可维护性 |
| 2.3 | 问题分级明确 | 每个问题有影响范围、严重程度、建议处理方式 |
| 2.4 | 优化项分组明确 | 已分为“立即实施 / 建议纳入下周 / 暂缓处理” |
| 2.5 | 无改动分支处理明确 | 若近周无实质改动，报告中明确说明且不伪造重构结果 |

---

## 三、实施与验证校验

| 序号 | 校验项 | 通过标准 |
|------|--------|----------|
| 3.1 | 立即实施项边界清晰 | 仅高价值低风险项进入修改 |
| 3.2 | 代码修改伴随测试/文档同步 | 若有业务代码改动，则同步更新相关测试或说明 |
| 3.3 | 验证信号真实 | 已执行与改动范围直接相关的检查，且结果真实记录 |
| 3.4 | 高风险改动可回滚 | 如实施改动，回滚路径已说明 |
| 3.5 | 无法安全修复时停止扩张 | 风险不可控项被降级为建议，不强行落地 |

---

## 四、交付物校验

| 序号 | 校验项 | 通过标准 |
|------|--------|----------|
| 4.1 | 周度代码审查报告已生成 | `docs/40-dev-loop/weekly-code-review/weekly-code-review-2026-09-12.md` 已创建或更新 |
| 4.2 | 项目状态已同步 | `docs/00-governance/project-status.md` 已按真实状态更新 |
| 4.3 | 规范或 skills 沉淀已记录 | 已新增或更新规范/skills 草案，或明确说明无适合沉淀项 |
| 4.4 | 风险与回滚说明完整 | 报告包含风险、验证、回滚说明 |
| 4.5 | 下周建议明确 | 报告给出可执行的后续治理方向 |

---

## 五、Git 流程校验

| 序号 | 校验项 | 通过标准 |
|------|--------|----------|
| 5.1 | 提交信息符合规范 | `refactor(weekly-review): 每周代码审查与优化 - 2026-09-12` |
| 5.2 | 推送结果已记录 | push 成功或阻塞原因已记录 |
| 5.3 | 分支合并前状态已核实 | 当前工作区干净且目标分支已更新 |
| 5.4 | 合并方式正确 | 使用 `--no-ff` 合并到 `feature-prd` |
| 5.5 | 删除分支动作安全 | 仅在确认当前确为临时分支时才删除本地和远程分支 |

---

## 六、特殊门禁

- 若当前分支本身就是 `feature-prd`，则“切换到 `feature-prd` 并合并当前临时分支”这一动作需要重新判断是否适用，禁止错误删除当前分支。
- 若最近 7 天无 Git 提交，则本轮不应编造“本周主要代码改动模块”，而应明确说明“本周无实质代码改动，以下分析基于现有状态与历史上下文”。
- 若执行阶段发现非本人预期改动或脏工作区异常，立即停止并请求用户决策。
