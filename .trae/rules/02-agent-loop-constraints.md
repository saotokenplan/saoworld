# 02 - AI Agent Loop 执行约束

> 适用角色：AI Agent、自动化任务
> 本文件定义 Agent 在执行任务时的循环约束、权限边界、异常处理规则。

---

## 一、任务执行流程约束

### 1.1 规划先行原则

所有复杂任务必须遵循以下流程：

```
需求分析 → 生成规划文档 → 用户确认 → 执行循环 → 结果验收
```

**强制要求**：
- 多步骤任务必须先生成 `task-plan.md` 与 `checklist.md`
- 规划文档生成后必须等待用户确认才进入执行
- 未确认规划直接执行的操作将被拒绝

### 1.2 循环迭代上限

| 循环层级 | 最大迭代 | 达到上限行为 | 输出文件 |
|---------|---------|-------------|---------|
| 主循环 | 12轮 | 暂停 + 生成摘要报告 + 等待人工 | overflow-master.md |
| 子循环 | 6轮 | 回退主循环 + 重新评估策略 | overflow-stage.md |
| 微循环 | 3轮 | 上报缺陷详情 + 请求人工方案 | overflow-patch.md |

**项目特定约束**：
- 内容生成循环：单个内容包生成不超过 5 轮
- 审核循环：自动审核失败后最多 2 轮修正尝试
- 发布循环：灰度发布观察期至少 1 个投票周期（约 7 天）

## 二、文件操作权限约束

### 2.1 白名单目录（可自由读写）

- `.trae/loop-log/` - 循环日志目录
- `.trae/output/` - 循环输出目录
- `docs/` - 文档目录（需遵守 [52-documentation.md](./52-documentation.md) 规范）
- `tools/` - 工具脚本目录

### 2.2 业务代码目录（需规划声明）

修改以下目录必须在 `task-plan.md` 中显式声明：

- `game/` - Godot 客户端代码（需同步更新测试）
- `services/` - 后端服务代码（需同步更新测试）
- `workers/` - Celery 异步任务

**业务同步规则**：
- 修改 `services/*/app/` 下代码时，必须同步更新 `services/*/tests/` 对应测试
- 修改游戏逻辑时，必须同步更新相关测试用例
- 测试覆盖率不得低于修改前水平

### 2.3 黑名单目录（禁止修改）

- `.git/` - Git 配置目录
- `.trae/rules/` - 规则配置目录（仅用户显式指令下可修改）
- `.trae/hooks/` - Hook 脚本目录
- `.trae/agents/` - Subagent 配置目录
- `.trae/skills/` - Skill 配置目录（仅用户显式指令下可修改）
- `infra/` - 基础设施配置
- `.env*` - 环境变量文件

### 2.4 特殊文件（需显式授权）

- `README.md` - 项目说明文件
- `pyproject.toml` - Python 项目配置
- `game/project.godot` - Godot 项目配置
- `docker-compose*.yml` - Docker 配置
- 任何以 `.secret.` 或 `.private.` 开头的文件

## 三、业务流程专项约束

### 3.1 内容生成流程约束

AI 内容生成必须遵循 [51-ai-content-generation.md](./51-ai-content-generation.md) 规范：

```
载入世界骨架快照 → 校验输入 → 匹配模板 → 生成内容 → 质量评分 → 自动审核 → 人工复核（如需） → 打包发布
```

**强制检查点**：
- 生成前：必须载入世界骨架快照，校验 `forbidden_tags` 不为空
- 生成后：质量评分 < 0.75 直接废弃，不得进入打包
- 发布前：必须通过四项内容检查（一致性、数值、安全、重复度）
- 灰度期：观察至少 1 个完整投票周期

### 3.2 投票流程约束

投票相关操作必须遵循 [50-security.md](./50-security.md) 风控规则：

- 票权计算：贡献度修正倍率不超过 1.2
- 幂等检查：必须校验 `idempotency_key` 全局唯一性
- 一人一票：通过数据库 `UNIQUE (vote_cycle_id, player_id)` 约束保证
- 异常检测：行为聚类分析识别异常投票模式

### 3.3 发布与回滚约束

发布流程必须遵循 [42-release-rollback.md](./42-release-rollback.md) 规范：

- 灰度优先：所有发布必须优先灰度，禁止直接全量发布
- 回滚路径：发布前必须验证回滚路径可执行
- 回滚终态：`rolled_back` 状态不可再向 `live`/`gray` 迁移
- 连续回滚：同类内容连续回滚超过 2 次时，暂停模板使用

## 四、异常处理与死循环防护

### 4.1 死循环检测条件

自动触发死循环警报的条件：

| 条件 | 触发阈值 | 输出文件 |
|------|---------|---------|
| 产出重复 | 连续 3 轮产出内容完全相同 | deadloop-content-repeat.md |
| 校验停滞 | 连续 5 轮校验未通过且缺陷类型相同 | deadloop-verify-stuck.md |
| 修复失败 | 同一缺陷修复尝试超过 3 次 | deadloop-fix-failed.md |

**触发后强制行为**：
1. 立即暂停当前循环
2. 写入 `.trae/loop-log/deadloop-alert.md`
3. 记录死循环类型与原因
4. 保存最近 N 轮轨迹
5. 生成人工干预建议
6. 等待用户决策

### 4.2 上下文溢出处理

**触发条件**：
- 对话上下文接近模型上限（预估剩余 < 20%）
- 长文档任务（预估产出 > 10000 字）
- 大数据任务（预估处理记录 > 1000 条）

**分段执行流程**：
```
检测溢出风险 → 将当前结果写入独立文件 → 清理历史上下文 → 保留关键状态 → 继续执行下一段 → 合并结果
```

**状态保留清单**：
- 当前循环轮次
- 当前执行阶段（如：内容生成、审核、发布）
- 已完成的校验项列表
- 未完成的缺陷列表
- 关键中间结果文件路径

### 4.3 循环日志强制记录

每轮循环结束必须写入 `.trae/loop-log/round-{n}.md`，包含：

- 本轮输入内容摘要
- 本轮执行的工具调用列表
- 本轮输出结果摘要
- 本轮修改的文件清单
- 本轮发现的错误/缺陷
- 本轮校验结果（通过/未通过）

## 五、信息真实性约束

**禁止编造**：
- 数据、文档、行业信息必须来自真实来源
- 无法找到来源的信息必须标注"待验证"

**引用格式**：
- 文件引用：`[文件名](file:///相对路径)`（使用相对路径，不使用绝对路径）
- 网页引用：`[来源标题](URL)`

---

## 六、循环终止条件

仅两种情况可终止循环：

1. **正常终止**：完整通过全部 checklist 验收项
2. **异常终止**：达到最大迭代轮次等待人工确认
