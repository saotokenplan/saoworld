# 全局 Loop Engineering 强制规则

所有 SOLO 循环自动加载本规则，强制执行以下约束。

## 一、规划先行原则
1. 所有任务必须先生成 `task-plan.md` 与 `checklist.md`
2. 规划文档生成后，必须等待用户确认才进入执行循环
3. 未确认规划直接执行的操作将被拒绝

## 二、迭代上限约束
1. 主循环最大迭代次数：12轮
2. 阶段子循环最大迭代次数：6轮
3. 微修复循环最大迭代次数：3轮
4. 达到上限自动暂停，上报人工审核，禁止无限循环

## 三、循环日志强制记录
1. 每一轮循环结束，必须写入 `.trae/loop-log/round-{n}.md`
2. 日志内容必须包含：
   - 本轮输入内容摘要
   - 本轮执行的工具调用列表
   - 本轮输出结果摘要
   - 本轮修改的文件清单
   - 本轮发现的错误/缺陷
   - 本轮校验结果（通过/未通过）

## 四、校验闭环机制
1. 未通过 Verifier 校验时，禁止进入下一阶段
2. 校验失败必须自主分析缺陷原因
3. 启动局部修正子循环（而非重跑全流程）
4. 修复完成必须复测，复测通过才放行

## 五、信息真实性约束
1. 循环内禁止编造数据、文档、行业信息
2. 所有结论必须附参考来源：
   - 文件引用格式：`[文件名](file:///路径)`
   - 网页引用格式：`[来源标题](URL)`
3. 无法找到来源的信息必须标注"待验证"

## 六、上下文溢出处理
1. 上下文接近溢出时，自动触发分段机制
2. 将中间结果落地到独立文件
3. 清理历史上下文，保留关键状态
4. 不丢失任何已完成的阶段性成果

## 七、循环终止条件
仅两种情况可终止循环：
1. 完整通过全部 checklist 验收项（正常终止）
2. 达到最大迭代轮次等待人工确认（异常终止）

## 八、文件操作约束
1. 写入文件必须在白名单范围内
2. 禁止修改黑名单目录下的任何文件
3. 跨目录操作需要用户显式授权

## 九、项目专属约束（游戏开发项目）
1. 游戏逻辑代码修改必须同步更新对应测试
2. 配置文件修改必须记录变更原因
3. 资源文件引用路径必须经过校验
4. 涉及网络协议的修改必须与 API 文档同步
