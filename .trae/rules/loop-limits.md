# 循环迭代上限与死循环防护规则

## 一、迭代上限硬约束

| 循环层级 | 最大迭代 | 达到上限行为 | 输出文件 |
|---------|---------|-------------|---------|
| 主循环 | 12轮 | 暂停 + 生成摘要报告 + 等待人工 | overflow-master.md |
| 子循环 | 6轮 | 回退主循环 + 重新评估策略 | overflow-stage.md |
| 微循环 | 3轮 | 上报缺陷详情 + 请求人工方案 | overflow-patch.md |

## 二、死循环检测条件

自动触发死循环警报的条件：

### 条件1：产出重复检测
- 连续3轮迭代产出内容完全相同
- 触发行为：暂停循环，写入 `deadloop-content-repeat.md`

### 条件2：校验停滞检测
- 连续5轮校验结果均为"未通过"
- 且缺陷类型/位置相同
- 触发行为：暂停循环，写入 `deadloop-verify-stuck.md`

### 条件3：修复失败检测
- 同一缺陷ID修复尝试超过3次
- 每次修复后复测均未通过
- 触发行为：暂停循环，写入 `deadloop-fix-failed.md`

## 三、死循环触发后的强制行为

检测到死循环后，必须执行以下流程：
1. 立即暂停当前循环
2. 写入 `.trae/loop-log/deadloop-alert.md`
3. 记录死循环类型与原因
4. 保存最近N轮轨迹
5. 生成人工干预建议
6. 等待用户决策

## 四、上下文溢出防护

### 分段执行触发条件
- 对话上下文接近模型上限（预估剩余 < 20%）
- 长文档任务（预估产出 > 10000 字）
- 大数据任务（预估处理记录 > 1000 条）

### 分段执行流程
```
检测到溢出风险 →
触发分段机制 →
1. 将当前阶段结果写入独立文件 →
2. 清理历史对话上下文 →
3. 保留关键状态信息 →
4. 继续执行下一段 →
5. 合并分段结果 →
最终输出完整产物
```

### 状态保留清单
分段清理时必须保留以下信息：
- 当前循环轮次
- 当前执行阶段
- 已完成的校验项列表
- 未完成的缺陷列表
- 关键中间结果文件路径

## 五、循环效率监控

### 效率预警条件
| 预警类型 | 触发条件 | 预警行为 |
|---------|---------|---------|
| 单轮耗时预警 | 单轮执行 > 5分钟 | 记录预警日志 |
| 累计耗时预警 | 累计执行 > 30分钟 | 生成效率报告 |
| 循环膨胀预警 | 子循环调用次数 > 预期 | 提示优化策略 |

### 效率报告输出
达到预警条件时，输出 `efficiency-report.md` 到 loop-log 目录，包含：
- 各阶段耗时统计
- 效率瓶颈分析
- 优化建议
- 历史效率对比

## 六、循环冲突检测

### 文件读写冲突检测
- 多并行循环检查是否有文件读写冲突
- 冲突检测规则：两个循环同时写同一文件
- 冲突处理：隔离输出目录，各循环独立输出

### 规则冲突检测
- 检查是否存在相互矛盾的规则
- 检查规则优先级是否正确配置
- 冲突处理：提示用户修正规则配置

## 七、全量审计日志

循环执行过程中，以下日志文件全量记录：

| 日志文件 | 记录内容 | 更新频率 |
|---------|---------|---------|
| round-counter.txt | 当前轮次计数 | 每轮开始 |
| round-{n}.md | 本轮详细执行记录 | 每轮结束 |
| round-{n}-files.log | 本轮修改文件清单 | 每次文件操作 |
| round-{n}-verify.log | 本轮校验结果 | 每次校验 |
| defect-report.md | 缺陷记录与状态 | 发现缺陷时 |
| checklist-status.md | 验收进度 | 每轮校验 |
| efficiency-report.md | 效率统计 | 达到预警条件 |
| deadloop-alert.md | 死循环警报 | 检测到死循环 |
| final-audit.md | 最终审计报告 | 任务完成 |
