# 文档评审检查清单

> 文档状态：active
> 适用阶段：当前
> 维护要求：持续维护

## 目的

本文档用于为新增文档、重要修订和结构性调整提供统一的评审清单，减少“文档写了但不可维护”“路径改了但引用没同步”“内容有了但层级不清”的问题。

## 适用范围

- 新增治理文档、规范文档、接口参考文档
- 对已有文档的大幅改写
- 文档迁移、重命名、目录重组
- 会影响多个入口或引用路径的文档变更

## 使用方式

- 作者在提交前先按本清单自检。
- 评审者在 review 时按本清单抽查关键项。
- 若本次变更属于结构性调整，应重点检查“目录与引用”“入口与映射”“提交粒度”三组条目。

## 一、基础检查

- 文档标题是否准确反映主题，没有过泛或过窄
- 文档目的是否写清，读者能快速理解这份文档是干什么的
- 文档当前定位是否明确，是否说明与其他规范的关系
- 文档状态是否清晰，必要时是否标注为 `draft`、`active`、`deprecated` 或 `archived`
- 若属于治理文档、规范文档或 API 文档，是否参考统一模板组织结构
- 文档是否放在正确目录，没有落到错误层级
- 文件名是否稳定、可复用、符合当前目录命名风格

## 二、内容检查

- 内容是否围绕单一主题展开，没有把多个无关主题混在一起
- 文档是否区分“背景说明”和“执行约束”
- 如属于实施文档，是否明确边界、前提和适用范围
- 如属于治理文档，是否明确流程、责任或检查点
- 如属于接口文档，是否包含与总览、权限、错误码的一致性约束
- 是否存在明显重复内容，且应由更高权威文档统一维护

## 三、层级与权威关系检查

- 若文档位于 `10-requirements/`，是否避免重复维护接口、表结构、事件流等实现细节
- 若文档位于 `20-specs/`，是否足够明确到可作为执行基线
- 若文档位于 `30-api/`，是否说明其是参考索引而不是替代规范
- 若文档位于 `40-dev-loop/`，是否区分当前可执行与目标态设计
- 若文档与 `20-specs/` 存在冲突，是否已经以 `20-specs/` 为准做修正

## 四、目录与引用检查

- 文档路径是否符合 `docs/00-governance/`、`10-requirements/`、`20-specs/`、`30-api/`、`40-dev-loop/`、`50-research/` 的分层规则
- 文中引用路径是否使用最新目录结构
- 是否仍残留旧路径或旧目录名
- 若涉及 `.trae/skills/` 的规范来源，是否已同步更新
- 若文档被迁移或重命名，是否已完成全局引用检查

## 五、入口与导航检查

- 是否需要更新 `docs/README.md`
- 是否需要更新 `README.md`
- 是否需要更新 `docs/00-governance/document-map.md`
- 是否需要更新 `docs/00-governance/quick-start.md`
- 是否需要更新 `docs/00-governance/project-status.md`
- 是否需要更新 `docs/00-governance/spec-skill-mapping.md`

## 六、结构性变更专项检查

以下项目仅在迁移、重命名、目录重组时强制检查：

- 是否先更新了 `document-directory-spec.md`
- 是否已有明确迁移目标，而不是临时挪动文件
- 是否把迁移和引用修复放在同一主题内完成
- 是否避免留下“旧路径已失效但入口没改”的中间状态
- 是否避免把治理文档、接口文档再次散落到 `docs/` 根目录

## 七、可维护性检查

- 文档中的术语是否前后一致
- 列表、目录名、路径和标题风格是否一致
- 是否存在过期状态描述
- 文档的生命周期状态是否与当前实际用途一致
- 是否存在“后续补充”但其实已经完成的陈旧说明
- 文档是否足够短而清晰，或足够长且结构明确，没有中间态混乱

## 八、提交前检查

- 本次提交是否只围绕一个清晰主题
- commit message 是否概括了“这一次改了什么”
- commit message 是否避免复述整段会话总结
- 是否没有混入无关文件
- 若是目录重组，是否已经确认工作区中只剩本主题相关变更

## 九、评审结论建议

评审时可使用以下结论：

- `通过`
  - 文档定位清晰、结构正确、引用完整、可直接合并
- `通过但建议优化`
  - 主体无误，但存在表达、导航或命名上的可改进点
- `需修改后再评审`
  - 存在层级错误、引用未同步、权威关系冲突或范围混乱

## 与其他文档的关系

- 目录分层规则以 `docs/00-governance/document-directory-spec.md` 为准
- 文档状态规范以 `docs/00-governance/document-lifecycle.md` 为准
- 模板结构建议以 `docs/00-governance/document-template-spec.md` 为准
- 变更执行步骤以 `docs/00-governance/document-change-process.md` 为准
- 全局文档角色与权威关系以 `docs/00-governance/document-map.md` 为准
