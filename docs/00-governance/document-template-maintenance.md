# 文档模板维护规则

> 文档状态：active
> 适用阶段：当前
> 维护要求：持续维护

## 目的

本文档用于约束模板字段在“已完成全量对齐”之后如何持续保持，避免后续新增、迁移、大幅改写或状态调整时重新出现 `适用范围`、`当前定位`、`与其他文档的关系` 等结构缺口。

## 适用范围

- 适用于 `docs/` 目录下全部正式 Markdown 文档的后续维护。
- 适用于新增文档、结构性改写、目录迁移、重命名和生命周期状态调整后的增量复查。
- 不替代模板规范、变更流程和评审清单，而是补充“何时触发模板复查”与“复查到什么程度”。

## 当前定位

- 本文档是模板对齐完成后的持续维护规则，用于回答“后续什么情况下必须重新检查模板字段”。
- 本文档聚焦触发条件、最小动作和收口要求，不单独定义文档正文写法本身。
- 当文档模板、变更流程和评审清单之间存在衔接问题时，应以本文档补足模板维护动作。

## 触发条件

出现以下任一情况时，应触发一次模板维护检查：

- 新增一份正式文档。
- 对现有文档做大幅改写，导致原有章节结构明显变化。
- 文档发生迁移、重命名或职责调整。
- 文档状态从 `draft` 转为 `active`，或从 `active` 转为 `deprecated` / `archived`。
- 入口文档、治理文档、规范文档或 API 文档新增章节模板要求。

## 最小检查项

触发模板维护检查时，至少确认以下事项：

- 是否存在明确标题和状态标注块。
- 是否具备 `## 目的`。
- 是否具备 `## 适用范围`。
- 是否具备 `## 当前定位`。
- 是否具备 `## 与其他文档的关系`。
- 若属于历史归档文档，是否已说明保留原因和当前使用方式。

## 增量复查规则

- 单份新增或单份大改时，优先做单文档复查，不必每次重扫全仓。
- 同一轮改动涉及多个目录时，应至少覆盖本轮受影响的全部文档，而不是只检查主文件。
- 若模板规范本身发生变化，应重新使用 `document-template-alignment-checklist.md` 的口径做一次全量复查。
- 若只是修正文案、路径或少量字段，不改变章节结构时，可不额外触发模板专项复查。

## 收口要求

模板维护动作完成后，应至少做到：

- 文档自身结构已补齐或明确说明为何不适用。
- 相关入口、映射或状态说明已同步。
- 如本轮出现新的结构缺口，应更新 `document-template-alignment-checklist.md`。
- 如本轮已消除缺口，也应更新 `document-template-alignment-checklist.md`，避免清单过期。

## 不应做的事

- 不因为“正文已经差不多”而长期跳过结构字段补齐。
- 不把模板维护拖到多轮之后，导致清单与实际状态脱节。
- 不在 `active` 的正式文档中长期保留缺少定位或关系说明的中间态。
- 不把模板规则写在聊天约定里而不落回文档。

## 维护建议

- 新增正式文档时，把模板检查作为创建动作的一部分，而不是事后补救。
- 每次目录迁移或大批量改写后，优先做一次本主题内的增量复查。
- 若治理入口文档发生变化，优先同步 `docs/README.md`、`document-map.md` 和 `project-status.md`。
- 若清单长期保持全量对齐，可继续把它作为“巡检基线”，而不是重新退回临时排查工具。

  - 记录当前模板对齐状态，并作为本规则触发后的复查记录载体。
- `docs/00-governance/document-change-process.md`
  - 规定新增、修订、迁移和删除时应把模板维护动作纳入流程。

  - 规定模板维护完成后应如何在评审时做收口检查。
- `docs/00-governance/project-status.md`
  - 记录当前模板对齐阶段是否已完成，以及后续维护重点。
