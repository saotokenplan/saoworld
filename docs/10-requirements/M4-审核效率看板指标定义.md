# M4 审核效率看板指标定义

> 文档状态：draft
> 适用阶段：M4 规划期（灰度发布解锁前）
> 维护要求：随 WP3 推进持续维护
> 关联工作包：M4-WP3 审核效率监控

## 目的

本文档定义 M4「审核效率监控」（WP3）的**看板指标体系**：自动审核通过率、审核耗时、人工介入率三项核心指标的口径、数据源、看板面板布局与告警/SLO 阈值，用于：

1. 承载 M4 验收口径中「审核效率提升：自动审核通过率 >70%，审核时间 <30 分钟」的持续测量与达标判定；
2. 为 WP2 阈值调优提供统一的衡量出口（调优前后对比、按周趋势、分层归因都落到本文档定义的指标上）；
3. 在真实运行时到位前，预先固化「测什么、口径是什么、在哪看、越限怎么告警」，避免实施期边建边改口径。

本文档只回答「指标怎么定义、缺口是什么、看板与告警怎么设计」，不落地任何埋点代码与配置文件（属 WP3 实施期动作），也不重复阈值调优本身（以 `M4-阈值调优预案.md` 为准）。

## 适用范围

- 覆盖 `services/review` 自动审核与人工审核两条的效率测量，以及 `services/ops` 运营看板、`telemetry/` 监控配置三处承载面。
- 覆盖三项核心指标（通过率、耗时、人工介入率）与配套的辅助指标（安全误放、误拒、规则归因、积压量）。
- 不覆盖生成侧质量评分指标（属 WP1）、不覆盖发布链路指标（属 WP4）、不覆盖 HTTP 层通用 RED 指标（已在 `telemetry/metrics/metrics.yaml` 服务级指标中定义）。

## 一、指标体系总览

指标体系分两层：**三项核心指标**直接对应 M4 验收口径（WP3 必须交付）；**辅助指标**为核心指标的分层归因与护栏（随核心指标一并落地）。

### 核心指标

| # | 指标 | M4 验收目标 | 一句话口径 |
|---|------|-------------|------------|
| K1 | 自动审核通过率 | > 70% | approved 判定数 / 自动审核总判定数 |
| K2 | 审核耗时 | < 30 分钟 | 审核记录创建 → 终结的时长分布（P50/P95） |
| K3 | 人工介入率 | 持续下降或不升 | manual_review 判定数 / 自动审核总判定数，按周对比 |

### 辅助指标

| # | 指标 | 目标 / 护栏 | 用途 |
|---|------|-------------|------|
| A1 | 安全误放率 | = 0（一票否决） | K1 调优的安全护栏，任何通过率提升不得以 A1 上升为代价 |
| A2 | 应过误拒率 | < 15% | 通过率与误拒的互斥校验（口径同阈值调优预案第一节） |
| A3 | 规则判定分布 | 观测用 | 各规则（安全/完整度/重复度/质量分）的 approved/rejected/manual_review 分布，用于归因 |
| A4 | 审核积压量 | 观测用 | pending_review_count 趋势，积压是 K2 恶化的先行信号 |
| A5 | 应人工自动终结比例 | 不上升 | 人工件被自动终结的漏检护栏（口径同阈值调优预案） |

## 二、核心指标口径定义

### K1 自动审核通过率

- **分子**：判定结果为 `approved` 的自动审核记录数。
- **分母**：自动审核引擎产生终局判定的记录总数（approved + rejected + manual_review）。
- **双轨测量**：
  - **离线验收轨（调优用）**：对样本集回放结果统计，只认 `real_llm` 来源样本（`sampleset_v2` 起），按对象类型与 source 分层——口径与 `M4-阈值调优预案.md` 第一节完全一致，以该文档为权威。
  - **在线运行轨（看板用）**：`sum(rate(reviews_total{result="approved"}[1h])) / sum(rate(reviews_total[1h]))`，按 object_type 分层（依赖缺口 M2/M4 修复后补齐分层标签）。
- **达标判定**：M4 验收以离线验收轨为准（>70%）；在线轨用于调优上线后的持续监控，跌破 70% 触发告警（见第五节）。

### K2 审核耗时

- **定义**：审核记录从创建（`created_at`）到终结（`updated_at`，result 落入 approved/rejected 之一）的时长。自动判定件耗时近似为引擎处理时长；人工件耗时为排队 + 人工处理时长，两者必须分开统计。
- **统计量**：P50 / P95 / max，按 review_type（auto/manual）与 object_type 分层。
- **目标**：P95 < 30 分钟（M4 验收口径「审核时间 <30 分钟」按 P95 解读，避免长尾单点否决整体达标）。
- **数据源**：当前无专用埋点（缺口 M1）；实施期新增 `review_duration_seconds` Histogram，过渡期可用审核记录持久层 `updated_at - created_at` 离线推导做基线。

### K3 人工介入率

- **分子**：自动审核引擎判定为 `manual_review` 的记录数。
- **分母**：同 K1 分母。
- **统计窗口**：按周对比（阈值调优预案第一节口径），目标为调优后持续下降或不升；绝对值不设硬性目标（人工介入本身是安全机制，压到零反而危险）。
- **前置依赖**：当前 auto 路径 manual_review 判定不计入 `reviews_total`（缺口 M2），该缺口修复前 K3 在线轨不可信，只能依赖持久层离线统计。

## 三、现状埋点盘点与缺口（2026-07-23 代码口径）

### 已有埋点（`services/review/app/core/metrics.py`）

| 指标 | 类型 | 标签（代码实际） | 记录点 |
|------|------|------------------|--------|
| `reviews_total` | Counter | `result` | `routes.py`：人工 approve（L399）、人工 reject（L507）、auto 路径仅 `is_automatic` 时（L612-613） |
| `review_operations_total` | Counter | `action` | `routes.py` L218（create） |
| `reviews_by_risk_level` | Gauge | `risk_level` | 按风险等级聚合当前审核数 |

### 已有承载面

- **持久层**：`review_records` 含 `review_type`（auto/manual）、`result`、`risk_level`、`quality_score`、`created_at`、`updated_at`，可作全部三项核心指标的离线推导数据源。
- **ops 看板**：`GET /api/v1/ops/dashboard` 的 `DashboardMetrics` 仅有 `pending_review_count` 一个审核字段，无效率类指标。
- **telemetry 声明**：`telemetry/metrics/metrics.yaml` 已声明 review 三指标；`telemetry/dashboards/README.md` 描述了看板分区结构。

### 缺口清单（全部列为 WP3 实施期改造项，规划期不修复）

| # | 缺口 | 影响 | 实施期动作 |
|---|------|------|------------|
| M1 | 无审核耗时埋点（无 `review_duration_seconds` Histogram） | K2 无在线数据源，验收只能靠离线推导 | routes 在审核终结时记录时长 Histogram，labels: `review_type`、`object_type` |
| M2 | auto 路径 `manual_review` 判定不计入 `reviews_total`（`routes.py` L612 仅 `is_automatic` 时计数） | K1 分母失真、K3 分子缺失 | auto 路径对所有终局判定统一计数，并增加 `review_type` 标签区分自动/人工 |
| M3 | `metrics.yaml` 声明与代码标签不一致（`reviews_total` 声明 `result`+`risk_level` vs 代码仅 `result`；`review_operations_total` 声明 `operation` vs 代码 `action`） | 配置与实现两份真相，看板查询会落空 | 以代码为准回填 metrics.yaml，或按声明补标签后同步两侧；纳入 WP3 提交一并处理 |
| M4 | 无 per-rule 判定分布指标（`rule_results` 仅存在于 API 响应体） | A3 规则归因不可用，调优只能靠离线回放 | 新增 `review_rule_decisions_total{rule, result}` Counter，引擎评估处埋点 |
| M5 | `telemetry/dashboards/` 无实体 dashboard JSON（README 引用的 `game-dashboard.json` 不存在） | 看板无落地物，仅停留在文字描述 | 按第四节布局定义导出 Grafana JSON 落盘，同步 README |
| M6 | `alerts.yaml` 无审核效率告警、`slo-definitions.yaml` 无 review SLO | K1/K2 越限无通知，达标无判定依据 | 按第五节定义增补告警条目与 SLO-REVIEW 系列 |

## 四、看板面板布局定义

看板定名「审核效率看板」（Grafana dashboard，实施期落 `telemetry/dashboards/review-efficiency-dashboard.json`），四层布局：

| 层 | 面板 | 内容 | 数据源 / PromQL 草案 |
|----|------|------|----------------------|
| L1 核心 KPI | 通过率 / P95 耗时 / 人工介入率 / 积压量 | 单值大数字 + 达标着色（绿/黄/红） | K1/K2/K3 口径见第二节；积压量取 ops 看板 `pending_review_count` |
| L2 趋势 | 三项核心指标 7d/30d 趋势 | 折线，按周对比叠加 | `sum(rate(reviews_total{result=...}[1h])) by (result)` 等 |
| L3 耗时分布 | 审核耗时热力图 + P50/P95 曲线 | 按 review_type 分面 | `histogram_quantile(0.95, rate(review_duration_seconds_bucket[1h]))`（依赖 M1） |
| L4 规则归因 | 各规则判定分布堆叠柱 + 误放/误拒护栏表 | 按 rule × result 分组 | `sum(rate(review_rule_decisions_total[1d])) by (rule, result)`（依赖 M4） |

ops 运营看板（`/api/v1/ops/dashboard`）实施期增补三个审核效率字段（`auto_pass_rate`、`review_p95_minutes`、`manual_intervention_rate`），与 Grafana 看板共用同一份口径，不做第二份计算逻辑。

## 五、告警与 SLO 定义（设计草案）

### 告警条目（沿用 `telemetry/alerts/alerts.yaml` 声明格式，实施期增补进 `business_metrics_alerts`）

| 告警 | 级别 | 条件（草案） |  duration | 说明 |
|------|------|--------------|-----------|------|
| review_auto_pass_rate_low | medium | `sum(rate(reviews_total{result="approved"}[1h])) / sum(rate(reviews_total[1h])) < 0.7` | 1h | K1 跌破验收线；样本量过低时需配合最小样本门槛防抖动 |
| review_duration_slo_breach | high | `histogram_quantile(0.95, sum(rate(review_duration_seconds_bucket[1h])) by (le)) > 1800` | 1h | K2 P95 超 30 分钟（依赖 M1） |
| review_manual_intervention_rate_rising | medium | 人工介入率本周均值 > 上周均值 × 1.2 | 1d | K3 周对比显著上升，提示规则退化或生成质量下降（依赖 M2） |
| review_backlog_growing | low | `pending_review_count` 连续 2h 单调上升且 > 50 | 2h | A4 积压先行信号，阈值随公测量级重基线 |
| review_safety_bypass | critical | 安全误放样本出现（离线回放门禁转在线） | 即时 | A1 护栏，一票否决；在线形态为安全规则命中后仍 approved 的记录数 > 0 |

### SLO 条目（沿用 `telemetry/slo/slo-definitions.yaml` 格式，实施期增补）

| ID | 名称 | target | indicator | window | severity |
|----|------|--------|-----------|--------|----------|
| SLO-REVIEW-001 | Review Turnaround Latency | 0.95 | `review_duration_seconds` P95 < 1800s（按 review_type 分层） | 30d | blocker |
| SLO-REVIEW-002 | Auto Review Pass Rate | 0.70 | approved / 自动审核总判定（real_llm 口径，验收以离线轨为准） | 30d | blocker |

## 六、与 WP2 的衔接

- 阈值调优预案第一节衡量指标表中「人工介入率」由本文档 K3 承载；「自动通过率」「安全误放率」「应过误拒率」离线验收轨口径以 `M4-审核样本集设计.md` / `M4-阈值调优预案.md` 为权威，本文档不重复定义，只补充在线运行轨。

- WP2 的死参数发现（`DuplicateDetectionRule.max_similarity` 未接线）对本文档的含义：重复度规则的 A3 归因面板在实施期接线改造前只反映单对象多样度检测，标注解读时需注意。
