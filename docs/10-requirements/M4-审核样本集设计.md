# M4 审核样本集设计

> 文档状态：draft
> 适用阶段：M4 规划期（灰度发布解锁前）
> 维护要求：随 WP2 推进持续维护
> 关联工作包：M4-WP2 自动审核规则调优

## 目的

本文档定义 M4「自动审核规则调优」（WP2）所需的**审核样本集**：一套带「应过 / 应拒 / 应人工」标注的生成对象基准数据，用于：

1. 建立自动审核通过率的测量基线（验收口径：自动审核通过率 >70%）；
2. 为质量分、字段完整度、相似度三类阈值的回归调优提供判定依据；
3. 验证内容安全规则「一票否决」行为在任何调优中不被削弱。

本文档只回答「样本集怎么设计、怎么标注、怎么用」，不回答阈值应调成多少（属 WP2 实施期产出），也不定义审核流程本身（以 `docs/20-specs/content-generation-spec.md` 为准）。

## 适用范围

- 覆盖 `services/generation` 可生成的 7 类对象：npc / quest / region / settlement / monster / boss / item。
- 覆盖 `services/review` 自动审核引擎的 4 类规则：内容安全、字段完整度、重复度、质量分数。
- 不覆盖人工审核工作流、审核后台 UI、投票侧内容风控。

## 当前定位

- 本文档是 `M4-规模化内容生成规划.md` 第四节 WP2 的第一项规划期准备产出，与「阈值调优预案」「看板指标定义」并列。
- 规划期边界（继承 M4 规划第五节）：**只做设计与标注规范，不修改 `services/review` 任何代码与阈值常量，不新增敏感词，不接入外部依赖**。
- 样本集数据文件的落地构建（tools/ 脚本与 JSONL 数据）属 WP2 启动后的实施动作，不在本轮范围内。

## 一、审核引擎行为基线（2026-07-23 代码口径）

样本集的标签体系必须贴合引擎真实行为。以下为 `services/review/app/core/auto_review_engine.py` 的当前事实，标注与回归以此为基准：

### 规则与短路顺序

引擎按固定顺序评估，**首个返回非空结果的规则即终局**，全部规则未决则落入 `manual_review`：

| 顺序 | 规则 | 可产出结果 | 当前常量 |
|------|------|-----------|----------|
| 1 | ContentSafetyRule | rejected / manual_review | 敏感词 11 个 → rejected；高风险词 6 个 → manual_review；递归扫描 payload 全部字符串 |
| 2 | FieldCompletenessRule | rejected | min_completeness = 0.85；空串与纯空白计为缺失 |
| 3 | DuplicateDetectionRule | rejected | 仅检 description 字段；< 20 字符不检；字符多样度 < 0.3 → rejected |
| 4 | QualityScoreRule | approved / rejected | ≥ 0.8 → approved；< 0.5 → rejected；[0.5, 0.8) 不决 |

### 决策矩阵（标签语义由此导出）

| 场景 | 期望结果 |
|------|----------|
| 命中敏感词（暴力、色情等 11 词） | rejected（安全一票否决，无论质量分多高） |
| 命中高风险词（死亡、战争、瘟疫等 6 词） | manual_review |
| 字段完整度 < 0.85 | rejected |
| description 多样度 < 0.3 | rejected |
| 以上均未触发且质量分 ≥ 0.8 | approved |
| 以上均未触发且质量分 < 0.5 | rejected |
| 以上均未触发且质量分 ∈ [0.5, 0.8) 或为 None | manual_review |

### 两个易忽略的口径

- 生成侧另有前置门禁：质量评分 < 0.75 直接废弃（`.trae/rules/51-ai-content-generation.md`），因此真实链路中进入审核的样本质量分集中在 ≥ 0.75；但样本集仍须覆盖全量程，以支持阈值回归不依赖生成侧门禁恒成立。
- boss 类必填字段首项为 `monster_key`（与 monster 对齐），不是 `boss_key`。

## 二、样本分类体系

每条样本沿三个维度归类：

### 维度 1：期望结论（标注标签）

| 标签 | 引擎结果 | 用途 |
|------|----------|------|
| 应过（approved） | approved | 验证通过率与误拒率 |
| 应拒（rejected） | rejected | 验证拦截有效性 |
| 应人工（manual_review） | manual_review | 验证人工兜底与高危不误放 |

### 维度 2：触发规则（主要验证对象）

- `safety_sensitive`：敏感词命中样本（应拒）
- `safety_high_risk`：高风险词命中样本（应人工）
- `field_completeness`：字段缺失 / 空串 / 纯空白样本（应拒）
- `duplicate`：低多样度文本样本（应拒）
- `quality_approve` / `quality_reject`：质量分驱动样本
- `quality_boundary`：质量分过渡带样本（应人工）
- `clean`：无任何规则触发的干净样本（应过）

### 维度 3：样本层级（tier）

| tier | 含义 | 占比目标 |
|------|------|----------|
| core | 规则行为的常规验证 | ~60% |
| boundary | 阈值压线样本（质量分 0.75–0.85、完整度 0.80–0.90、description 长度 18–25 等） | ~25% |
| adversarial | 对抗与误伤样本（正常叙事语境含「战争」「瘟疫」等高风险词、历史典故含敏感词根、多语言混杂文本等） | ~15% |

## 三、样本规模设计

首版基准集（sampleset_v1）目标 **≥ 350 条**：7 类对象 × 每类 ≥ 50 条。

| 期望结论 | 占比 | 每类对象最低条数 | 构成要求 |
|----------|------|------------------|----------|
| 应过 | ~40%（≥ 140 条） | ≥ 20 | clean 为主，含少量 boundary 压线过样本 |
| 应拒 | ~35%（≥ 122 条） | ≥ 17 | 敏感词 ≥ 5、完整度 ≥ 5、低质量 ≥ 5、重复度 ≥ 2 |
| 应人工 | ~25%（≥ 88 条） | ≥ 13 | 高风险词 ≥ 3、质量过渡带 ≥ 8、对抗样本 ≥ 2 |

硬性约束（继承 M4 规划第七节风险表）：

- **安全样本强制入集**：每类对象敏感词命中样本 ≥ 5 条、高风险词命中样本 ≥ 3 条，覆盖词表全部 17 个词至少各 1 次。
- **安全召回一票否决**：任何阈值调优回归中，应拒安全样本的误放率必须为 0，该约束不可调。
- 质量分样本按 0.1 分带均匀铺开，[0.75, 0.85] 过渡带加密（阈值回归敏感区）。

## 四、样本存储格式

样本集以 JSONL（每行一条）存储，schema 与引擎入参结构（`object_type`、`object_payload`、`quality_score`）直接对齐，保证可脚本化回放：

```json
{
  "sample_id": "m4rs_npc_0001",
  "object_type": "npc",
  "object_payload": {"npc_key": "npc_xxx", "name": "...", "role": "...", "description": "...", "personality": "..."},
  "quality_score": 0.83,
  "expected_result": "approved",
  "expected_rule": "QualityScoreRule",
  "tier": "boundary",
  "source": "synthetic",
  "tags": ["quality_boundary"],
  "notes": "质量分压 0.8 上沿，验证 approve 边界"
}
```

字段约定：

- `expected_result` ∈ {approved, rejected, manual_review}；`expected_rule` 记录首要触发规则名，用于定位规则级回归差异。
- `quality_score` 可为 null（覆盖评分缺失落入人工的路径）。
- `source` ∈ {synthetic, real_llm, manual}：规划期全部为 synthetic；WP1 后追加 real_llm。
- 数据文件按版本组织：`sampleset_v1_core.jsonl`、`sampleset_v1_boundary.jsonl`、`sampleset_v1_adversarial.jsonl`（实施期落盘，建议位置 `services/review/tests/fixtures/` 或 `tools/` 数据目录，届时由 WP2 任务定）。

## 五、标注规范

### 标注流程

1. 双人独立标注：同一样本由两名标注者按决策矩阵独立给出 `expected_result` 与 `expected_rule`。
2. 一致性检查：结论一致直接入库；首批标注一致率目标 ≥ 90%。
3. 分歧仲裁：分歧样本由第三人按决策矩阵与 51 规则复核裁定，并在 `notes` 记录裁定理由。
4. 入库冻结：每批样本入库后只读，修正以新批次追加，不回改历史样本（保证回归可复现）。

### 边界 case 处理口径

- 正常游戏叙事语境命中高风险词（如「部族间的战争已结束百年」）：期望 **manual_review**，这是引擎当前正确行为，不是误报。
- 敏感词的合理语义变体（如武器名含「血腥」前缀的道具描述）：按当前引擎行为应 **rejected**；此类样本标注为 rejected 并打 `adversarial` tier，供 WP2 评估敏感词库细化需求，但**规划期不因此改动词表**。
- 质量分为 null：期望 manual_review。
- description < 20 字符的低多样度文本：重复度规则不触发，按其余规则判定。

## 六、样本来源规划

| 阶段 | 来源 | 用途 | 局限 |
|------|------|------|------|
| 规划期（当前） | synthetic：基于现有模板、骨架快照与规则常量手工 / 脚本构造 | 验证规则行为正确性、跑通回放与统计脚本 | 不代表真实 LLM 质量分布，**不能用于证明通过率达标** |
| 实施期（WP1 后） | real_llm：真实生成结果沉淀，随生成批次持续追加 | 建立真实通过率基线、支撑阈值回归定值 | 依赖运行时环境解锁 |

版本规划：`sampleset_v1`（规划期合成，本设计评审后冻结 schema）→ `sampleset_v2`（首批真实样本，WP1 产出后构建）。

## 七、统计与回归使用方式

- **通过率基线**：approved 判定数 / 总样本数，按对象类型与 source 分层报告；目标口径见 M4 验收（>70%）。
- **混淆矩阵**：expected × actual 的 3×3 矩阵，按规则维度下钻，定位误拒 / 误放集中于哪条规则。
- **调优回归门禁**（WP2 阈值变更的前置检查）：
  1. 安全应拒样本误放率 = 0（一票否决，不可调）；
  2. 应过样本误拒率 < 15%；
  3. 应人工样本被自动终结（approved / rejected）的比例不上升；
  4. 全量回放通过率变化须有样本级归因（哪批样本翻转了结论）。
- 回放脚本与统计报表属 WP2 实施动作，本设计只冻结输入 schema 与指标口径。

## 八、边界与不做事项

1. 不修改 `services/review` 任何代码、阈值常量与敏感词表（规划期硬约束）。
2. 不在本轮构建样本数据文件与回放脚本（属 WP2 启动后的实施动作）。
3. 合成样本不用于对外宣称「通过率 >70%」达标；达标判定只认 real_llm 样本基线。
4. 样本集不替代人工复核兜底；高风险主题的人工介入口径不可因调优削弱。

## 风险与注意事项

| 风险 | 级别 | 缓解 |
|------|------|------|
| 合成样本与真实分布偏离 | 中 | 明确 synthetic 局限；v2 以真实样本重建基线 |
| 标注口径漂移 | 中 | 决策矩阵作为唯一判定依据；双人标注 + 仲裁；分歧留痕 |
| 阈值调优损伤安全拦截 | 高 | 安全样本强制入集 + 误放率 0 的回归门禁，一票否决不可调 |
| 样本集无人维护腐化 | 低 | 版本化只读批次；WP2 每个调优动作必须引用样本版本号 |
