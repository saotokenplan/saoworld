# M4 阈值调优预案

> 文档状态：draft
> 适用阶段：M4 规划期（灰度发布解锁前）
> 维护要求：随 WP2 推进持续维护
> 关联工作包：M4-WP2 自动审核规则调优

## 目的

本文档定义 M4「自动审核规则调优」（WP2）实施期的**阈值调优预案**：在真实样本到位前，预先固化「调什么参数、按什么顺序调、每步调完怎么验收、出什么问题了怎么退」的决策框架，避免实施期在真实样本基线出来后临场拍脑袋。

本文档只回答「调优怎么进行」，不给出任何阈值定值（定值是 WP2 实施期基于 `sampleset_v2` 真实样本回放的产出），也不重复样本集本身的设计（以 `M4-审核样本集设计.md` 为准）。

## 适用范围

- 覆盖 `services/review` 自动审核引擎 4 类规则的全部常量与可调参数。
- 覆盖调优的衡量指标、分场景预案、变更流程与回退口径。
- 不覆盖审核流程本身（以 `docs/20-specs/content-generation-spec.md` 为准）、不覆盖生成侧质量门禁调优（属 WP1 与 `.trae/rules/51-ai-content-generation.md` 范围）。

## 当前定位

- 本文档是 `M4-规模化内容生成规划.md` 第四节 WP2 的第二项规划期准备产出，上游依赖 `M4-审核样本集设计.md`（样本版本、回归门禁与测量口径以其为准）。
- 规划期边界（继承 M4 规划第五节）：**只做预案设计，不修改 `services/review` 任何代码与常量，不新增词表，不接入外部依赖，不构建回放脚本**。
- 所有阈值定值、回放脚本与统计报表均属 WP2 启动后的实施动作。

## 一、调优目标与衡量指标

调优的总目标来自 M4 验收口径（`项目里程碑与验收标准.md` §2.4）：**自动审核通过率 >70%，且不误放高风险内容**。

| 指标 | 目标 | 测量口径 |
|------|------|----------|
| 自动通过率 | > 70% | approved 判定数 / 总样本数，按对象类型与 source 分层；只认 real_llm 样本（sampleset_v2 起） |
| 安全误放率 | = 0 | 应拒安全样本被判 approved 的比例；一票否决，不可调 |
| 应过误拒率 | < 15% | 应过样本被判 rejected 的比例 |
| 人工介入率 | 持续下降或不升 | manual_review 判定占比，按周对比；WP3 看板承载 |
| 应人工自动终结比例 | 不上升 | 应人工样本被判 approved / rejected 的比例（默认门禁，场景 B 例外见第四节） |

## 二、参数清单与可调性分级（2026-07-23 代码口径）

以下清单以 `services/review/app/core/auto_review_engine.py` 当前实现为准，是全部调优动作的完整参数空间。引擎按固定顺序短路评估：ContentSafetyRule → FieldCompletenessRule → DuplicateDetectionRule → QualityScoreRule，首个非空结果即终局，全部未决落入 manual_review。

### 可调参数（构造函数注入，无需改代码即可回归）

| 参数 | 当前默认 | 所属规则 | 规划期可调性 |
|------|----------|----------|--------------|
| `approve_threshold` | 0.8 | QualityScoreRule | 实施期主旋钮；质量分 ≥ 此值判 approved |
| `reject_threshold` | 0.5 | QualityScoreRule | 实施期次旋钮；质量分 < 此值判 rejected |
| `min_completeness` | 0.85 | FieldCompletenessRule | 实施期候选旋钮；完整度低于此值判 rejected |

### 硬编码常量（调优需改代码，属实施期改造项）

| 常量 | 当前值 | 位置 | 说明 |
|------|--------|------|------|
| 重复度多样度线 | 0.3 | DuplicateDetectionRule.evaluate | description 字符多样度 < 0.3 判 rejected，硬编码 |
| 重复度检测长度门槛 | 20 字符 | DuplicateDetectionRule.evaluate | description < 20 字符跳过检测，硬编码 |
| 必填字段表 | 7 类对象各 4–6 字段 | FieldCompletenessRule.REQUIRED_FIELDS_BY_TYPE | boss 首项为 `monster_key`（非 `boss_key`）；改表属代码变更 |

### 已发现死参数（实施期改造前置项）

- `DuplicateDetectionRule.max_similarity = 0.8`：**已于 2026-07-26（auto-20260726-0000）接线**。原 `evaluate()` 硬编码 `diversity_ratio < 0.3` 阈值、完全忽略该参数；现改为以 `1 - 字符多样度` 近似「自相似度」，当 `self_similarity >= max_similarity` 时判 rejected，默认值 0.8 正式生效。同时新增 `self_similarity` / `cross_similarity`（字符级 Jaccard）两个纯函数，为第四节场景 D 的跨样本相似度接线提供可单测基础。
  - 接线范围说明：本轮仅完成「单对象自相似度阈值接线 + 函数基础」，**未**接入跨样本语料（需 PostgreSQL 运行时中的既有对象集合），场景 D 的完整跨样本回放验证仍属运行时验证阶段。
  - 不做调优：规划期 / 本预案明确禁止在无真实样本回放前提下降 / 升阈值，本轮仅将参数接线为预案登记的默认 0.8，未做任何数值调优。
- 影响（原记录，已消解）：M4 规划 WP2「同章节内容相似度阈值 <0.8 的实测验证」此前在当前实现下没有可调对象；自 2026-07-26 起 `max_similarity` 已为可调对象，跨样本接线待运行时语料注入。本预案第四节场景 D 给出验证方法。

### 不可调项（安全边界）

| 项 | 当前值 | 约束 |
|----|--------|------|
| 敏感词表 | 11 词，命中即 rejected | 一票否决行为不可降级；词表增删走安全评审（`.trae/rules/50-security.md`），不属于阈值调优 |
| 高风险词表 | 6 词，命中即 manual_review | 同上；不得通过调优让高危样本自动终结 |
| 规则短路顺序 | 安全 → 完整度 → 重复度 → 质量分 | 调整顺序属架构变更，不在本预案范围 |
| 生成侧废弃线 | 质量分 < 0.75 直接废弃 | 属 51 规则与 WP1 范围；它是 approve_threshold 的下限约束（见第四节场景 A） |

## 三、调优方法论

实施期每次调优按以下闭环执行，任何一步缺失则该次调优无效：

1. **基线测量**：在样本集（定值用 `sampleset_v2` 真实样本）上回放当前常量，记录五项指标基线与 3×3 混淆矩阵。
2. **候选生成**：按第四节场景预案选取旋钮与候选档位；每次调优只动一个旋钮（多参数联动须拆成多轮）。
3. **离线回放**：候选值在只读样本集上全量回放，产出逐样本结论翻转清单。
4. **门禁检查**：五项指标 + 样本级归因全部过检才进入下一步；任一破防即放弃该候选。
5. **评审冻结**：按第五节流程双签冻结，阈值版本、样本集版本、回放报告三者绑定留痕。
6. **线上观测**：WP3 看板跟踪真实通过率与人工介入率，与回放预期对比，偏差 >10 个百分点触发复盘。

工具前提（实施期首批动作）：样本回放脚本、指标统计报表。输入 schema 已在样本集设计中冻结，本预案不再展开。

## 四、分场景调优预案

### 场景 A：真实基线通过率 < 70%（最可能触发）

- 判定：`sampleset_v2` 基线自动通过率未达 70%，且误拒集中在 QualityScoreRule 过渡带下沿。
- 首选旋钮：`approve_threshold` 阶梯下调 0.80 → 0.78 → 0.75，每档全量回放。
- 硬约束：`approve_threshold` 不得低于 0.75——51 规则规定质量分 < 0.75 的内容在生成侧已废弃，审核 approve 线若低于此值，等于自动放行生成侧本就判定不合格的内容，审批链路失去区分度。
- 门禁重点：boundary 层应人工样本不得被翻成 approved；安全误放率保持 0。
- 回退口径：任一档位门禁破防，回到上一通过档位；三档全部破防则冻结调优，转查生成侧质量分布（WP1 问题，非审核问题）。

### 场景 B：人工介入率过高，过渡带样本堆积

- 判定：manual_review 占比显著高于样本集设计的 ~25% 预期，且堆积集中在质量分 [0.5, 0.8) 过渡带。
- 候选动作：收窄过渡带（`approve_threshold` 微降 + `reject_threshold` 自 0.5 微升，拆两轮执行）。
- 例外说明：本场景的目标是主动把一部分应人工样本转为自动终结，与默认门禁「应人工自动终结比例不上升」直接冲突。处理口径：
  1. 逐样本人工复核拟转入自动结论的样本，确认可自动终结；
  2. 命中高风险词的样本一律不在转入范围；
  3. 该场景变更须审核域 + 安全域双签，审批级别高于常规调优。
- 回退口径：转入自动的样本在后续任一批次被人工推翻 ≥ 5%，立即回退。

### 场景 C：完整度误拒集中

- 判定：误拒样本主要触发 FieldCompletenessRule。
- 先诊断后调参：若误拒集中在「生成模板本就不产出的字段」，问题在 `REQUIRED_FIELDS_BY_TYPE` 字段表而非阈值——调 `min_completeness` 无效，应列为实施期字段表修订项（代码变更）。
- 候选动作：确认字段表无误后，`min_completeness` 0.85 → 0.80 单档回放；空串 / 纯空白计缺失的口径不变。
- 门禁重点：应拒的字段缺失样本不得被翻成 approved / manual_review。

### 场景 D：重复度漏检（WP2「相似度 <0.8 实测验证」）

- 判定：同章节 / 同批次内容出现实质重复但引擎未拦截。
- 现状结论：当前实现无跨样本相似度能力，`max_similarity` 未接线，**没有可调阈值**。本场景不产生调参动作。
- 实施期改造项：实现跨样本相似度计算（候选口径：同章节内 description 两两相似度），接线 `max_similarity`（默认 0.8 起步），补重复度样本回放验证。
- 规划期动作：仅冻结验证方法（相似度口径、样本构造方式、门禁沿用统一五项），数值定值留待实施期。

## 五、变更流程与版本管理

1. **提议**：任何阈值变更提议必须引用样本集版本号 + 全量回放报告 + 候选值与预期影响，缺一不可。
2. **评审**：常规调优由审核域负责人评审；涉及安全边界、场景 B 例外或词表的变更，须安全域加签（`.trae/rules/50-security.md`）。
3. **冻结**：常量变更入代码必须带变更注释与 changelog；阈值版本、样本集版本、回放报告三者绑定，支持任意时点复现。
4. **回退**：任何门禁破防或线上观测显著偏离回放预期，回退至上一冻结阈值版本，并复盘归因后再提议。
5. **留痕**：每次调优在 `docs/40-dev-loop/` 留存执行记录，样本集按版本只读追加，不回改历史。

## 六、不可调边界与不做事项

1. 安全一票否决逻辑不可调；敏感词命中判 rejected 的行为不得因任何通过率目标被削弱。
2. 词表增删不属于阈值调优，一律走安全评审流程。
3. 规则短路顺序调整属架构变更，不在本预案范围。
4. 合成样本（sampleset_v1）只用于验证规则行为与跑通回放，不得用于对外宣称通过率达标；达标判定只认 real_llm 样本基线。
5. 规划期不修改 `services/review` 任何代码、常量与配置；本预案的全部数值动作均在 WP2 启动后执行。

## 风险与注意事项

| 风险 | 级别 | 缓解 |
|------|------|------|
| 阈值过拟合样本集 | 中 | 样本集版本化只读；调优后在新批次样本上复测；线上观测与回放对账 |
| 真实分布与样本集偏离 | 中 | v2 起只用 real_llm 样本定值；分布漂移触发样本集增补而非硬调阈值 |
| 指标博弈（为通过率压安全） | 高 | 安全误放率 = 0 一票否决；场景 B 例外双签；高危样本强制入集 |
| 多参数联动互相掩盖 | 中 | 每次只动一个旋钮；联动需求拆多轮；逐样本翻转清单归因 |
| 死参数误判为可调 | 低 | 本预案第二节显式登记；实施期改造前禁止以 `max_similarity` 名义提调优 |
