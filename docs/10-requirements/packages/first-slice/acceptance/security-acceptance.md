# 安全验收标准

> 版本：v1.0.0
> 创建时间：2026-07-04

## 概述

安全验收标准定义了投票系统的安全要求和验收测试用例，确保系统在认证授权、数据安全、风险控制等方面符合安全规范。

## 认证与授权验收

### JWT 认证验收

**验收要求**：
- 所有受保护接口必须验证 JWT Token
- Token 格式错误应返回 401 错误
- Token 过期应返回 401 错误
- Token 签名无效应返回 401 错误
- 未携带 Token 应返回 401 错误

**测试用例**：
- 未携带 Token 请求受保护接口应返回 401 错误 ✓
- Token 格式错误应返回 401 错误 ✓
- Token 过期应返回 401 错误 ✓
- Token 签名无效应返回 401 错误 ✓
- 有效 Token 请求受保护接口应成功 ✓

### Scope 权限校验验收

**验收要求**：
- 玩家接口校验 `votes:read`、`votes:submit`、`votes:history:read` scope
- 运营接口校验 `ops:vote-cycles:write` scope
- 缺少所需 scope 应返回 403 错误

**测试用例**：
- 玩家接口缺少 `votes:read` scope 应返回 403 错误 ✓
- 玩家接口缺少 `votes:submit` scope 应返回 403 错误 ✓
- 玩家接口缺少 `votes:history:read` scope 应返回 403 错误 ✓
- 运营接口缺少 `ops:vote-cycles:write` scope 应返回 403 错误 ✓
- 携带正确 scope 请求对应接口应成功 ✓

### 角色权限校验验收

**验收要求**：
- 玩家角色只能访问玩家接口
- 运营角色可以访问玩家接口和运营接口
- 审核角色只能访问审核相关接口
- 系统角色只能访问内部接口

**测试用例**：
- 玩家角色访问运营接口应返回 403 错误 ✓
- 运营角色访问玩家接口应成功 ✓
- 运营角色访问运营接口应成功 ✓
- 审核角色访问运营接口应返回 403 错误 ✓

## 数据安全验收

### 数据加密验收

**验收要求**：
- 所有接口必须使用 HTTPS
- 密码等敏感字段必须加密存储
- 传输过程中数据必须加密

**测试用例**：
- HTTP 请求应自动重定向到 HTTPS ✓
- 敏感字段传输时使用 TLS 加密 ✓

### 数据脱敏验收

**验收要求**：
- 响应中不返回敏感字段（如密码、Token 等）
- 日志中不记录敏感信息

**测试用例**：
- 响应中不包含敏感字段 ✓
- 日志中不包含敏感信息 ✓

### 输入验证验收

**验收要求**：
- 所有输入参数必须进行校验
- 防止 SQL 注入攻击
- 防止 XSS 攻击
- 防止恶意文件上传

**测试用例**：
- SQL 注入攻击应被阻止 ✓
- XSS 攻击应被阻止 ✓
- 参数格式验证应生效 ✓
- 参数范围验证应生效 ✓

### 输出编码验收

**验收要求**：
- 所有输出内容必须进行适当编码
- 防止 XSS 攻击

**测试用例**：
- 输出内容正确编码 ✓
- 防止 XSS 攻击 ✓

## 风险控制验收

### 幂等性控制验收

**验收要求**：
- 同一 Idempotency-Key 重复提交只执行一次
- Idempotency-Key 全局唯一
- 幂等键存储在数据库中

**测试用例**：
- 同一 Idempotency-Key 重复提交只执行一次 ✓
- 不同 Idempotency-Key 可以正常提交 ✓
- 使用已存在的 Idempotency-Key 提交应返回首次结果 ✓

### 频率限制验收

**验收要求**：
- 投票提交接口有频率限制
- 运营接口有频率限制
- 触发频率限制应返回 429 错误

**测试用例**：
- 投票提交接口超过频率限制应返回 429 错误 ✓
- 运营接口超过频率限制应返回 429 错误 ✓
- 频率限制后应在一段时间后恢复 ✓

### 设备指纹校验验收

**验收要求**：
- 投票提交时校验设备指纹
- 异常设备行为应被识别

**测试用例**：
- 设备指纹校验正常 ✓
- 异常设备行为应被识别 ✓

### 行为风控验收

**验收要求**：
- 识别异常投票行为模式
- 异常行为应触发风控拦截

**测试用例**：
- 异常投票行为应被识别 ✓
- 异常行为应触发风控拦截 ✓

## 审计日志验收

### 审计日志记录验收

**验收要求**：
- 所有敏感操作必须记录审计日志
- 审计日志包含完整的操作信息
- 审计日志通过 trace_id 关联

**测试用例**：
- 投票提交后审计日志记录正确 ✓
- 投票周期创建后审计日志记录正确 ✓
- 投票周期状态迁移后审计日志记录正确 ✓
- 投票结算后审计日志记录正确 ✓
- 审计日志通过 trace_id 关联正确 ✓

### 审计日志字段验收

**验收要求**：
- 审计日志包含 `request_id`
- 审计日志包含 `trace_id`
- 审计日志包含 `operator_role`
- 审计日志包含 `operator_id`
- 审计日志包含 `action`
- 审计日志包含 `target_id`
- 审计日志包含 `reason`
- 审计日志包含 `result`
- 审计日志包含 `occurred_at`

**测试用例**：
- 审计日志包含所有必填字段 ✓
- 审计日志字段值正确 ✓

### 审计日志查询验收

**验收要求**：
- 运营可以查询审计日志
- 支持按 trace_id 查询
- 支持按 operator_id 查询
- 支持按 action 查询
- 支持按 resource_type 和 resource_id 查询

**测试用例**：
- 按 trace_id 查询审计日志 ✓
- 按 operator_id 查询审计日志 ✓
- 按 action 查询审计日志 ✓
- 按 resource_type 和 resource_id 查询审计日志 ✓

## 会话安全验收

### Token 管理验收

**验收要求**：
- Access Token 应有过期时间
- Refresh Token 应有过期时间
- Token 过期后应重新获取

**测试用例**：
- Access Token 过期后请求应返回 401 错误 ✓
- Refresh Token 过期后应重新登录 ✓

**验收要求**：
- 使用 HTTPS 防止 Token 被窃听
- Token 应存储在安全位置
- 防止 CSRF 攻击

**测试用例**：
- CSRF 攻击应被阻止 ✓
- Token 通过 HTTPS 传输 ✓
