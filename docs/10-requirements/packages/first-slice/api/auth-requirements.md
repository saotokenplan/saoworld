# 认证与权限要求

> 版本：v1.0.0
> 创建时间：2026-07-04

> 说明：本文档用于快速理解最小投票链路的认证、权限与审计关注点；JWT 声明、Scope 矩阵、请求头要求、错误码和审计字段的正式定义以 `docs/30-api/`、`docs/20-specs/backend-data-spec.md` 和相关安全规范为准。

## 认证视图

| 主题 | 本切片需要理解什么 |
|------|------------------|
| 认证方式 | 受保护接口统一使用 OIDC 签发的 JWT Bearer Token |
| 角色划分 | 至少区分 `player`、`ops`、`reviewer`、`system` 四类角色 |
| Scope 控制 | 玩家与运营接口需要按最小权限原则拆分访问能力 |
| 请求追踪 | 写接口需要链路追踪字段，运营写接口需要幂等保护 |
| 审计要求 | 敏感操作必须可追踪到操作者、原因和结果 |

## 最小链路关注点

### 玩家侧

- 读取当前投票、提交投票、查看历史结果需要不同 Scope
- 提交投票不仅要认证成功，还要满足玩家身份、风控和幂等要求

### 运营侧

- 创建、推进、开放、关闭和结算投票周期都属于敏感操作
- 运营写接口必须能回溯操作者、操作原因和链路标识

### 系统侧

- 自动化任务和内部状态流转需要使用系统身份
- 系统身份不应直接暴露为普通客户端可用权限

## 安全与风控关注点

- Token 传输必须走 HTTPS
- 权限控制遵循最小权限原则
- 关键写操作需要幂等与审计
- 投票提交需要设备或行为风控能力
