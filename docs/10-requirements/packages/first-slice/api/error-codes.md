# 错误码清单

> 版本：v1.0.0
> 创建时间：2026-07-04

> 说明：本文档用于快速理解最小投票链路会遇到的错误场景；正式错误码枚举与命名以 `docs/30-api/api-error-codes.md` 和 `docs/20-specs/backend-data-spec.md` 为准。如出现同义 code，优先以源规范收敛。

## 阅读方式

- 本文档只保留最小投票链路需要理解的错误场景分组。
- 具体错误码命名、HTTP 状态码、`details.issue` 枚举和响应结构请以源规范为准。
- 如果业务文档中的错误场景与正式 code 不一致，应优先修改业务文档，而不是扩充第二套 code 表。

## 投票接口错误码

| 错误场景分组 | 业务上要理解什么 |
|------------|------------------|
| 周期不存在或状态不允许 | 玩家或运营操作发生在错误时间窗，当前周期不可用 |
| 候选项不存在或不属于当前周期 | 玩家提交的目标无效，或与当前周期不匹配 |
| 玩家无资格或重复投票 | 玩家不满足投票条件，或重复提交被拒绝 |
| 风控阻断 | 系统识别到设备或行为风险，不允许继续投票 |
| 运营操作冲突 | 创建、开放、结算等动作与当前状态或数据条件冲突 |

## 使用建议

### 客户端

- 对 401 和 403 做明确鉴权提示，不要混用
- 对 400 带 details 的错误，可按 field 和 issue 做表单级错误映射
- 对 409 做状态冲突处理，不要直接重试所有请求
- 对 429 做指数退避和频率提示

### 服务端

- 同一错误语义只使用一个稳定 code，不要为同类错误新造近义词
- 不要把数据库底层异常直接透传给客户端
- 对运营和审核写接口，错误响应中仍应保留 request_id 方便审计
- 参数校验错误应尽可能提供 details 数组
