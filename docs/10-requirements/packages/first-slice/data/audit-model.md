# 审计日志模型

> 版本：v1.0.0
> 创建时间：2026-07-04

> 说明：本文档用于快速理解最小投票链路中的审计对象、记录时机与检索价值；正式字段、索引、分区、append-only 约束和 action/resource 枚举以 `docs/20-specs/backend-data-spec.md` 与相关安全规范为准。

## 审计模型视图

| 主题 | 本切片需要理解什么 |
|------|------------------|
| 记录对象 | 玩家投票、投票周期创建与状态迁移、结算、发布等敏感操作都应进入审计链 |
| 关键标识 | `trace_id`、`request_id`、操作者身份、动作、资源和结果需要可追溯 |
| 使用价值 | 支持问题排查、责任归属、风控复核和发布回溯 |
| 存储特性 | 审计日志是高价值追加型数据，不应被普通业务流程覆盖或篡改 |

## 最小投票链路中的重点场景

- 玩家提交投票
- 运营创建和推进投票周期
- 系统或运营执行投票结算
- 后续内容发布或回滚动作

## 读者最该关注的点

- 每条记录都需要能回答“谁在什么时候对什么做了什么，结果如何”
- 链路标识需要支持把一次操作串联到 API、任务和日志
- 运营类写操作需要能回看操作原因
