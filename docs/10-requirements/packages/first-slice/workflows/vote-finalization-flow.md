# 投票结算流程

> 版本：v1.0.0
> 创建时间：2026-07-04

> 说明：本文档用于从流程视角说明投票关闭后如何完成结算，并把结果交给后续内容链路；正式状态迁移、事件结构、错误码和幂等规则以 `docs/20-specs/backend-data-spec.md` 与相关源规范为准。

## 流程摘要

1. 投票周期关闭，玩家不再允许继续提交
2. 系统汇总该周期下的有效投票记录
3. 系统按候选项计算加权结果并确定获胜方向
4. 系统更新候选项和周期状态，标记本轮已完成结算
5. 系统写入结算审计日志，并把结果交给后续内容链路

## 触发方式

- 自动触发：周期达到结束时间后由系统关闭并进入结算
- 手动触发：运营在合规前提下关闭周期或发起结算

## 关键检查点

### 关闭阶段

- 只有开放中的周期才能进入关闭
- 关闭后必须立即停止新的投票提交
- 关闭动作需要留下可追溯的审计记录

### 计票阶段

- 只统计属于当前周期的有效投票
- 结果计算要体现权重规则
- 计票逻辑应保证重复执行不会产生不同结果

### 判定阶段

- 获胜方向需要有明确的判定逻辑
- 极端接近或特殊场景需要有补充裁决规则
- 结算结果需要能被玩家展示和后续生成链路共同消费

### 输出阶段

- 周期需要进入已结算状态
- 获胜候选项、统计摘要和结算时间需要可回查
- 结果需要能够继续关联内容包、区域影响和发布时间

## 常见异常场景

- 周期尚未关闭却尝试结算
- 当前周期没有有效候选项或有效投票
- 多次触发结算时需要返回一致结果
- 结果写入或后续链路通知失败时需要保留回溯信息
