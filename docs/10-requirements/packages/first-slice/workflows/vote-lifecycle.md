# 投票生命周期流程

> 版本：v1.0.0
> 创建时间：2026-07-04

## 概述

投票生命周期描述了投票从创建到结算的完整流程，包含运营管理和玩家参与两个视角。

## 运营视角流程

### 阶段 1：创建投票周期（draft）

**触发条件**：运营决定发起新的投票周期

**操作步骤**：
1. 运营登录后台管理系统
2. 进入投票管理页面
3. 点击"创建投票周期"按钮
4. 填写投票周期信息：
   - 所属章节（chapter_id）
   - 开始时间（starts_at）
   - 结束时间（ends_at）
   - 创建原因（created_reason）
5. 添加候选项（3-5 个）：
   - 候选项标题
   - 描述摘要
   - 详细描述
   - 影响区域
   - 风险标签
6. 点击"保存"按钮
7. 系统创建投票周期记录，状态为 draft

**输出**：
- 投票周期创建成功
- 返回 vote_cycle_id
- 记录审计日志（action: vote_cycle_create）

### 阶段 2：计划投票周期（scheduled）

**触发条件**：运营确认投票周期配置完整

**操作步骤**：
1. 运营在后台查看 draft 状态的投票周期
2. 确认配置信息和候选项完整
3. 点击"计划"按钮
4. 填写计划原因
5. 系统校验配置完整性
6. 系统更新状态为 scheduled

**校验规则**：
- 必须至少有一个 active 状态的候选项
- starts_at 必须小于 ends_at
- created_by 和 created_reason 必须存在

**输出**：
- 投票周期状态更新为 scheduled
- 记录审计日志（action: vote_cycle_scheduled）

### 阶段 3：开放投票（open）

**触发条件**：达到开始时间或运营手动开放

**操作步骤**：
1. 系统定时检查 scheduled 状态的投票周期
2. 当当前时间 >= starts_at 时，自动触发开放
3. 或运营手动点击"开放"按钮
4. 系统校验：
   - 当前章节没有其他 open 状态的投票周期
   - 至少有一个 active 状态的候选项
5. 系统更新状态为 open
6. 系统记录审计日志

**校验规则**：
- 同一章节下只能有一个 open 状态的投票周期
- 必须至少有一个 active 状态的候选项

**输出**：
- 投票周期状态更新为 open
- 玩家可开始提交投票
- 记录审计日志（action: vote_cycle_opened）

### 阶段 4：关闭投票（closed）

**触发条件**：达到结束时间或运营手动关闭

**操作步骤**：
1. 系统定时检查 open 状态的投票周期
2. 当当前时间 >= ends_at 时，自动触发关闭
3. 或运营手动点击"关闭"按钮
4. 系统更新状态为 closed
5. 系统记录审计日志

**输出**：
- 投票周期状态更新为 closed
- 玩家不可再提交投票
- 记录审计日志（action: vote_cycle_closed）

### 阶段 5：结算投票（finalized）

**触发条件**：运营确认计票结果

**操作步骤**：
1. 运营在后台查看 closed 状态的投票周期
2. 点击"结算"按钮
3. 系统执行计票流程：
   - 查询该周期下所有有效投票记录
   - 按候选项分组统计（考虑权重）
   - 计算每个候选项的加权总分
   - 确定获胜候选项
4. 系统更新获胜候选项状态为 selected
5. 系统更新投票周期状态为 finalized
6. 系统记录结算时间和获胜候选项
7. 系统记录审计日志

**计票规则**：
- 加权总分最高的候选项为获胜者
- 若前两名差值小于阈值，触发剧情一致性裁决

**输出**：
- 投票周期状态更新为 finalized
- 获胜候选项标记为 selected
- 返回结算结果（各候选项票数、获胜者）
- 记录审计日志（action: vote_cycle_finalized）

## 玩家视角流程

### 阶段 1：查看当前投票

**操作步骤**：
1. 玩家登录游戏
2. 进入投票界面
3. 系统查询当前 open 状态的投票周期
4. 系统返回投票周期信息和候选项列表
5. 玩家查看候选项详情

**输出**：
- 投票周期信息（标题、时间、候选项）
- 候选项详情（描述、影响区域、风险标签）

### 阶段 2：提交投票

**操作步骤**：
1. 玩家选择一个候选项
2. 玩家点击"投票"按钮
3. 系统校验：
   - 投票周期状态为 open
   - 玩家未在本周期投过票
   - 候选项存在且状态为 active
   - 玩家满足投票资格
4. 系统生成投票记录
5. 系统记录审计日志

**校验规则**：
- 同一玩家在同一周期内只能投一票
- 必须提供 Idempotency-Key
- 设备指纹校验

**输出**：
- 投票成功确认
- 记录投票记录到 votes 表
- 记录审计日志（action: vote_submit）

### 阶段 3：查看投票结果

**操作步骤**：
1. 投票结算后，玩家进入投票界面
2. 系统查询 finalized 状态的投票周期
3. 系统返回投票结果：
   - 总票数
   - 各候选项票数和占比
   - 获胜候选项
   - 预计影响区域
   - 预计上线周期

**输出**：
- 投票结果统计
- 获胜候选项信息
- 历史投票结果落地情况

## 状态迁移矩阵

| 当前状态 | 目标状态 | 操作 | 角色 |
|----------|----------|------|------|
| draft | scheduled | 计划 | ops |
| scheduled | open | 开放 | ops/system |
| open | closed | 关闭 | ops/system |
| closed | finalized | 结算 | ops/system |
| closed | open | 重新开放 | ops |

## 关键约束

1. **唯一性约束**：同一章节下同时只能有一个 open 状态的投票周期
2. **完整性约束**：创建时必须包含 chapter_id、starts_at、ends_at、created_by、created_reason
3. **审计约束**：所有状态迁移操作必须记录审计日志
4. **幂等性约束**：投票提交必须支持幂等重试
5. **时间约束**：ends_at 必须大于 starts_at
