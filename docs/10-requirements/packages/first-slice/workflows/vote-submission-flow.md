# 投票提交流程

> 版本：v1.0.0
> 创建时间：2026-07-04

> 说明：本文档用于从流程视角说明玩家如何完成一次有效投票；正式请求结构、错误码、字段约束和性能门槛以 `docs/30-api/` 与 `docs/20-specs/backend-data-spec.md` 为准。

## 流程摘要

1. 玩家进入投票界面并查询当前开放周期
2. 客户端展示候选项摘要、时间窗和影响信息
3. 玩家选择候选项并发起投票提交
4. 服务端完成认证、资格、周期、候选项、幂等和风控检查
5. 系统写入投票记录并记录审计日志
6. 客户端展示提交结果，并在当前周期内避免重复投票

## 关键检查点

### 查询当前投票

- 玩家需要先确认当前是否存在开放周期
- 候选项信息应足够支持玩家做出选择
- 当前周期、候选项和倒计时信息应保持一致

### 提交前校验

- 玩家身份和所需 Scope 必须有效
- 候选项必须属于当前开放周期
- 玩家必须满足资格要求，且当前周期仍处于可投窗口

### 提交保护

- 同一玩家在同一周期内只能完成一次有效投票
- `Idempotency-Key` 需要支持网络重试场景
- 风控能力需要阻断异常设备或异常行为

### 提交后结果

- 系统需要返回可追踪的提交结果
- 客户端需要把当前周期视为“已投”状态
- 审计链需要能回溯玩家、候选项、处理结果和链路标识

## 常见失败场景

- 当前没有开放周期
- 候选项不存在或不属于当前周期
- 玩家资格不足或已在本周期投票
- 请求命中风控或幂等冲突
