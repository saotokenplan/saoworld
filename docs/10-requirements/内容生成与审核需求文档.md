# 内容生成与审核需求文档

> 文档状态：active
> 适用阶段：需求实现
> 维护要求：持续维护
> 更新频率：每Sprint更新

## 文档定位

本文档定义AI内容生成与审核的完整流程和需求，确保生成内容质量可控、安全合规、符合世界观设定。

---

## 一、内容生成流程

### 1.1 生成流程概述

```
投票结算 → 生成参数提取 → 模板匹配 → AI生成 → 质量评分 → 规则审核 → 人工复核 → 打包发布
```

### 1.2 各阶段职责

| 阶段 | 职责 | 产出 |
|------|------|------|
| 投票结算 | 确定高票候选方向 | 生成参数草案 |
| 生成参数提取 | 将投票结果转换为结构化参数 | generated_params |
| 模板匹配 | 根据生成类型选择合适模板 | 模板ID + 填充参数 |
| AI生成 | 调用LLM生成内容 | 生成内容对象 |
| 质量评分 | 自动评估生成质量 | 质量分数（0-1） |
| 规则审核 | 校验设定一致性、数值、安全 | 审核通过/拒绝 |
| 人工复核 | 高风险内容人工审核 | 复核意见 |
| 打包发布 | 打包为内容包，灰度发布 | 内容包 |

## 二、生成对象需求

### 2.1 NPC生成

| 项目 | 内容 |
|------|------|
| 生成目标 | NPC身份、职业、性格、对话风格、关系网 |
| 优先级 | P0 |

**生成字段**：

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| npc_id | string | 唯一ID，前缀`npc_` | 是 |
| name | string | NPC名称 | 是 |
| title | string | 称号/头衔 | 是 |
| occupation | string | 职业 | 是 |
| faction_id | string | 所属阵营 | 是 |
| personality_tags | array | 性格标签（3-5个） | 是 |
| description | string | 描述（100-200字） | 是 |
| dialogue_style | string | 对话风格（正式/幽默/神秘等） | 是 |
| location_id | string | 常驻地点 | 是 |
| relationship_map | object | 与其他NPC的关系 | 否 |
| quest_ids | array | 关联任务ID列表 | 否 |
| schema_version | int | schema版本 | 是 |

**生成约束**：
- NPC名称不得与现有NPC重复
- 性格标签必须符合阵营设定
- 描述必须符合区域背景
- 对话风格必须与性格一致

**验收标准**：
- 生成字段完整度 > 95%
- 符合世界观设定
- 与现有NPC相似度 < 0.8
- 对话风格一致

**相关需求**：S2-02

## 四、质量评分需求

### 4.1 评分维度

| 维度 | 权重 | 说明 |
|------|------|------|
| 完整性 | 20% | 字段是否齐全 |
| 一致性 | 30% | 是否符合世界观设定 |
| 合理性 | 25% | 数值、逻辑是否合理 |
| 原创性 | 15% | 是否与现有内容重复 |
| 可玩性 | 10% | 是否适合作为游戏内容 |

### 4.2 评分规则

| 分数范围 | 处理方式 |
|----------|----------|
| >= 0.85 | 直接通过，进入打包 |
| 0.75 - 0.85 | 进入人工复核 |
| < 0.75 | 直接废弃，重新生成 |

### 4.3 评分系统

| 项目 | 内容 |
|------|------|
| 目标 | 自动评估生成内容质量 |
| 优先级 | P0 |

**用户故事**：
- 作为系统，我希望自动评估生成内容的质量，以便筛选优质内容
- 作为系统，我希望根据评分结果自动决定处理方式，以便提高效率
- 作为策划，我希望查看评分详情，以便优化模板

**验收标准**：
- 自动计算五个维度的评分
- 总分准确反映内容质量
- 根据分数自动决定处理方式
- 提供评分详情供分析

**相关需求**：S2-05

## 五、规则审核需求

### 5.1 审核维度

| 维度 | 审核内容 | 处理方式 |
|------|----------|----------|
| 一致性检查 | 阵营关系、NPC身份、时间线、地理约束 | 冲突则拒绝 |
| 数值平衡检查 | 奖励、敌人强度、资源刷新 | 越界则拒绝 |
| 内容安全检查 | 敏感词、高风险主题、年龄层适配 | 命中则拒绝 |
| 重复度检查 | NPC相似度、支线复用比例、文案重复率 | 超阈值则拒绝 |

### 5.2 审核阈值

| 检查项 | 阈值 | 处理方式 |
|--------|------|----------|
| NPC相似度 | <= 0.8 | 超阈值拒绝 |
| 支线骨架复用比例 | <= 0.6 | 超阈值拒绝 |
| 文案段落重复率 | <= 0.3 | 超阈值拒绝 |
| 奖励突破章节上限 | 任何 | 拒绝 |
| 敌人强度超区域区间 | 任何 | 拒绝 |
| 敏感词命中 | 任何 | 拒绝 |
| 高风险主题 | 任何 | 进入人工复核 |

### 5.3 审核流程

| 项目 | 内容 |
|------|------|
| 目标 | 自动校验生成内容是否符合规则 |
| 优先级 | P0 |

**用户故事**：
- 作为系统，我希望自动检查生成内容是否与世界观冲突，以便保证一致性
- 作为系统，我希望自动检查数值是否平衡，以便保证游戏公平性
- 作为系统，我希望自动检查内容是否安全，以便保证合规性
- 作为审核员，我希望查看审核失败原因，以便决策

**验收标准**：
- 四个维度的检查自动执行
- 检查结果明确（通过/拒绝/人工复核）
- 拒绝时提供详细原因
- 高风险内容进入人工复核队列

**相关需求**：S2-05

## 六、人工复核需求

### 6.1 复核流程

| 项目 | 内容 |
|------|------|
| 目标 | 人工审核高风险和低分内容 |
| 优先级 | P1 |

**用户故事**：
- 作为审核员，我希望查看待审核内容列表，以便处理审核任务
- 作为审核员，我希望查看内容详情和自动审核结果，以便做出决策
- 作为审核员，我希望批准、拒绝或标记需要修改的内容，以便控制上线质量
- 作为策划，我希望查看审核统计，以便优化模板和规则

**复核操作**：
- **批准**：内容通过审核，进入打包流程
- **拒绝**：内容被拒绝，记录拒绝原因
- **修改**：内容需要修改后重新提交
- **跳过**：暂不处理，保留在队列中

**验收标准**：
- 待审核列表按优先级排序
- 显示内容详情和自动审核结果
- 支持四种复核操作
- 审核统计数据完整

**相关需求**：S6-04

### 7.2 内容包发布

| 项目 | 内容 |
|------|------|
| 目标 | 将内容包灰度发布到游戏中 |
| 优先级 | P0 |

**用户故事**：
- 作为运营，我希望将内容包发布到灰度环境，以便测试
- 作为运营，我希望灰度期间观察关键指标，以便评估效果
- 作为运营，我希望灰度通过后发布到全量，以便所有玩家体验
- 作为玩家，我希望收到内容更新通知，以便了解新内容

**发布流程**：
1. packaged → gray（灰度发布）
2. gray → live（全量发布）
3. gray → rolled_back（灰度回滚）
4. live → rolled_back（线上回滚）
5. live → archived（归档）

**验收标准**：
- 内容包状态迁移正确
- 灰度范围配置生效
- 发布后玩家可获取新内容
- 发布记录完整可追溯

**相关需求**：S0-04, S2-07

---

### 7.3 内容包回滚

| 项目 | 内容 |
|------|------|
| 目标 | 紧急情况下撤回已发布的内容包 |
| 优先级 | P0 |

**用户故事**：
- 作为运营，我希望在发现问题时快速回滚内容包，以便减少影响
- 作为系统，我希望回滚后玩家不再看到问题内容，以便恢复正常体验
- 作为运营，我希望查看回滚记录，以便分析原因

**回滚触发条件**：
- 关键错误率突增（5xx > 1%）
- 投票/核心玩法不可用
- 内容出现严重世界观冲突或安全问题
- 数值异常导致经济系统失衡

**验收标准**：
- 回滚操作快速执行
- 内容包状态变为rolled_back（终态）
- 回滚后玩家不可见问题内容
- 回滚记录包含原因和影响范围

**相关需求**：S0-06
