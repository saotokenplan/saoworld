# 内容生成与审核需求文档

> 文档状态：active
> 适用阶段：需求实现
> 维护要求：持续维护
> 更新频率：每Sprint更新

## 文档定位

本文档定义AI内容生成与审核的完整流程和需求，确保生成内容质量可控、安全合规、符合世界观设定。

本文档用于描述 AI 内容生成与审核的业务目标、对象范围、流程意图和验收背景。生成字段、审核阈值、结构化 schema、状态流转和发布约束等执行细节，以 `docs/20-specs/content-generation-spec.md`、`docs/20-specs/backend-data-spec.md` 和相关治理规范为准。

## 一、内容生成流程

### 1.1 生成流程概述

```
投票结算 → 生成参数提取 → 模板匹配 → AI生成 → 质量评分 → 规则审核 → 人工复核 → 打包发布
```

### 1.2 各阶段职责

| 阶段 | 职责 | 产出 |
|------|------|------|
| 投票结算 | 确定高票候选方向 | 生成参数草案 |
| 生成参数提取 | 将投票结果转换为结构化参数 | generated_params |
| 模板匹配 | 根据生成类型选择合适模板 | 模板ID + 填充参数 |
| AI生成 | 调用LLM生成内容 | 生成内容对象 |
| 质量评分 | 自动评估生成质量 | 质量分数（0-1） |
| 规则审核 | 校验设定一致性、数值、安全 | 审核通过/拒绝 |
| 人工复核 | 高风险内容人工审核 | 复核意见 |
| 打包发布 | 打包为内容包，灰度发布 | 内容包 |

## 二、生成对象需求

本节只保留生成对象的业务目标与验收意图；字段级 schema、阈值和约束细节统一以 `docs/20-specs/content-generation-spec.md` 为准。

| 对象 | 业务目标 | 优先级 | 关键验收意图 |
|------|----------|--------|--------------|
| NPC | 生成可进入世界、任务和对话系统的角色内容 | P0 | 角色设定完整、与阵营/区域一致、风格稳定 |
| 支线任务 | 生成可导入任务系统的支线内容 | P0 | 目标清晰、奖励合理、失败处理可理解 |
| 聚落描述 | 扩充区域演化后的场景与聚落表达 | P1 | 地貌、资源、阵营与描述相互匹配 |
| 怪物 | 扩充区域敌对内容和战斗遭遇 | P1 | 强度、掉落和行为模式与区域阶段相符 |
| 装备 | 生成可投放的战利品与奖励内容 | P1 | 品质、属性和等级要求保持平衡 |

**共同业务约束**：
- 生成对象必须可追溯到投票结果、模板版本和生成批次
- 生成结果必须能进入后续评分、审核、打包与发布链路
- 任何字段完整度、schema 版本和结构约束，以源规范为准

## 三、模板、评分与审核

### 3.1 模板管理

| 项目 | 内容 |
|------|------|
| 目标 | 管理不同领域的生成模板与版本 |
| 优先级 | P0 |

**业务关注点**：
- 模板需要支持领域区分、版本迭代和质量阈值配置
- 策划应能理解模板适用对象、风格目标和参数约束
- 模板的具体字段与版本命名规则以执行规范为准

### 3.2 质量评分

| 项目 | 内容 |
|------|------|
| 目标 | 自动评估生成内容质量并决定流转方向 |
| 优先级 | P0 |

**业务关注点**：
- 评分系统需要覆盖完整性、一致性、合理性、原创性和可玩性
- 评分结果要能驱动“通过 / 人工复核 / 废弃重生”三类处理
- 分数阈值和权重由执行规范统一维护

### 3.3 规则审核

| 项目 | 内容 |
|------|------|
| 目标 | 自动校验世界一致性、数值平衡、内容安全与重复度 |
| 优先级 | P0 |

**业务关注点**：
- 审核结果必须明确区分通过、拒绝和人工复核
- 审核失败需要可解释原因，便于策划与审核员处理
- 阈值、命中规则和具体判定逻辑以源规范为准

### 3.4 人工复核

| 项目 | 内容 |
|------|------|
| 目标 | 处理高风险或低分内容并给出最终决策 |
| 优先级 | P1 |

**业务关注点**：
- 审核员需要看到待办列表、自动审核结果和上下文详情
- 复核动作至少覆盖批准、拒绝、退回修改和暂缓处理
- 复核结果需要沉淀为后续模板优化和规则修正输入

## 四、内容包管理与成本控制

### 4.1 内容包创建与发布

| 项目 | 内容 |
|------|------|
| 目标 | 将审核通过的内容组织为可灰度、可追溯、可回滚的内容包 |
| 优先级 | P0 |

**业务关注点**：
- 内容包需要能关联章节、区域、对象集合和生成来源
- 发布必须遵循 packaged → gray → live 的受控路径
- 发布记录、灰度范围和玩家可见性应可审计、可回溯

### 4.2 内容包回滚

| 项目 | 内容 |
|------|------|
| 目标 | 在质量、安全或稳定性问题出现时快速撤回内容 |
| 优先级 | P0 |

**业务关注点**：
- 回滚触发通常来自严重冲突、安全问题、数值失衡或服务异常
- 回滚后玩家不应继续接触问题内容
- 回滚原因、影响范围和对应记录必须完整沉淀

### 4.3 成本控制

| 项目 | 内容 |
|------|------|
| 目标 | 监控生成成本并支持预算控制 |
| 优先级 | P1 |

**业务关注点**：
- 需要持续追踪 token 用量、模板成本和内容包成本
- 成本超阈值时应触发告警并支持后续优化分析
- 成本统计的精确口径与告警规则由执行规范维护
