## 功能目标

功能设计需要回答两个问题：玩家在这个世界里具体做什么，以及系统如何把“投票决定方向、AI 生成内容”真正嵌入核心玩法中。这里不讨论底层实现细节，只定义产品层面的玩法循环、功能模块和交互规则。

## 核心玩法循环

游戏的基础体验仍然要建立在“探索、战斗、成长、获取资源、影响世界”这条主循环上。投票和 AI 生成不是附加活动，而是世界持续更新的驱动器。

| 阶段 | 玩家行为 | 系统反馈 |
|------|----------|----------|
| 探索 | 进入区域、发现地标、接触势力、收集线索 | 解锁地图、区域热度、兴趣偏好数据 |
| 参与 | 完成任务、挑战敌人、建设据点、提升声望 | 角色成长、阵营关系变化、区域状态变化 |
| 表达 | 参与世界走向投票 | 形成下一周期生成方向 |
| 更新 | 进入新上线的内容 | 遇到新 NPC、新区域、新事件和新冲突 |
| 回流 | 再次探索和参与 | 形成长期留存和社区讨论 |

## 世界设计

### 地图结构

地图不建议做成真正意义上的无限随机平铺，而应设计成可持续扩展的开放世界。地图至少分为三层：

1. 核心大陆：长期常驻，承载主线和基础玩法。
2. 扩展区域：根据投票结果和章节推进逐步解锁。
3. 异变区域：限时开放，用来承接实验玩法和高强度事件。

### 剧情结构

剧情分为两层：

1. 固定骨架：世界观、文明来源、核心阵营和终局冲突保持稳定。
2. 可变分支：区域冲突、重要角色命运、阶段重点和局部事件可由玩家投票影响。

这样既能让玩家感受到世界在变化，又不会让剧情因为频繁投票而失去逻辑一致性。

## 玩家投票设计

### 投票目标

玩家投票不直接输入任意内容，而是在系统给出的候选方向中选择。候选方向可以包括：

1. 新区域主题
2. 阵营冲突走向
3. 关键角色命运
4. 世界事件类型
5. 新聚落风格

### 投票规则

| 规则项 | 设计建议 |
|--------|----------|
| 投票周期 | 按周或双周结算 |
| 候选数量 | 每期 3 到 5 项 |
| 投票资格 | 与章节进度、等级或活跃度挂钩 |
| 票权规则 | 基础票权一致，可附加少量世界贡献度修正 |
| 异常控制 | 设备指纹、异常行为识别、冷却期和人工复核 |
| 结果处理 | 高票结果进入生成链路，接近票数由系统结合剧情一致性兜底 |

### 投票体验要求

投票必须是剧情和世界更新的一部分，而不是一个脱离游戏本体的活动页面。玩家在投票前，需要先理解当前冲突与候选方向；投票后，需要明确看到自己的选择如何转化成地图变化、NPC 登场和剧情推进。

## AI 内容生成设计

### 生成对象

AI 主要负责生成以下内容：

1. NPC 身份、职业、语气和关系网
2. 聚落主题、场景描述和环境变化
3. 支线任务和局部事件
4. 野外遭遇、敌人组合和道具文本
5. 区域风格化叙事内容

### 不建议完全交给 AI 的内容

以下内容不建议直接由 AI 自由生成：

1. 核心战斗规则
2. 世界观根设定
3. 经济底层参数
4. 高价值奖励投放
5. 主线最终节点

## 功能模块

### 1. 世界地图系统

负责区域解锁、地图层级、地标分布、资源刷新和区域状态变化。新区域不是单纯扩大面积，而是承接新的阵营冲突、探索目标和资源竞争逻辑。

### 2. 剧情与任务系统

负责主线、支线、奇遇、阵营关系和章节推进。任务需要具备明确的触发条件、地点、目标、敌人、奖励和失败处理，避免 AI 只生成一段文本却无法成为真正玩法。

### 3. NPC 与聚落生成系统

负责生成角色身份、个性标签、阵营归属、关系链、常驻区域和行为模式。聚落则需要生成其外观风格、资源结构、居民构成和冲突背景。

### 4. 玩家投票系统

负责提供候选方案、收集投票、校验资格、结算结果和公示影响。系统要把投票结果转换为结构化生成参数，而不是将玩家语言直接传给生成模型。

### 5. 规则审核系统

负责校验 AI 内容是否存在设定冲突、奖励越界、敏感内容、内容重复和数值失衡。这个模块决定生成内容能不能真正进入游戏。

### 6. 世界更新与回滚系统

负责内容灰度发布、区域热更新、版本管理和紧急回滚。一旦 AI 生成内容批量上线，这个系统必须支持按区域、按事件或按内容包撤回。

## 关键交互流程

### 流程一：玩家参与世界更新

1. 玩家在游戏中体验当前区域和章节冲突。
2. 玩家在剧情节点或大厅入口看到本期候选方向。
3. 玩家投票表达偏好。
4. 系统在周期结束后公示结果。
5. 新内容上线并在世界中体现。
6. 玩家进入更新后的区域继续体验。

### 流程二：新区域生成上线

1. 系统汇总投票结果和玩家行为数据。
2. 生成系统根据高票方向产出内容草案。
3. 规则系统校验设定一致性和数值边界。
4. 审核通过后形成新内容包。
5. 内容包灰度上线到对应区域。
6. 玩家进入新区域并触发新的探索与任务。

## MVP 功能范围

第一阶段建议只做以下功能：

1. 1 个核心区域和 1 个可扩展新区域
2. 1 条主线骨架和 3 条候选剧情分支
3. AI 生成 NPC、支线、事件和聚落描述
4. 周期性投票机制
5. 基础规则校验和人工复核

## 验收标准

| 维度 | 标准 |
|------|------|
| 玩法闭环 | 玩家能完整经历探索、投票、更新、回流全过程 |
| 世界感知 | 玩家能明确看到投票结果如何影响世界 |
| 内容质量 | 新 NPC、任务和区域具备基本可玩性，不只是文本变化 |
| 功能稳定 | 投票、生成、审核、上线链路能够稳定跑通 |
| 运营可控 | 候选内容、上线节奏和风险内容可被运营干预 |
