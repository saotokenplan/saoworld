# 投票与社区需求文档

> 文档状态：active
> 适用阶段：需求实现
> 维护要求：持续维护
> 更新频率：每Sprint更新

## 文档定位

本文档定义投票系统和社区功能的需求，确保玩家能有效参与世界治理，建立活跃的社区生态。

本文档用于描述投票与社区的业务目标、用户故事、体验意图和验收背景。投票周期状态机、候选项数据结构、接口契约、错误码和审计约束等执行细节，以 `docs/20-specs/product-spec.md`、`docs/20-specs/backend-data-spec.md` 与 `docs/30-api/` 下源文档为准。

## 一、投票系统

### 1.1 投票周期管理

| 项目 | 内容 |
|------|------|
| 目标 | 创建和管理投票周期 |
| 优先级 | P0 |

**用户故事**：
- 作为运营，我希望创建投票周期，以便组织玩家投票
- 作为运营，我希望配置投票周期的时间范围和规则，以便控制投票节奏
- 作为运营，我希望查看投票周期列表和状态，以便管理投票进度

**业务关注点**：
- 投票周期需要包含章节归属、开放时间窗、主题说明和可追溯的创建原因
- 运营可以查看周期列表、当前状态和结算结果，但具体状态枚举与迁移路径以执行规范为准
- 同一章节同一时间只能存在一个对玩家可投的有效周期

**验收标准**：
- 投票周期可创建、编辑、删除
- 状态流转正确
- 同一章节同时只能有一个open状态的周期
- 创建和状态变更记录审计日志

**相关需求**：S0-03, S6-03

### 1.2 投票候选项

| 项目 | 内容 |
|------|------|
| 目标 | 创建和管理投票候选项 |
| 优先级 | P0 |

**用户故事**：
- 作为运营，我希望创建投票候选项，以便提供玩家选择
- 作为运营，我希望候选项包含世界背景和影响说明，以便玩家理解选择后果
- 作为运营，我希望候选项包含生成参数草案，以便投票后自动触发生成

**业务关注点**：
- 候选项必须让玩家理解“为什么投、投完会影响哪里、风险是什么”
- 每个候选项都应关联可落入生成链路的参数草案，但参数结构以执行规范为准
- 候选项需要支持撤回、当选和票数展示等管理场景

**验收标准**：
- 每期候选项数量为3-5个
- 候选项包含完整的背景说明和生成参数
- 候选项状态可变更（withdrawn/selected）
- 票数实时更新

**相关需求**：S0-03, S6-03

---

### 1.3 投票提交

| 项目 | 内容 |
|------|------|
| 目标 | 玩家提交投票 |
| 优先级 | P0 |

**用户故事**：
- 作为玩家，我希望查看当前投票周期和候选项，以便了解投票内容
- 作为玩家，我希望选择候选项并提交投票，以便表达我的意愿
- 作为玩家，我希望提交后收到确认，以便知道投票成功

**体验与风控关注点**：
- 资格：满足章节进度、活跃度或贡献度门槛
- 票权：基础一致，贡献度修正倍率不超过1.2
- 幂等：提交端需要具备重复请求不重复计票的保障
- 提交结果应给玩家明确反馈，并保留可审计链路

**验收标准**：
- 玩家进入投票界面可见当前周期和候选项
- 提交投票后显示确认提示
- 幂等键校验生效（重复提交只计一次）
- 投票记录写入数据库

**相关需求**：S0-05, S3-01, S3-02

---

### 1.4 投票结算

| 项目 | 内容 |
|------|------|
| 目标 | 计算投票结果并确定生成方向 |
| 优先级 | P0 |

**用户故事**：
- 作为系统，我希望在投票周期结束后自动结算，以便确定获胜方向
- 作为运营，我希望查看投票结果统计，以便确认结果
- 作为系统，我希望将投票结果转换为生成参数，以便自动触发生成

**业务关注点**：
- 高票结果优先进入生成链路
- 接近结果需要保留额外裁决或一致性兜底机制
- 结算完成后应产出可传递给生成链路的结构化结果

**验收标准**：
- 投票周期结束后自动结算
- 结算结果包含各候选项票数和占比
- 获胜候选项标记为selected
- 生成参数自动传递到generation-service

**相关需求**：S2-06

---

### 1.5 投票结果展示

| 项目 | 内容 |
|------|------|
| 目标 | 向玩家展示投票结果和落地情况 |
| 优先级 | P0 |

**用户故事**：
- 作为玩家，我希望查看投票结果，以便了解哪项获得了多数支持
- 作为玩家，我希望查看上轮投票结果的实际落地情况，以便感知投票影响
- 作为玩家，我希望看到投票对世界的具体影响，以便理解我的选择有意义

**展示内容**：
- 总票数与各候选项占比（图表）
- 最终采用方向
- 预计影响区域
- 预计上线周期
- 上一轮投票结果的实际落地情况

**验收标准**：
- 投票结算后客户端展示结果
- 结果包含图表和详细信息
- 上轮投票结果显示"已落地"标记
- 可跳转到对应内容查看实际影响

**相关需求**：S4-01, S4-04

## 二、投票体验优化

### 2.1 投票讨论区

| 项目 | 内容 |
|------|------|
| 目标 | 为每个投票周期提供讨论空间 |
| 优先级 | P0 |

**用户故事**：
- 作为玩家，我希望在投票界面看到其他玩家的讨论，以便了解不同观点
- 作为玩家，我希望发表自己的观点，以便参与讨论
- 作为玩家，我希望对讨论进行点赞和回复，以便互动

**讨论区功能**：
- 每个投票周期关联一个讨论区
- 讨论按热度排序（点赞数）
- 支持点赞和回复
- 讨论内容实时更新

**验收标准**：
- 投票界面显示讨论区入口
- 讨论区显示所有发言
- 支持点赞和回复操作
- 讨论内容实时同步

**相关需求**：S4-02

## 三、社区系统

### 3.1 好友系统

| 项目 | 内容 |
|------|------|
| 目标 | 玩家添加好友并查看状态 |
| 优先级 | P0 |

**用户故事**：
- 作为玩家，我希望添加好友，以便与朋友一起玩
- 作为玩家，我希望查看好友在线状态，以便知道谁在游戏
- 作为玩家，我希望查看好友的基本信息，以便了解他们的进度

**好友功能**：
- 搜索玩家添加好友
- 好友请求发送和接受
- 在线状态显示（在线/离线/忙碌）
- 好友列表管理

**验收标准**：
- 可搜索玩家并发送好友请求
- 好友请求可接受或拒绝
- 好友列表显示在线状态
- 好友信息包含等级和区域

**相关需求**：S5-01

|------|------|
| 目标 | 玩家之间发送消息 |

## 四、社交数据API

### 4.1 API需求

| 项目 | 内容 |
|------|------|
| 目标 | 提供社交相关的数据接口 |
| 优先级 | P0 |

**用户故事**：
- 作为客户端开发，我希望调用好友相关API，以便实现好友功能
- 作为客户端开发，我希望调用聊天相关API，以便实现聊天功能
- 作为客户端开发，我希望调用公会相关API，以便实现公会功能

**API列表**：

| API | 方法 | 说明 |
|-----|------|------|
| /api/v1/players/friends | GET | 获取好友列表 |
| /api/v1/players/friends/requests | GET | 获取好友请求 |
| /api/v1/players/friends/requests | POST | 发送好友请求 |
| /api/v1/players/friends/requests/{id} | PUT | 接受好友请求 |
| /api/v1/players/friends/requests/{id} | DELETE | 拒绝好友请求 |
| /api/v1/players/friends/{friend_id} | DELETE | 删除好友 |
| /api/v1/chat/messages | GET | 获取聊天记录 |
| /api/v1/chat/messages | POST | 发送消息 |
| /api/v1/guilds | GET | 获取公会列表 |
| /api/v1/guilds | POST | 创建公会 |
| /api/v1/guilds/{guild_id} | GET | 获取公会详情 |
| /api/v1/guilds/{guild_id}/members | GET | 获取公会成员 |
| /api/v1/guilds/{guild_id}/invites | POST | 发送公会邀请 |
| /api/v1/guilds/{guild_id}/announcements | POST | 发布公告 |

**验收标准**：
- API接口完整
- 权限校验正确
- 响应格式符合规范
- 错误码正确返回

**相关需求**：S5-05

## 五、投票安全与风控

### 5.1 异常检测

| 项目 | 内容 |
|------|------|
| 目标 | 检测和防止异常投票行为 |
| 优先级 | P0 |

**用户故事**：
- 作为系统，我希望检测刷票行为，以便保证投票公平
- 作为系统，我希望检测机器人投票，以便防止作弊
- 作为运营，我希望收到异常告警，以便及时处理

**检测机制**：
- 设备指纹识别
- 行为聚类分析
- 频率限制（每分钟最多投票1次）
- 冷却期（投票后5分钟内不可再次投票）
- 人工复核可疑投票

**验收标准**：
- 刷票行为被检测并阻止
- 机器人投票被识别
- 异常行为触发告警
- 人工复核流程完善

**相关需求**：S6-07
