# 每日进展更新机制

> 文档状态：active
> 适用阶段：项目管理
> 维护要求：持续维护
> 更新频率：每日更新

## 文档定位

本文档定义项目每日进展的记录机制和模板，确保产品经理和研发团队能够及时了解项目状态，发现问题并调整方向。

---

## 一、更新机制

### 1.1 更新频率

- **频率**：每日更新
- **时间**：每天上午 10:00 前发布前一日进展

### 1.2 更新责任人

- **产品经理**：负责汇总和分析进展，编写每日更新
- **技术负责人**：提供技术进展和风险信息
- **各模块负责人**：提供各自模块的进展信息

### 1.3 更新渠道

- **文档位置**：`docs/40-dev-loop/daily-progress/`
- **命名格式**：`daily-progress-YYYY-MM-DD.md`
- **通知方式**：团队群公告、邮件通知

## 五、异常处理流程

### 5.1 发现异常

当以下情况发生时，触发异常处理：

- Sprint进度落后超过10%
- 出现高优先级Bug
- 关键需求无法按时完成
- 外部依赖延迟超过2天

### 5.2 处理流程

1. **确认异常**：产品经理确认异常情况
2. **评估影响**：评估对项目的影响范围和严重程度
3. **制定方案**：与技术负责人共同制定解决方案
4. **调整计划**：根据方案调整迭代计划
5. **通知团队**：向团队发布调整后的计划和指导意见

### 5.3 升级机制

| 异常类型 | 升级对象 |
|----------|----------|
| 需求延迟超过3天 | 技术负责人 |
| 高优先级Bug无法修复 | 技术负责人 |
| 风险等级升级为高 | 技术负责人 + 产品负责人 |
| Sprint无法按时完成 | 全体团队会议 |
