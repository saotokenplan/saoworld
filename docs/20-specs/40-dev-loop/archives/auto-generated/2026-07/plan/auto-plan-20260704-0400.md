## 任务目标与背景

vote-service、world-service、content-service、generation-service、review-service、gateway-service、player-service 和 ops-service 八个核心服务已完整实现并通过验证。workers Celery 异步任务框架也已就绪，包含 7 个核心异步任务。

根据 `project-status.md` 的"下一阶段建议"第 9 项：需要补异步任务和事件的 payload schema（不阻塞投票 MVP，但内容链路需要）。

目前虽然 workers 任务框架已实现，但缺少统一的 payload schema 规范文档。异步任务的输入输出参数、事件消息结构、重试策略等都散落在代码中，缺少统一的规范文档，不利于后续服务间集成和内容链路打通。

**本次目标**：创建异步任务与事件的 payload schema 规范文档，统一定义 7 个核心异步任务的输入输出结构、事件消息格式、重试策略、死信处理规则，为内容链路打通和服务间集成提供明确的契约规范。

### 步骤 2：编写异步任务 payload schema

为 7 个核心异步任务定义详细的输入输出结构：

1. **generate_content_batch**（内容生成批量任务）
   - 输入参数：template_type、count、region_id、chapter_id、trace_id
   - 输出结果：request_id、status
   - 调用服务：generation-service

2. **run_world_consistency_review**（世界一致性审核）
   - 输入参数：content_package_id、trace_id
   - 输出结果：content_package_id、result、score、issues_count
   - 调用服务：world-service + review-service

3. **run_balance_review**（数值平衡审核）
   - 输入参数：content_package_id、trace_id
   - 输出结果：content_package_id、result、score、issues_count
   - 调用服务：review-service

4. **package_content_batch**（内容打包）
   - 输入参数：package_id、object_ids、trace_id
   - 输出结果：package_id、status、object_count
   - 调用服务：content-service

5. **release_content_package**（内容发布）
   - 输入参数：content_package_id、release_mode、gray_scope_jsonb、trace_id
   - 输出结果：content_package_id、release_mode、status
   - 调用服务：content-service

6. **rollback_content_package**（内容回滚）
   - 输入参数：content_package_id、reason、trace_id
   - 输出结果：content_package_id、status、reason
   - 调用服务：content-service

7. **daily_gate_scan**（每日门禁扫描）
   - 输入参数：scan_date、scan_scope、trace_id
   - 输出结果：scan_id、total_checks、passed_count、failed_count
   - 调用服务：多服务联合

每个任务都需定义：
- 任务名称与队列
- 输入字段（名称、类型、必填、说明、示例）
- 输出字段（名称、类型、说明）
- 错误类型与重试策略
- 关联的事件主题

### 步骤 3：编写事件消息 schema

定义内部事件总线的事件主题和消息格式：

1. **vote.cycle.closed** - 投票周期关闭
2. **vote.result.finalized** - 投票结果结算完成
3. **generation.request.created** - 生成请求创建
4. **generation.batch.completed** - 批量生成完成
5. **review.batch.completed** - 批量审核完成
6. **content.package.released** - 内容包发布
7. **content.package.rolled_back** - 内容包回滚

每个事件定义：
- 事件主题（topic）
- 触发时机
- 消息结构（event_id、event_type、occurred_at、trace_id、producer、payload）
- payload 字段说明
- 消费者列表

### 步骤 4：编写重试策略与死信队列规范

- 重试分类：可重试错误 vs 不可重试错误
- 重试策略：指数退避、最大重试次数（3次）、退避基数（2秒）
- 死信队列（DLQ）：定义、触发条件、处理流程
- 幂等性要求：每个任务必须支持幂等执行
- 任务状态：pending → processing → succeeded / failed_retryable / failed_permanent

### 步骤 5：编写追踪与审计字段规范

- trace_id 传递规范：全链路追踪 ID 必须在任务和事件中传递
- request_id 规范：请求追踪 ID 格式
- 审计日志字段：operator_id、operator_role、action、resource_type、resource_id、details_jsonb
- 结构化日志要求：每个任务必须记录 task_started、task_completed、task_failed 事件
