## 任务目标与背景

Sprint 3 S3-01「贡献度系统」、S3-02「投票资格门槛」、S3-03「成就系统」、S3-04「个人中心」已完成。S3-05 是 Sprint 3 的下一个 P1 任务，目标是在 player-service 和 Godot 客户端实现等级与经验系统：

1. **player-service 等级与经验系统**：
   - 玩家等级（level）和经验值（experience_points）字段
   - 经验值获取与等级提升逻辑
   - 等级经验曲线配置（指数增长）
   - 升级奖励（贡献度、物品等）
   - 等级 API（查询等级、获取经验、升级通知）

2. **Godot 客户端等级系统集成**：
   - PlayerManager 扩展等级数据管理
   - 等级与经验值显示
   - 升级动画与通知
   - 个人中心界面集成等级信息

本任务完成后，玩家成长系统将具备"等级与经验"核心能力，为后续技能系统（S3-06）奠定基础。

## 具体执行步骤

### 步骤 1：实现等级与经验数据模型

- 在 `services/player/app/domain/models.py` 的 `Player` 模型中新增：
  - `level`：玩家等级（Integer，默认 1，>= 1）
  - `experience_points`：当前经验值（Integer，默认 0，>= 0）
- 创建 Alembic 迁移脚本
- 新增经验流水表 `player_experience_logs`（可选，用于审计）

### 步骤 2：实现等级经验曲线工具

- 在 `services/player/app/schemas/player.py` 新增：
  - 等级经验曲线配置（每级所需经验值，指数增长）
  - `get_experience_for_level(level: int) -> int`：获取指定等级所需经验
  - `get_level_from_experience(exp: int) -> int`：根据经验值计算等级
  - `get_level_progress(exp: int) -> float`：获取当前等级进度百分比
  - `calculate_level_up_rewards(level: int) -> dict`：计算升级奖励

### 步骤 3：实现等级与经验仓储层

- 在 `services/player/app/repositories/` 下新增 `level_repo.py`（或扩展 player_repo.py）
- `PlayerLevelRepository`：
  - `get_player_level(player_id)`：获取玩家等级与经验
  - `add_experience(player_id, amount, source, source_id)`：增加经验值，自动处理升级
  - `check_level_up(player_id)`：检查是否可以升级
  - `grant_level_up_rewards(player_id, new_level)`：发放升级奖励

### 步骤 4：实现等级与经验 API 端点

- 玩家 API（`router`）：
  - `GET /player/level`：获取玩家等级、经验、下一等级所需经验、进度
- 运营 API（`ops_router`）：
  - `POST /ops/players/{player_id}/experience`：手动增加经验值
  - `GET /ops/players/{player_id}/level`：获取玩家等级详情

### 步骤 5：任务完成自动发放经验奖励

- 修改 `complete_quest` 接口，任务完成时根据任务难度发放经验奖励
- 经验奖励从 `rewards_jsonb.experience_points` 字段读取
- 升级时自动发放升级奖励（贡献度等）
