# 每周代码审查自动执行规范

> 状态：active
> 生效日期：2026-07-21
> 适用范围：每周六自动执行的代码审查、风险分析与低风险重构任务

## 目的

将“每周代码审查与重构优化”固化为可重复执行的自动任务，避免每次重复确认，同时保留风险控制边界。

## 自动执行原则

1. 固定统计窗口为最近 7 天
2. 固定在每周六执行
3. 默认无需再次人工确认
4. 仍需在任务内部生成规划文档与检查清单，但生成后可直接进入执行，不等待人工批准
5. 只允许自动落地高价值、低风险、可验证的修改
6. 无法确认安全性的事项只能输出建议，不得强行修改

## 标准执行步骤

1. 收集最近 7 天 Git 改动范围、热点目录、核心文件与主题
2. 读取最新需求文档、质量规则、项目状态文档和最近周报
3. 从架构一致性、可读性、可靠性、稳定性、可测试性、可维护性 6 个维度分析
4. 将问题拆为：
   - 立即实施
   - 建议纳入下周
   - 暂缓处理
5. 仅对“立即实施”项落地代码修改
6. 补最小必要测试并运行静态检查、类型检查、单元测试
7. 生成周度代码审查报告并更新 `project-status.md`
8. 如执行了代码修改，再进行 git 提交与推送

## 自动执行边界

### 允许直接执行

- 规则死分支修复
- 状态聚合逻辑修复
- 明显错误参数调用修复
- 高频重复逻辑的小步抽取
- 缺失的最小回归测试补齐
- 周报、状态文档、检查清单和 runbook 更新

### 禁止自动扩大范围

- 无边界大规模重写
- 跨多个服务的共享抽象重构
- 无运行时验证支撑的高影响行为修改
- 需要真实环境、外部依赖或业务确认才能安全落地的改动

## 降级策略

遇到以下情况时，应降级为“只出报告不改代码”：

- 热点问题需要跨模块联动且回归面过大
- 缺少最小验证环境或关键依赖不可用
- 代码现状与文档严重漂移，无法在一轮内安全收敛
- 发现潜在高风险问题但无法快速确认行为预期

## 输出要求

每次自动执行都必须输出并更新：

- `docs/40-dev-loop/weekly-code-review/weekly-code-review-YYYY-MM-DD.md`
- `docs/00-governance/project-status.md`

报告至少包含：

- 本周改动概览
- 六维分析结论
- 已实施的重构项
- 暂未处理但建议跟进的问题
- 测试与验证结果
- 风险与回滚说明
- 下周建议治理方向

## 回滚要求

- 所有自动落地修改必须保持小步、可回滚
- 优先按文件级别保持独立提交面
- 若验证失败且无法快速修复，应撤销本轮高风险修改，只保留分析报告与治理建议

## 本规范的执行授权

- 2026-07-21 用户已明确授权：后续每周自动执行该任务时，不再需要额外人工确认
- 该授权仅适用于“每周代码审查与低风险重构”这一固定任务
- 若未来任务范围显著扩大，或涉及高风险结构变更，仍应重新获取人工决策
