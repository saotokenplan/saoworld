## 任务目标与背景

vote-service、world-service、content-service、generation-service、review-service、gateway-service 和 player-service 已完整实现并通过验证。但 MVP 的运营管理链路还缺少核心环节——ops-service 负责后台运营入口、指标汇总、Issue 触发，是连接运营人员与游戏世界的关键桥梁。

根据 `backend-data-spec.md` 和 `42-release-rollback.md` 的定义，ops-service 需要提供统一的运营管理入口，包括投票周期管理、内容发布/回滚审批、运营指标汇总等功能。API 规范中已定义运营接口（如 `POST /api/v1/ops/vote-cycles`），但这些接口分散在各个服务中，缺少统一的运营服务层。

**本次目标**：初始化 ops-service 服务骨架，实现运营管理核心功能（指标汇总、运营日志查询、系统状态监控），集成统一响应 envelope、JWT 认证、审计日志持久化，遵循已验证的服务架构模式。

- 运营操作接口（JWT + ops scope）：

- 系统状态接口（JWT + ops scope）：
