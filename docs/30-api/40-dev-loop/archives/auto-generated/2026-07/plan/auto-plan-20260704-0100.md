## 任务目标与背景

vote-service、world-service、content-service、generation-service、review-service、gateway-service、player-service 和 ops-service 八个核心服务已完整实现并通过验证。但 MVP 的异步任务链路还缺少关键基础设施——workers Celery 异步任务 Worker 尚未实现。

根据 `42-release-rollback.md` 规范，以下长任务必须通过 Celery 异步执行：
- `generate_content_batch` - AI批量内容生成
- `run_world_consistency_review` - 世界一致性审核
- `run_balance_review` - 数值平衡审核
- `package_content_batch` - 内容打包
- `release_content_package` - 内容发布
- `rollback_content_package` - 内容回滚
- `daily_gate_scan` - 每日门禁扫描

当前 `workers/` 目录仅有占位 README，缺少 Celery 配置、任务定义、测试等核心文件。`services/*/app/tasks/` 目录也仅有 `__init__.py` 空文件，任务逻辑尚未实现。

**本次目标**：初始化 workers Celery 异步任务框架，实现核心异步任务定义（内容生成、审核、发布、回滚、门禁扫描），配置 Redis 消息队列，集成统一日志和追踪，遵循已验证的服务架构模式。

### 步骤 2：实现内容生成任务（content_generation.py）

- 创建 `workers/tasks/content_generation.py`
- 实现 `generate_content_batch` 任务：
  - 接收请求参数（template_type、count、region_id、chapter_id）
  - 调用 generation-service API 创建生成请求
  - 等待生成结果（轮询或事件驱动）
  - 处理生成失败（重试/标记失败）
  - 记录审计日志

### 步骤 3：实现内容审核任务（content_review.py）

- 创建 `workers/tasks/content_review.py`
- 实现 `run_world_consistency_review` 任务：
  - 加载世界骨架快照
  - 校验阵营关系一致性
  - 校验 NPC 身份认知边界
  - 校验聚落资源与势力匹配
  - 提交审核结果到 review-service

- 实现 `run_balance_review` 任务：
  - 校验奖励上限
  - 校验敌人强度区间
  - 校验支线累计收益
  - 校验资源刷新配置
  - 提交审核结果到 review-service

### 步骤 4：实现内容打包任务（content_packaging.py）

- 创建 `workers/tasks/content_packaging.py`
- 实现 `package_content_batch` 任务：
  - 收集已批准的生成对象
  - 组装内容包结构（regions、npcs、quests、events）
  - 设置 schema_version
  - 创建内容包记录到 content-service
  - 记录审计日志

### 步骤 5：实现内容发布与回滚任务（content_release.py）

- 创建 `workers/tasks/content_release.py`
- 实现 `release_content_package` 任务：
  - 校验内容包状态（packaged）
  - 更新状态到 gray（灰度）或 live（全量）
  - 设置灰度范围（gray_scope_jsonb）
  - 记录发布记录到 ReleaseRecord
  - 记录审计日志

- 实现 `rollback_content_package` 任务：
  - 校验内容包状态（gray/live）
  - 更新状态到 rolled_back（终态）
  - 记录回滚记录到 RollbackRecord
  - 记录审计日志

### 步骤 6：实现门禁扫描任务（gate_scan.py）

- 创建 `workers/tasks/gate_scan.py`
- 实现 `daily_gate_scan` 任务：
  - 扫描未审核的生成对象
  - 自动标记低质量内容
  - 生成门禁扫描报告
  - 记录审计日志
