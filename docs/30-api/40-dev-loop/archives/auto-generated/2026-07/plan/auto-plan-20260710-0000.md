## 具体执行步骤

### 步骤 1：扩展任务系统数据模型与仓储层
- 扩展 PlayerQuest 模型，补充任务状态机校验
- 扩展 PlayerQuestRepository，新增：
  - 接取任务（accept_quest）：available → active 状态迁移
  - 更新任务进度（update_objectives）：更新 objectives_jsonb
  - 完成任务（complete_quest）：active → completed 状态迁移 + 奖励发放
  - 失败任务（fail_quest）：active → failed 状态迁移
- 状态迁移合法性校验，严格遵循 available → active → completed/failed 路径

### 步骤 2：实现任务系统 API 接口
- 玩家 API 新增：
  - `POST /api/v1/player/quests/{quest_id}/accept` - 接取任务
  - `POST /api/v1/player/quests/{quest_id}/progress` - 更新任务进度
  - `POST /api/v1/player/quests/{quest_id}/complete` - 提交任务完成
  - `GET /api/v1/player/quests/{quest_id}` - 获取任务详情
- 运营 API 新增：
  - `POST /api/v1/ops/players/{player_id}/quests` - 为玩家创建任务
  - `PUT /api/v1/ops/players/{player_id}/quests/{quest_id}/status` - 管理员更新任务状态
- 统一响应 envelope 格式
- JWT 鉴权与 Scope 校验

### 步骤 3：补充审计日志与业务指标
- 任务接取/完成/失败时记录审计日志
- 新增业务指标：任务接取数、任务完成数、任务失败数
- 在关键操作点埋点

### 步骤 4：编写测试用例
- 任务接取测试（正常接取、重复接取、状态不合法）
- 任务进度更新测试（正常更新、任务不存在、非活跃状态）

- 任务失败测试
