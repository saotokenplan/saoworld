## 任务目标与背景

### 为什么要做这件事

Sprint 2 AI 生成接入阶段已完成 S2-01（LLM服务接入）、S2-02（NPC生成模板）、S2-03（任务生成模板），核心生成能力已就绪。

当前投票结算链路存在以下问题：
1. vote-service 发布 `vote.result.finalized` 事件时，只包含 `winning_candidate_id` 和 `winning_candidate_name`，缺少候选项的 `generated_params` 和 `region_scope`
2. workers 的 `handle_vote_result_finalized` 处理器调用 `generate_content_batch` 时，使用硬编码的默认参数（template_type="npc", count=1）
3. 投票候选项虽然有 `generated_params` 字段，但没有被实际用于驱动内容生成

根据需求迭代计划 Sprint 2 S2-06「投票结果→生成参数映射」为 P0 优先级，验收标准：「投票finalize后自动触发生成请求」。

### 目标

实现投票结果到生成参数的完整映射链路，包括：
1. vote-service 发布投票结算事件时，包含获胜候选项的完整生成参数
2. workers 事件处理器从事件中提取生成参数，传递给生成服务
3. 生成服务根据传入参数创建生成请求
4. 完整测试覆盖

## 具体执行步骤

### 步骤 1：扩展 vote-service 事件发布，包含完整生成参数

- 更新 `app/core/event_publisher.py` 的 `publish_vote_result_finalized` 方法
- 增加 `generated_params`、`region_scope`、`chapter_id` 等字段
- 确保事件 payload 包含足够信息供下游生成使用

### 步骤 2：更新 vote-service 结算逻辑，查询获胜候选项详情

- 更新 `app/repositories/` 或结算逻辑
- 投票 finalize 时，查询获胜候选项的完整信息（包括 generated_params、region_scope）
- 将完整信息传递给事件发布器

### 步骤 3：更新 workers 事件处理器，提取生成参数

- 更新 `workers/events/handlers.py` 的 `handle_vote_result_finalized`
- 从事件 payload 中提取 `generated_params`、`region_scope` 等
- 将参数传递给 `generate_content_batch` 任务

### 步骤 4：更新 workers 内容生成任务，支持动态参数

- 更新 `workers/tasks/content_generation.py` 的 `generate_content_batch`
- 支持从 `generated_params` 中读取 template_type、count、region_id、chapter_id、template_id 等
- 参数优先级：显式参数 &gt; generated_params &gt; 默认值

### 步骤 5：测试编写与验证

- 更新 vote-service 测试，验证事件发布包含完整参数
- 更新 workers 测试，验证事件处理器正确提取和传递参数
- 验证端到端链路：投票结算 → 事件发布 → 生成请求创建
