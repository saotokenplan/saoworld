## 任务目标与背景

Sprint 3 S3-01「贡献度系统」已在 player-service 落地，包含贡献度数据模型、贡献度 API、任务奖励发放和贡献度→投票权重倍率计算工具。S3-02 依赖 S3-01，目标是在 vote-service 投票提交时：

1. 校验玩家贡献度是否达到投票资格门槛；
2. 根据玩家贡献度计算投票权重倍率（上限 1.2）；
3. 与 player-service 贡献度 API 集成，实现跨服务数据查询。

本任务完成后，投票链路将具备"贡献度驱动投票权重"的核心能力，为后续玩家成长系统与治理玩法奠定基础。

## 具体执行步骤

### 步骤 1：实现贡献度查询客户端

- 在 `services/vote/app/core/` 下新增 `player_client.py`
- 提供 `PlayerContributionClient` 类，封装对 player-service `GET /api/v1/player/contribution` 的 HTTP 调用
- 返回玩家当前贡献度总分；player-service 不可用时抛出 `DEPENDENCY_UNAVAILABLE`
- 在 `config.py` 新增配置项：`player_service_url`、`contribution_threshold`、`jwt_secret` 复用现有值

### 步骤 2：实现投票权重计算与资格检查工具

- 在 `services/vote/app/core/` 下新增 `contribution.py`
- 复用 player-service 的 `calculate_vote_weight_multiplier` 算法（每 1000 贡献度 +0.1，上限 1.2）
- 提供 `check_vote_eligibility(contribution_points: int, threshold: int) -> bool` 函数

### 步骤 3：在投票提交接口中集成资格门槛与权重倍率

- 修改 `services/vote/app/api/routes.py` 的 `submit_vote` 函数
- 在已有校验（幂等、周期、候选、重复投票）之后、创建 vote 记录之前：
  1. 调用 `PlayerContributionClient` 查询玩家贡献度
  2. 使用 `check_vote_eligibility` 判断贡献度是否达到门槛
  3. 若未达门槛，返回 `403 Forbidden` + 新错误码 `INSUFFICIENT_CONTRIBUTION`
  4. 若达到门槛，使用 `calculate_vote_weight_multiplier` 计算最终权重：`body.weight * multiplier`
  5. 最终权重仍受数据库 `CHECK (weight > 0 AND weight <= 10.0)` 约束

### 步骤 4：补充错误码与指标

- 在 `services/vote/app/core/errors.py` 新增 `INSUFFICIENT_CONTRIBUTION` 错误码
- 在 `services/vote/app/core/metrics.py` 新增投票资格拒绝指标 `vote_eligibility_rejected_total`
