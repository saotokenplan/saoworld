## 任务目标与背景

项目已完成 vote-service 核心投票链路、运营写接口、JWT 鉴权和审计日志持久化。但与 `12-api-design.md` 规范对比，仍存在三个重要差距：

1. **响应格式不对齐**：规范要求所有成功响应使用统一 envelope 包装（`request_id`、`data`、`meta`、`trace_id`），当前实现直接返回扁平结构
2. **玩家接口缺少 JWT 认证**：规范要求除公开接口外所有接口需 Bearer Token，当前玩家接口（`/votes/current`、`/votes/submit`、`/votes/history`）仅使用 `X-Player-Id` 头，无真实身份验证
3. **模型缺失索引和 FK 约束**：`votes` 表缺少 `candidate_id_idx` 索引，`winning_candidate_id` 缺少 FK → `vote_candidates.candidate_id`

**本次目标**：对齐 API 规范，实现统一响应 envelope、玩家接口 JWT 认证、模型约束补全，使 vote-service 更接近生产就绪状态。

## 具体执行步骤

### 步骤 1：实现统一响应 Envelope

- 在 `app/schemas/vote.py` 中新增通用 envelope 模型：
  - `EnvelopeResponse[T]`：`request_id` + `data: T` + `meta`（可选）+ `trace_id`（可选）
  - `PaginatedMeta`：`total` + `limit` + `offset`
- 更新所有路由返回值，使用 envelope 包装
- 更新 `main.py` 中的异常处理器，使错误响应也符合规范 envelope

### 步骤 2：为玩家接口添加 JWT 认证

- 为 `GET /votes/current` 添加 JWT 认证（scope: `votes:read`）
- 为 `POST /votes/submit` 添加 JWT 认证（scope: `votes:submit`）
