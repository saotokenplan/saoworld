## 任务目标与背景

### 背景

上一轮任务（auto-20260704-1200）为所有 8 个后端服务集成了 `prometheus-fastapi-instrumentator`，提供基础 HTTP 指标（请求数、延迟、错误率）。但执行摘要明确指出：

> 遗留：基础 metrics 已集成，后续可添加业务指标（投票数、内容包数等）、Redis 分布式限流指标、数据库连接池指标

当前 `/metrics` 端点只能采集到 HTTP 层面的指标，无法反映业务运行状况。运营和监控人员无法通过 Grafana 看到：
- 投票提交总数、当前开放投票周期数
- 内容包数量按状态分布、发布与回滚次数
- 生成请求成功率、审核批准率
- 玩家总数、任务完成数
- 网关代理请求数、限流触发数、认证失败数

### 目标

为所有 8 个后端服务添加业务专属的 Prometheus 指标，使 Grafana 仪表盘能够展示业务运行状态，为运营决策和异常检测提供数据支撑。
