**发现的问题**：

1. **P0 - 灰度发布可见性判断缺失**：
   - content-service 的 `list_visible_packages` 方法只过滤 `gray` 和 `live` 状态，没有根据玩家 ID 判断灰度范围
   - 所有玩家都能看到灰度内容包，违背了灰度发布的初衷
   - `GET /api/v1/content/updates` 接口未使用 `X-Player-Id` 请求头
   - 缺少灰度范围判断逻辑（按区域、按玩家百分比、按指定玩家列表）

2. **P0 - Workers API 路径不匹配**：
   - workers 的 `content_review.py` 中调用 review-service 的路径是 `/api/v1/reviews`
   - 但 review-service 的实际路径是 `/api/v1/ops/review/records`
   - 这会导致内容审核 Worker 无法正常创建审核记录，阻塞内容审核链路

## 具体执行步骤

### 步骤 1：完善灰度可见性判断逻辑（content-service）

- 在 `ContentRepository` 中新增 `is_player_in_gray_scope` 方法
  - 支持三种灰度范围判断：
    - `region_ids`：按区域判断
    - `player_percent`：按玩家百分比（基于玩家 ID 哈希）
    - `player_ids`：按指定玩家列表
  - 优先级：player_ids > player_percent > region_ids
- 修改 `list_visible_packages` 方法，增加 `player_id` 参数
  - 对于 `live` 状态的包，所有人可见
  - 对于 `gray` 状态的包，只有在灰度范围内的玩家可见
- 修改 `GET /api/v1/content/updates` 接口
  - 增加 `X-Player-Id` 请求头读取
  - 传递 player_id 到 repository 层
