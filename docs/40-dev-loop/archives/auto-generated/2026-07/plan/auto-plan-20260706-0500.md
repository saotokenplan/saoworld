## 任务目标与背景

**背景**：项目当前处于内容发布与验证阶段，核心目标是完成首期内容包灰度发布，验证端到端玩法流程。CI/CD 基础基础设施已搭建（GitHub Actions、Docker、Docker Compose），但完整的自动化构建发布流水线仍需完善，包括内容检查门禁、端到端测试集成、灰度发布流程、自动健康检查和回滚机制。

**问题识别**：
1. CI 流水线缺少内容检查（四项检查）和 E2E 测试
2. CD 流水线缺少灰度发布流程
3. 部署脚本缺少灰度发布和自动回滚逻辑
4. 健康检查脚本只检查单一端点，缺少服务级别的全面检查

**目标**：完善 CI/CD 流水线，添加内容检查门禁和 E2E 测试，实现灰度发布流程，增强健康检查和自动回滚机制，为首期内容包灰度发布做好准备。

## 具体执行步骤

1. 扩展 CI 流水线：添加内容检查门禁（四项检查）和 E2E 测试
2. 扩展 CD 流水线：添加灰度发布阶段，支持灰度→全量的渐进式发布
3. 创建灰度发布脚本（gray-release.sh）
4. 完善健康检查脚本（health-check.sh）：添加服务级别检查
5. 完善回滚脚本（rollback.sh）：添加回滚日志记录
6. 更新项目状态文档（docs/00-governance/project-status.md），记录 CI/CD 完善状态
7. 运行测试验证所有改动
