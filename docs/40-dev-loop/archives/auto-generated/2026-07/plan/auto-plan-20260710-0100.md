## 任务目标与背景

**目标**：实现 Sprint 1 核心玩法 P0 项 S1-01「玩家移动与场景切换」，让玩家能够在首期区域中自由移动，并支持从世界地图进入区域、从区域返回世界地图的场景切换。

**背景**：
- Sprint 0 技术准备与灰度发布基础设施已全部完成，当前处于灰度发布验证阶段
- 由于部署环境需要人工决策与真实基础设施资源，Sprint 0 的发布演练存在阻塞
- 利用窗口期提前启动 Sprint 1 核心玩法的技术实现
- 客户端已有主菜单、世界地图、投票、NPC、任务等 UI 场景，但缺少实际可操控的玩家角色与区域探索场景
- S1-01 是 Sprint 1 的 P0 级基础需求，阻塞后续战斗、任务追踪、声望系统等玩法的客户端落地

**优先级**：P0（阻塞 MVP 核心玩法落地的功能缺口）

## 具体执行步骤

### 步骤 1：玩家角色场景与移动逻辑
- 创建 `game/scenes/player/Player.tscn` 与 `game/scripts/player/player.gd`
- 使用 `CharacterBody2D` 实现玩家角色
- 支持键盘输入移动（WASD / 方向键），配置 `project.godot` 输入映射
- 实现移动动画状态（idle / move）
- 添加碰撞体与边界检测

### 步骤 2：首期区域探索场景
- 创建 `game/scenes/world/CoreRegion.tscn` 与 `game/scripts/world/core_region.gd`
- 构建一个可行走的首期区域场景（铁卫城周边主题）
- 添加地面、障碍物、区域边界
- 在场景中实例化 Player 并设置初始位置
- 添加返回世界地图的 UI 按钮

### 步骤 3：世界地图进入区域
- 修复 `world_map.gd` 中 `_on_region_card_pressed()` 的信号接收逻辑
- 在世界地图详情面板添加「进入区域」按钮
- 点击后发射 `enter_region_requested(region_id)` 信号
- 在 `Main.gd` 中处理该信号，切换到对应的 Region 场景

### 步骤 4：主入口场景切换扩展
- 在 `Main.gd` 中预加载 `Player` 与 `CoreRegion` 场景
- 添加 `_on_enter_region_requested` 处理函数
- 添加从区域返回世界地图/主菜单的信号处理
- 保持当前场景管理逻辑的一致性

### 步骤 5：配置与数据
- 在 `game/data/config/` 下新增 `input_config.json`，记录移动按键与速度配置
- 更新 `game/data/regions/region_list.json`，补充首期区域对应的场景路径字段

### 步骤 6：测试用例
- 创建 `game/tests/test_player.gd`：测试玩家移动输入处理、速度、动画状态
- 创建 `game/tests/test_region_scene.gd`：测试区域场景加载、玩家实例化、返回信号
- 创建 `game/tests/test_world_map_navigation.gd`：测试区域选择与进入信号
- 更新 `game/tests/README.md` 测试清单

### 步骤 7：文档与状态更新
