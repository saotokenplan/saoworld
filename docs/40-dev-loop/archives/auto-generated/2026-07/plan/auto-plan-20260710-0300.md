## 任务目标与背景

**目标**：完善世界地图系统（S1-02），实现区域状态显示、地标导航和地图交互优化，支持玩家在世界地图上直观了解各区域状态并进行导航。

**背景**：
- Sprint 0 技术准备已全部完成，灰度发布基础设施就绪
- Sprint 1 已提前启动，S1-01「玩家移动与场景切换」和 S1-04/S1-09「任务系统 API」已完成
- S1-11「NPC 与任务数据接口」已完成（auto-20260710-0200）
- 当前世界地图已有基础的区域卡片展示，但缺少完整的状态标识、导航交互和 API 对接
- world-service 已提供区域列表和详情 API，但客户端 WorldManager 可能未完整实现或未正确对接
- S1-02 是 Sprint 1 P0 项，依赖 S1-01，为后续 NPC 对话系统（S1-03）和任务系统（S1-04）提供导航基础

**优先级**：P0（阻塞 Sprint 1 后续核心玩法客户端落地）

## 具体执行步骤

### 步骤 1：检查现有世界地图实现

- 读取 `game/scenes/world/WorldMap.tscn` 和 `game/scripts/world/world_map.gd`
- 读取 `game/scripts/autoload/WorldManager.gd`（如存在）或 `game/scripts/autoload/APIManager.gd`
- 分析现有功能：区域列表展示、区域卡片、进入区域按钮、状态标识
- 确定需要补充的功能点

### 步骤 2：完善世界地图场景与UI

- 增强区域卡片显示：添加区域状态图标（locked/active/unstable/archived）、区域类型标识（核心区域/扩展区域）
- 添加区域详情面板：展示区域描述、解锁条件、已完成任务数、推荐等级
- 添加导航功能：点击区域卡片显示详情，支持快速跳转进入区域
- 添加地图缩放与平移支持（如适用）
- 添加区域筛选功能：按状态、按章节筛选

### 步骤 3：完善 WorldManager 数据管理

- 实现 `WorldManager.gd`（如未存在则创建）：区域列表缓存、区域详情缓存、状态同步
- 实现从 world-service 获取区域数据的 API 调用
- 实现区域解锁状态判断（根据 player_regions）
- 实现区域数据刷新机制

### 步骤 4：实现区域状态同步

- 从 player-service 获取玩家已解锁区域列表
- 在世界地图上高亮显示已解锁区域

- 显示区域声望值（如已实现）
