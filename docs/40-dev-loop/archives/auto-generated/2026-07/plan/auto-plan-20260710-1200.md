## 任务目标与背景

### 为什么要做这件事

Sprint 1 P0 项已全部完成，项目进入 Sprint 2 AI 生成接入阶段。

当前 generation-service 已具备：
- LLM 服务适配器（支持 OpenAI API 和 Mock）- S2-01 完成
- 内容生成器（NPC/任务/区域描述生成）- S2-01 完成
- 模板管理模块（TemplateManager，支持模板加载、匹配、版本管理）- auto-20260710-0900 完成
- 质量评分模块（QualityScorer，质量阈值 0.75）- auto-20260710-0900 完成
- NPC 生成模板体系（6个职业模板 + 数据适配器）- S2-02 完成

但缺少 **完整的任务生成模板**：
- 当前模板仅为简单 JSON 定义（quest_template.json），字段不完整
- 缺少 Jinja2 模板文件（不像 NPC 有 templates/npc/ 目录）
- 生成的任务数据无法直接导入 world-service 的 Quest 系统
- 任务字段完整度未达到验收标准（>95%）

根据需求迭代计划 Sprint 2 S2-03「任务生成模板」为 P0 优先级，验收标准：「生成的任务字段完整度>95%，符合世界观」。

### 目标

实现完整的任务生成模板体系，包括：
1. 创建任务生成 Jinja2 模板文件（主线、支线、事件、日常四种类型）
2. 实现任务模板渲染逻辑（基于世界骨架和投票结果）
3. 实现任务生成后的数据转换（适配 world-service Quest 数据结构）
4. 集成质量评分（确保生成质量达标）
5. 完整测试覆盖

## 具体执行步骤

### 步骤 1：设计任务生成模板结构

- 分析 world-service Quest 数据模型（quest_list.json、quest_definitions 数据库表）
- 确定任务生成模板必需字段：
  - 基础信息：title、description、quest_type、chapter_id、region_key
  - NPC 关联：start_npc_key、end_npc_key
  - 前置条件：prerequisites
  - 任务目标：objectives（id、description、type、target、completed）
  - 奖励：rewards（experience、reputation、gold、items）
  - 失败条件：failure_condition
  - 世界观约束：aligns_with_faction、impact

### 步骤 2：创建任务生成模板文件

- 创建 `services/generation/templates/quest/quest_base.jinja2`：基础任务模板
- 创建 `services/generation/templates/quest/quest_main.jinja2`：主线任务模板
- 创建 `services/generation/templates/quest/quest_side.jinja2`：支线任务模板
- 创建 `services/generation/templates/quest/quest_event.jinja2`：事件任务模板
- 创建 `services/generation/templates/quest/quest_daily.jinja2`：日常任务模板
- 每个模板包含完整字段定义和 Prompt 指令

### 步骤 3：实现任务模板渲染逻辑

- 更新 `app/core/template_manager.py`：
  - 添加任务模板匹配策略（基于 quest_type）
  - 添加 `get_quest_template_by_type` 方法
- 更新 `app/core/content_generator.py`：
  - 优化 `generate_quest_text()` 方法
  - 添加任务专用生成参数构建
  - 添加生成结果结构化解析（JSON 格式输出）

### 步骤 4：实现任务数据转换适配器

- 创建 `app/core/quest_data_adapter.py`：
  - 实现生成结果到 world-service Quest 数据结构的转换
  - 验证字段完整性（确保>95%字段已填充）
  - 处理缺失字段的默认值填充
  - 验证数据格式（quest_type 枚举值等）

### 步骤 5：集成质量评分与内容审核

- 更新 `app/core/quality_scorer.py`：
  - 添加任务专用评分指标（字段完整性、目标合理性、奖励平衡性）
  - 设置任务质量评分权重
- 更新 `app/tasks/content_generation.py`：
  - 添加任务生成后的质量评分步骤
  - 添加质量不达标时的重试逻辑

### 步骤 6：测试编写

- 创建 `tests/test_quest_template.py`：任务模板加载与渲染测试
- 创建 `tests/test_quest_data_adapter.py`：任务数据转换测试
- 创建 `tests/test_quest_generation_integration.py`：任务生成端到端测试
- 使用 MockLLMAdapter 进行单元测试

## 风险与应对

| 风险 | 应对策略 |
|------|----------|
| LLM 输出格式不稳定 | 严格的 JSON schema 校验，解析失败时重试 |
| 字段缺失 | 设置默认值填充策略，完整性<95%时标记失败 |
| 奖励失衡 | 在模板中注入奖励限制约束，审核阶段检查数值平衡 |
