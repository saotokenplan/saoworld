## 任务目标与背景

### 目标

实现投票复盘报告功能，为玩家提供上轮投票的完整回顾：投票结果、实际落地内容、影响区域与参与率统计，增强玩家对世界演化进程的感知与参与感。

### 背景

当前投票历史仅展示玩家自己的投票记录与内容包摘要，缺少面向单轮投票周期的完整复盘视图。S4-05 投票复盘报告将：
- 汇总单轮投票周期的关键数据（总票数、参与率、获胜候选、各候选占比）
- 关联展示该周期落地产生的具体内容包、NPC、任务、区域
- 为玩家提供「投票→结果→落地影响」的完整叙事闭环

### 需求来源

Sprint 4 S4-05「投票复盘报告」，在每日进展报告（2026-07-13）中标记为"未开始"。S4-01「投票结果落地展示」与 S4-04「投票结果可视化」已分别为本任务奠定内容包关联与图表展示基础。

## 具体执行步骤

### 步骤 1：vote-service 新增投票复盘报告 API

**目标**：提供单轮投票周期的完整复盘数据。

**变更文件**：
- `services/vote/app/api/routes.py` - 新增复盘报告路由
- `services/vote/app/schemas/vote.py` - 新增复盘报告响应 Schema
- `services/vote/app/repositories/vote_repo.py` - 新增复盘报告查询方法

**实现内容**：
1. 新增 `GET /api/v1/votes/history/{vote_cycle_id}/review` 接口
2. 权限校验：`votes:history:read` scope
3. 返回数据包含：
   - 投票周期基本信息（vote_cycle_id、chapter_id、标题、状态、起止时间）
   - 投票统计（总票数、加权总票数、参与率、获胜候选）
   - 各候选结果（candidate_id、title、vote_count、weighted_score、percentage）
   - 获胜候选生成参数（generated_params、region_scope）
   - 关联内容包摘要（通过 content_client 批量查询）
4. 参与率通过 `total_votes / eligible_player_count` 估算：
   - 优先使用内容包 gray_scope 中可估算的玩家数
   - 降级使用固定基准值 1000（可配置）

### 步骤 2：content-service 扩展按投票周期批量查询

- `services/content/app/api/routes.py` - 新增批量查询内部/公开接口（如需要）
