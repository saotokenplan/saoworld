## 任务目标与背景

### 目标

实现 player-service 社交数据聚合 API，整合好友系统、私聊系统和公会系统的数据，为客户端提供统一的社交信息查询入口。

### 背景

Sprint 5 社区基础功能阶段，S5-01 好友系统、S5-02 私聊系统、S5-03 公会系统基础已全部完成，S5-05 作为 P0 优先级项，需要在 player-service 提供社交相关接口，为客户端提供便捷的社交数据查询能力，减少客户端多次请求的复杂度。

### 需求来源

`docs/10-requirements/需求迭代计划.md` Sprint 5 S5-05「社交数据API」，验收标准：player-service提供社交相关接口。

## 具体执行步骤

### 步骤 1：分析现有社交相关 API

**目标**：梳理已实现的社交相关接口。

**分析内容**：
1. 好友系统 API（7 个）：
   - POST /api/v1/player/friends/request - 发送好友请求
   - POST /api/v1/player/friends/accept - 接受好友请求
   - POST /api/v1/player/friends/reject - 拒绝好友请求
   - DELETE /api/v1/player/friends/{friend_id} - 删除好友
   - GET /api/v1/player/friends - 好友列表
   - GET /api/v1/player/friends/requests - 待处理请求
   - GET /api/v1/player/friends/{friend_id}/status - 关系状态查询

2. 私聊系统 API（6 个）：
   - POST /api/v1/player/messages - 发送私聊
   - GET /api/v1/player/messages/conversations - 对话列表
   - GET /api/v1/player/messages/conversations/{friend_id} - 对话历史
   - POST /api/v1/player/messages/{message_id}/read - 标记已读
   - GET /api/v1/player/messages/unread - 未读消息
   - GET /api/v1/player/messages/unread/count - 未读数

3. 公会系统 API（10 个）：
   - POST /api/v1/player/guilds - 创建公会
   - GET /api/v1/player/guilds/my - 获取我的公会
   - GET /api/v1/player/guilds/{guild_id} - 获取公会详情
   - PUT /api/v1/player/guilds/{guild_id} - 更新公会信息
   - DELETE /api/v1/player/guilds/{guild_id} - 解散公会
   - POST /api/v1/player/guilds/{guild_id}/members - 邀请成员
   - DELETE /api/v1/player/guilds/{guild_id}/members/{player_id} - 移除成员
   - POST /api/v1/player/guilds/{guild_id}/leave - 退出公会
   - POST /api/v1/player/guilds/{guild_id}/transfer - 转让会长
   - GET /api/v1/player/guilds/{guild_id}/members - 成员列表

### 步骤 2：设计社交数据聚合 API

**目标**：设计统一的社交数据聚合接口。

**变更文件**：
- `services/player/app/api/routes.py` - 新增社交聚合路由
- `services/player/app/schemas/player.py` - 新增社交聚合 Schema

**API 接口**：
- `GET /api/v1/player/social/overview` - 社交概览（Scope: social:read）
  - 返回好友数、未读消息数、公会信息、最近好友列表（前5个）

**响应数据结构**：
```python
class SocialOverview(BaseModel):
    friends_count: int  # 好友总数
    pending_requests: int  # 待处理好友请求数
    unread_messages: int  # 未读消息数
    guild_info: GuildSummary | None  # 公会信息（如果已加入）
    recent_friends: list[FriendSummary]  # 最近5个好友

class GuildSummary(BaseModel):
    guild_id: UUID
    name: str
    level: int
    member_count: int
    my_role: str  # leader/officer/member

class FriendSummary(BaseModel):
    player_id: UUID
    player_name: str
    level: int
    online: bool
```

### 步骤 3：实现社交数据聚合 API

**目标**：实现社交概览接口的业务逻辑。

**变更文件**：
- `services/player/app/api/routes.py` - 实现社交概览接口
- `services/player/app/schemas/player.py` - 定义响应 Schema

**实现内容**：
1. 调用 FriendRepository 获取好友数和待处理请求数
2. 调用 PrivateMessageRepository 获取未读消息数
3. 调用 GuildRepository 获取玩家所在公会信息
4. 聚合数据返回统一响应
