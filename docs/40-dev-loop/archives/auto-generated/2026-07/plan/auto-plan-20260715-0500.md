## 任务目标与背景

### 目标
执行 Sprint 8 S8-01「客户端性能优化」第一阶段：APIManager 异步化改造，解决同步阻塞请求导致的性能瓶颈，提升客户端响应流畅度。

### 背景
- 项目已进入 Sprint 0 灰度发布验证阶段，Sprint 1-7 全部完成
- S8-01 性能分析报告已生成（auto-20260715-0400），识别出 APIManager 的同步阻塞请求是 P0 级阻塞性问题
- 当前 `_make_request()` 使用 `await get_tree().process_frame` 循环阻塞等待响应，导致游戏主线程卡顿
- 每次请求都创建新的 HTTPRequest 节点，无连接复用，浪费资源
- 重试策略简单（固定指数退避），没有抖动，可能导致重试风暴

### 优化目标
- API 请求改为真正的异步非阻塞模式
- HTTP 请求连接池复用（最大 5 个）
- 智能重试策略（带抖动和退避）
- 请求超时控制

- 保持同步方法兼容性（用于简单场景）
