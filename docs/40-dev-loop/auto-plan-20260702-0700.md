## 任务目标与背景

vote-service 和 world-service 已完整实现并通过验证，具备投票链路和区域管理能力。但 MVP 还需要内容链路作为核心支撑——内容包管理、灰度发布、回滚是 AI 生成内容上线的必经之路。

根据 `backend-data-spec.md` 定义，`content_packages` 表是内容版本管理的核心表，API 规范已定义 `GET /api/v1/content/updates`、`GET /api/v1/content/packages/{content_package_id}`、`POST /api/v1/ops/content-packages/{id}/release`、`POST /api/v1/ops/content-packages/{id}/rollback` 等接口。

**本次目标**：初始化 content-service 服务骨架，实现内容包（content_packages）数据模型、玩家查询接口、运营管理接口（发布/回滚）、JWT 认证、统一响应 envelope、审计日志持久化，遵循 vote-service 和 world-service 已验证的架构模式。

### 步骤 5：实现 API 路由

- 健康检查：`GET /api/v1/health`

  - `GET /api/v1/content/packages/{package_id}` - 获取内容包详情
- 运营接口（JWT + ops scope）：
  - `POST /api/v1/ops/content-packages` - 创建内容包
  - `POST /api/v1/ops/content-packages/{package_id}/release` - 发布内容包（灰度/全量）

- 添加 `content:read` scope 校验依赖
- 玩家接口需 Bearer Token + content:read scope
- 运营接口需 `content:release` 和 `content:rollback` scope
