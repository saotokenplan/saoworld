## 任务目标与背景

vote-service、world-service、content-service 和 generation-service 已完整实现并通过验证，具备投票链路、区域管理、内容包管理和生成请求管理能力。但 MVP 的内容链路还缺少最后核心环节——review-service 负责结构化校验、风险判断和人工复核流转，是连接 AI 生成内容与内容包发布的关键桥梁。

根据 `backend-data-spec.md` 定义，`review_records` 表记录审核结果，包含审核项（一致性、数值、安全、重复度）、质量评分和风险级别。API 规范中已定义审核批准接口（`POST /api/v1/ops/review/{object_id}/approve`），但审核记录的创建、查询和人工复核流程尚未实现。

**本次目标**：初始化 review-service 服务骨架，实现审核记录（review_records）数据模型、运营审核接口（创建审核记录、审核批准/拒绝、查询审核列表）、JWT 认证、统一响应 envelope、审计日志持久化，遵循 generation-service 已验证的架构模式。

### 步骤 5：实现 API 路由

- 健康检查：`GET /api/v1/health`
- 运营接口（JWT + reviewer/ops scope）：

  - `GET /api/v1/ops/review/records/{review_id}` - 获取审核记录详情
  - `POST /api/v1/ops/review/{object_id}/approve` - 批准审核对象（批量审核）
  - `POST /api/v1/ops/review/{object_id}/reject` - 拒绝审核对象
