## 任务目标与背景

vote-service、world-service、content-service、generation-service 和 review-service 已完整实现并通过验证。但当前架构缺少统一的入口层，客户端需要分别连接多个服务。根据后端服务拆分规范，gateway-service 作为客户端统一入口，负责鉴权、限流、会话上下文管理和请求路由转发。

根据 `backend-data-spec.md` 和 `12-api-design.md`，网关需要：
- 统一接收所有客户端请求
- 验证 JWT Token 并解析用户信息
- 转发请求到对应后端服务
- 统一处理响应格式和错误
- 提供限流、熔断等中间件能力

**本次目标**：初始化 gateway-service 服务骨架，实现统一鉴权中间件、服务路由转发、请求追踪、限流中间件、统一响应处理，遵循已验证的服务架构模式。
