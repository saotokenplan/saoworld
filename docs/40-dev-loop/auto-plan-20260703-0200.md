## 任务目标与背景

vote-service、world-service、content-service、generation-service、review-service 和 gateway-service 已完整实现并通过验证。但 MVP 的玩家数据管理链路还缺少核心环节——player-service 负责账号、角色、成长、声望、章节进度管理，是连接玩家与游戏世界的关键桥梁。

根据 `backend-data-spec.md` 定义，`players` 表存储玩家基础信息，`player_quests` 表记录玩家任务进度，`player_regions` 表记录玩家区域解锁状态。API 规范中已定义玩家任务列表接口（`GET /api/v1/quests`），但玩家数据的创建、查询和状态管理尚未实现。

**本次目标**：初始化 player-service 服务骨架，实现玩家数据模型（Player、PlayerQuest、PlayerRegion）、玩家 API（查询任务列表、区域状态、玩家信息）、运营管理接口（创建玩家、更新玩家状态）、JWT 认证、统一响应 envelope、审计日志持久化，遵循已验证的服务架构模式。

### 步骤 5：实现 API 路由

- 健康检查：`GET /api/v1/health`
- 玩家接口（JWT + player scope）：
  - `GET /api/v1/player/info` - 获取当前玩家信息
  - `GET /api/v1/player/quests` - 获取玩家任务列表（分页）
  - `GET /api/v1/player/regions` - 获取玩家区域状态（分页）
- 运营接口（JWT + ops scope）：
  - `POST /api/v1/ops/players` - 创建玩家
  - `GET /api/v1/ops/players` - 查询玩家列表（分页）
  - `GET /api/v1/ops/players/{player_id}` - 获取玩家详情
  - `PUT /api/v1/ops/players/{player_id}` - 更新玩家信息
  - `POST /api/v1/ops/players/{player_id}/regions/{region_id}/unlock` - 解锁区域
