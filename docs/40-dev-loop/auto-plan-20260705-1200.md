## 任务目标与背景

**当前阶段**：内容发布与验证阶段（端到端集成验证完成）

**当前目标**：完成首期内容包灰度发布，验证端到端玩法流程，进入内容生成与投票驱动世界更新的闭环

**发现的问题**：

1. **P1 - 各服务错误码与 API 规范不一致**：
   - `docs/30-api/api-error-codes.md` 中定义了标准错误码（如 `VOTE_CYCLE_NOT_FOUND`、`DUPLICATE_VOTE`、`CONTENT_PACKAGE_NOT_FOUND` 等）
   - 但各服务实际使用的错误码与规范不一致：
     - vote-service 使用 `NO_OPEN_VOTE_CYCLE`、`ALREADY_VOTED`、`CANDIDATE_NOT_FOUND` 等
     - world-service 使用 `REGION_NOT_FOUND`、`INVALID_REGION_STATUS` 等
     - content-service 使用 `PACKAGE_NOT_FOUND`、`INVALID_PACKAGE_STATE` 等
   - 错误码不统一会导致客户端错误处理混乱，不利于 SDK 开发和问题排查

2. **P1 - 异常处理机制需完善**：
   - 各服务的异常处理逻辑分散在 `main.py` 和 `routes.py` 中
   - 缺少统一的异常类和错误码常量定义
   - 部分错误响应缺少 `details` 字段
   - 预留错误码（`INTERNAL_ERROR`、`TOKEN_EXPIRED` 等）未完全落地

3. **P2 - 客户端错误码映射需同步更新**：
   - Godot 客户端的 `APIManager` 中错误码处理需要与服务端对齐

**本次目标**：
1. 统一 8 个后端服务的错误码，对齐 `api-error-codes.md` 规范
2. 为各服务添加统一的错误码常量定义和自定义异常类
3. 完善异常处理机制，确保错误响应格式一致
4. 同步更新客户端错误码映射
5. 更新 `api-error-codes.md`，将已落地的预留错误码移入对应域
6. 确保所有测试通过
