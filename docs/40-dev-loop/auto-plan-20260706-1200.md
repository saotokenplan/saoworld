## 任务目标与背景

### 目标
将 ops-service 的系统状态接口从硬编码返回改进为实际 HTTP 调用各服务的健康检查接口，实现真实的服务健康状态监控。

### 背景
项目当前处于内容发布与验证阶段，核心目标是完成首期内容包灰度发布，验证端到端玩法流程。

当前 `GET /api/v1/ops/system/status` 接口返回的是硬编码的服务状态，所有服务都显示为 `ok`，无法反映真实的服务健康状况：

```python
services = [
    SystemServiceStatus(name="vote-service", status="ok", version="0.1.0"),
    ...
]
```

这导致：
1. 运营人员无法通过运营后台了解各服务的真实健康状态
2. 服务异常时无法及时发现和响应
3. 灰度发布和全量发布前无法进行有效的健康检查
4. 与 `tools/health-check.sh` 的真实健康检查逻辑不一致
