## 任务目标与背景

### 为什么做这件事

P2 阶段 9 个代理角色（Product Agent、System Designer、Gameplay、World、Backend、QA、Build、Ops、Orchestrator）已全部实现，但存在一个关键缺口：**Orchestrator 的 `execute_tasks` 方法当前是模拟执行**，只生成模拟的 ExecutionLog，不会真正调用其他 Agent 的 CLI 或核心逻辑。这意味着多代理协同的核心价值——Orchestrator 将任务分发给真实 Agent 执行——尚未落地。

同时，缺少**多代理协同端到端集成测试**，没有任何测试验证 Orchestrator 能真正调度 Product Agent → System Designer → Backend Agent 等完整链路。

这是 P0 级别的功能缺口，直接阻塞了多代理协同研发闭环的实际使用。

### 目标

1. 实现 `AgentDispatcher` 模块，使 Orchestrator 能通过子进程调用各 Agent 的 CLI 或直接调用核心逻辑
2. 实现 `WorkflowExecutor` 模块，支持按依赖关系顺序执行任务、收集结果、传递给下游 Agent
3. 编写多代理协同端到端集成测试，验证完整链路：Product Agent 生成需求 → System Designer 生成设计 → Backend Agent 生成代码 → QA Agent 验证
4. 保持所有现有测试通过
