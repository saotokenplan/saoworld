## 具体执行步骤

### 步骤 1：创建洞察与需求数据模型（ops-service）
- 在 ops-service 中新增 `insights` 表（洞察记录）
- 在 ops-service 中新增 `requirements` 表（需求包记录）
- 创建 Alembic 迁移脚本
- 实现对应的 Repository 层

### 步骤 2：实现洞察提取算法与质量评估
- 实现洞察分类（内容偏好、区域热度、投票倾向、难度反馈、内容缺口）
- 实现质量评估（置信度、影响力、新颖度、可行性）
- 实现洞察提取引擎（从分析报告中提取洞察）
- 实现洞察质量评分计算

### 步骤 3：实现需求生成引擎
- 实现从洞察到需求包的转化逻辑
- 实现需求优先级评估（基于影响力和可行性）
- 实现需求审核状态流转
- 实现需求包队列管理

### 步骤 4：实现洞察与需求 API 接口（ops-service）
- 在 ops-service 中新增洞察路由模块
- 实现 `GET /api/v1/insights` 获取洞察列表
- 实现 `GET /api/v1/insights/{insight_id}` 获取洞察详情
- 实现 `POST /api/v1/ops/insights/{insight_id}/generate-requirement` 基于洞察生成需求包
- 实现 `GET /api/v1/ops/requirements` 获取需求包列表
- 实现 `GET /api/v1/ops/requirements/{requirement_id}` 获取需求包详情
- 实现 `POST /api/v1/ops/requirements/{requirement_id}/approve` 审核批准需求包
- 统一响应 envelope 格式

### 步骤 5：编写测试用例
- ops-service 新增洞察 API 测试
- ops-service 新增需求 API 测试
- 覆盖正常流程和异常场景
- 确保 ruff 和 mypy 检查通过
