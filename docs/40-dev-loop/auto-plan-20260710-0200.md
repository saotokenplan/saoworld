## 任务目标与背景

**目标**：实现 world-service 的 NPC 与任务数据接口（数据库表 + 仓储 + API + 迁移脚本 + 测试），为 Sprint 1 P0 项 S1-11「NPC 与任务数据接口」提供后端数据基础。

**背景**：
- Sprint 0 技术准备与灰度发布基础设施已全部完成
- Sprint 1 已启动：S1-01（玩家移动与场景切换）和 S1-04/S1-09（任务系统 API）已分别在 auto-20260710-0100 和 auto-20260710-0000 中完成
- 当前 NPC 和任务定义数据仍以 JSON 文件（`game/data/npcs/npc_list.json`、`game/data/quests/quest_list.json`）形式存在于客户端
- 缺少后端统一的数据服务，导致：1）客户端无法获取动态更新的 NPC/任务内容；2）服务端其他服务（player-service 的任务进度已对接 player_quests 但缺少 quest_definition 表）缺乏权威数据源；3）运营后台无法对 NPC/任务进行增删改查
- S1-11 是 Sprint 1 P0 项，依赖 S1-03（NPC 对话系统）和 S1-04（任务系统基础），先完成后端数据接口，后续 S1-03（客户端对话系统）和 S1-10（玩家存档系统）都可以直接消费
- 项目已具备成熟的世界服务骨架（region、world_skeleton、audit_logs 三表 + 完整 API + 49 个测试用例），新功能遵循既有架构

**优先级**：P0（阻塞 Sprint 1 后续 NPC 对话与任务玩法客户端落地）

## 具体执行步骤

### 步骤 1：扩展领域模型（NPC + QuestDefinition）
- 在 `services/world/app/domain/models.py` 中新增：
  - `NPC` 模型：npc_id (UUID 主键)、npc_key (String 业务键，如 `npc_ironward_leader`）、chapter_id、name、title、faction_key、role、location_key、description、personality (JSON)、dialogues (JSON)、related_quests (JSON)、rewards (JSON)、created_at、updated_at
  - `QuestDefinition` 模型：quest_id (UUID 主键)、quest_key (String 业务键，如 `quest_main_ch01_start`）、chapter_id、title、description、quest_type (String)、region_key、start_npc_key、end_npc_key、prerequisites (JSON)、objectives (JSON)、rewards (JSON)、failure_condition (JSON)、created_at、updated_at
- 添加 CHECK 约束和索引（npc_key/quest_key 唯一、chapter_id 索引、quest_type 索引）
- 遵循 backend-data-spec.md 的字段命名（jsonb 字段、UUID、timestamptz）

### 步骤 2：Alembic 迁移脚本
- 创建 `services/world/alembic/versions/2026_07_10_0200_add_npc_and_quest_tables.py`
- 创建 npcs 和 quest_definitions 两张表
- 唯一约束：npc_key、quest_key
- 索引：npcs.chapter_id、npcs.faction_key、quest_definitions.chapter_id、quest_definitions.quest_type、quest_definitions.region_key

### 步骤 3：扩展仓储层
- 在 `services/world/app/repositories/world_repo.py` 中新增 NPC/Quest 方法：
  - `list_npcs(chapter_id, faction_key, limit, offset)` + `count_npcs`
  - `get_npc_by_key(npc_key)` + `get_npc_by_id(npc_id)`
  - `create_npc(...)`
  - `list_quests(chapter_id, quest_type, region_key, limit, offset)` + `count_quests`
  - `get_quest_by_key(quest_key)` + `get_quest_by_id(quest_id)`
  - `create_quest(...)`

### 步骤 4：扩展 Pydantic Schemas
- 在 `services/world/app/schemas/world.py` 中新增：
  - `NpcDialogue`、`NpcResponse`、`NpcListResponse`、`CreateNpcRequest`、`CreateNpcResponse`
  - `QuestObjective`、`QuestResponse`、`QuestListResponse`、`CreateQuestRequest`、`CreateQuestResponse`
  - 复用现有 `EnvelopeResponse`、`PaginatedMeta`、`ErrorDetail` 通用结构

### 步骤 5：实现 API 路由
- 在 `services/world/app/api/routes.py` 中新增：
  - 玩家接口（RequireWorldReadScope）：
    - `GET /api/v1/world/npcs` - 列表（支持 chapter_id、faction_key 过滤，分页）
    - `GET /api/v1/world/npcs/{npc_id}` - 按 ID 详情
    - `GET /api/v1/world/npcs/by-key/{npc_key}` - 按业务键详情（客户端用 npc_key 检索）
    - `GET /api/v1/world/quests` - 列表（支持 chapter_id、quest_type、region_key 过滤，分页）
    - `GET /api/v1/world/quests/{quest_id}` - 按 ID 详情
    - `GET /api/v1/world/quests/by-key/{quest_key}` - 按业务键详情
  - 运营接口（RequireOpsRole）：
    - `POST /api/v1/ops/world/npcs` - 创建 NPC
    - `POST /api/v1/ops/world/quests` - 创建任务定义
- 错误码新增：`NPC_NOT_FOUND`、`QUEST_NOT_FOUND`、`NPC_KEY_EXISTS`、`QUEST_KEY_EXISTS`
- 全部接口支持统一 envelope、TraceId 透传、JWT 鉴权、Scope 校验

### 步骤 6：扩展审计与指标
