## 任务目标与背景

**目标**：实现 Sprint 1 P0 项 S1-03「NPC 对话系统」，完成客户端 NPC 对话交互核心能力，支持与 NPC 多轮对话、对话树分支、条件触发、任务接取，以及与 world-service NPC 数据 API 的集成。

**背景**：
- Sprint 1 已提前启动，S1-01「玩家移动与场景切换」、S1-02「世界地图系统」、S1-04/S1-09「任务系统 API」、S1-11「NPC 与任务数据接口」均已完成
- 当前 NPCDialog 实现较为基础：仅支持线性对话序列、本地 JSON 数据、无对话树分支、无条件判断
- world-service 已提供 NPC 列表/详情 API（S1-11 已完成），客户端需要集成
- S1-03 是 Sprint 1 P0 项，为后续 S1-04 客户端集成和 S1-05 战斗系统提供 NPC 交互基础

**优先级**：P0（阻塞 Sprint 1 后续核心玩法落地）

## 具体执行步骤

### 步骤 1：增强对话数据配置

- 扩展 `game/data/npcs/npc_list.json`，为每个 NPC 添加完整对话树结构
- 对话树支持：对话节点（id、text、speaker）、玩家选择（choices）、条件分支（condition）、任务触发（quest_trigger）
- 新增对话状态映射：first_meet、has_quest、quest_completed、default 等

### 步骤 2：重构 NPCDialog 脚本支持对话树

- 重构 `game/scripts/ui/npc_dialog.gd`，支持对话树遍历
- 实现对话节点跳转（根据选择跳转到不同节点）
- 实现条件判断（根据玩家状态决定可用对话分支）
- 实现对话事件触发（任务接取、声望变化等）
- 保持向后兼容线性对话模式

### 步骤 3：创建 NPCDialog 场景

- 创建独立的 `game/scenes/ui/npc/NPCDialog.tscn` 场景文件
- 包含：NPC 名称、NPC 头像占位、对话文本、玩家选择按钮容器、关闭按钮
- 美观布局：对话气泡、角色名、选择高亮

### 步骤 4：扩展 WorldManager 支持 NPC 数据

- 在 `game/scripts/autoload/WorldManager.gd` 添加 NPC 相关方法
- 实现 `fetch_npcs()` 从 world-service NPC API 获取数据
- 实现 `fetch_npc_detail(npc_key)` 获取 NPC 详情
- 实现 NPC 数据缓存

### 步骤 5：实现区域场景 NPC 交互点

- 扩展 `game/scenes/world/CoreRegion.tscn` 添加 NPC 交互点
- NPC 交互点：可视化标记（Area2D）、接近检测、交互提示
- 玩家接近 NPC 时显示「按 E 对话」提示
- 按键触发打开 NPCDialog 场景

### 步骤 6：集成 NPC 对话与任务系统

- NPCDialog 接取任务时调用 PlayerManager 的任务接取 API
- 对话内容根据玩家当前任务状态动态变化
- 任务完成后 NPC 对话内容自动更新

### 步骤 7：编写 GUT 测试用例

- 对话树遍历测试（分支选择、节点跳转）
- 条件判断测试（first_meet / has_quest / default 状态切换）
- 任务接取信号测试
- 空对话树和边界情况测试
- WorldManager NPC 数据缓存测试

### 步骤 8：文档与状态更新

- 更新 `docs/00-governance/project-status.md`，记录 S1-03 完成状态
- 更新 `docs/10-requirements/需求迭代计划.md`，标记 S1-03 已完成
