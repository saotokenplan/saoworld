## 任务目标与背景

**目标**：实现 Sprint 1 P0 项 S1-10「玩家存档系统」，完成客户端玩家数据持久化能力，支持位置、任务状态、基础属性等核心数据的保存与加载，确保玩家进度不丢失。

**背景**：
- Sprint 1 已提前启动，S1-01/S1-02/S1-03/S1-04/S1-05/S1-09/S1-11 均已完成
- 当前 GameState 已包含玩家基础属性（等级、经验、位置、血量等），PlayerManager 提供任务状态管理
- S1-06「背包与资源系统」尚未完成（P1项），本次存档系统先支持基础数据，后续扩展背包
- S1-10 是 Sprint 1 最后一个 P0 项，完成后 Sprint 1 核心玩法链路完整闭环

**依赖关系**：
- S1-04「任务系统基础」已完成 ✅
- S1-06「背包与资源系统」未完成（后续扩展支持）

**验收标准**：
- 玩家退出游戏后再次进入，位置恢复到上次保存点
- 玩家任务进度保存并恢复（已接取、进行中、已完成）
- 玩家基础属性保存（等级、经验、血量）
- 存档数据支持本地文件存储（JSON格式）
- 存档时机明确（场景切换、任务更新、手动保存）
- 客户端启动时自动加载存档

**优先级**：P0（阻塞 Sprint 1 完整交付）

## 具体执行步骤

### 步骤 1：设计存档数据结构

- [x] 创建 `game/data/save/save_schema.json` 定义存档数据结构
- [x] 存档结构包含：
  - `schema_version`（版本标识）
  - `player_profile`（玩家档案：player_id、display_name、created_at、last_played_at）
  - `player_position`（位置信息：current_scene、position_x、position_y、current_region_id）
  - `player_attributes`（基础属性：level、experience、health、max_health、attack、defense）
