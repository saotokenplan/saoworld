## 任务目标与背景

### 为什么要做这件事

Sprint 2 AI 生成接入阶段已完成 S2-01（LLM服务接入）、S2-02（NPC生成模板）、S2-03（任务生成模板）、S2-05（生成质量评分）、S2-06（投票结果→生成参数映射），核心生成能力已就绪。

根据需求迭代计划 Sprint 2 S2-07「端到端闭环验证」为 P0 优先级，验收标准：「投票→生成→审核→打包→发布→客户端可见」。

当前需要验证完整链路是否已经具备端到端能力，包括：
1. vote-service 投票结算事件发布
2. workers 事件处理器触发内容生成
3. generation-service 创建生成请求并生成内容
4. review-service 审核生成内容
5. content-service 内容包打包与发布
6. 客户端 API 获取并加载内容

### 目标

1. 验证各服务间事件传递链路完整性
2. 验证端到端数据流转正确性
3. 更新或补充端到端集成测试
4. 确认完整闭环可运行

## 具体执行步骤

### 步骤 1：验证投票→生成链路

- 检查 vote-service 事件发布逻辑（`vote.result.finalized`）
- 检查 workers 事件处理器（`handle_vote_result_finalized`）
- 检查 generation-service 生成请求创建流程
- 验证参数传递正确性（generated_params、region_scope）

### 步骤 2：验证生成→审核链路

- 检查 generation-service 生成对象状态流转
- 检查 review-service 审核流程触发
- 验证质量评分机制是否生效
- 验证审核通过后内容状态更新

### 步骤 3：验证审核→打包→发布链路

- 检查 review 完成后触发打包的逻辑
- 检查 content-service 内容包创建
- 检查灰度发布流程
- 验证发布状态正确流转

### 步骤 4：验证客户端可见链路

- 检查 content-service 玩家 API（`/api/v1/content/updates`）
- 验证灰度可见性判断逻辑
- 验证客户端 ContentManager 加载逻辑

### 步骤 5：补充端到端集成测试

- 检查现有 playtest 端到端测试覆盖范围
- 补充或更新测试用例验证完整链路

### 步骤 6：更新项目状态文档

- 更新 project-status.md，标记 S2-07 完成
- 更新 auto-progress-log.md
