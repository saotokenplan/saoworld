## 任务目标与背景

### 目标

实现聚落描述生成能力，使 AI 能够根据区域设定和世界观生成符合设定的聚落描述。

### 背景

Sprint 2 AI 生成接入阶段已完成：
- S2-01 LLM 服务接入 ✅
- S2-02 NPC 生成模板 ✅
- S2-03 任务生成模板 ✅
- S2-05 生成质量评分 ✅
- S2-06 投票结果→生成参数映射 ✅
- S2-07 端到端闭环验证 ✅

剩余进行中项：S2-04 聚落描述生成、S2-08 生成成本控制

聚落是世界中的小型定居点，包括村庄、营地、集市等，是玩家探索和互动的重要场景。需要生成符合区域设定、资源特点和阵营关系的聚落描述。

### 验收标准

- 生成的聚落描述与区域设定一致
- 生成字段完整度 > 90%
- 资源与阵营相符
- 描述符合世界观

## 具体执行步骤

### 步骤 1：创建聚落描述生成模板

- 创建 `templates/settlement/settlement_base.jinja2` 基础模板
- 创建 `templates/settlement_template.json` JSON 配置
- 更新 `templates/region_template.json` 添加聚落相关字段

### 步骤 2：创建 SettlementDataAdapter 数据适配器

- 创建 `app/core/settlement_data_adapter.py`
- 实现字段完整度验证
- 实现默认值填充
- 实现 world-service 格式适配

### 步骤 3：扩展 TemplateManager 支持聚落模板

- 添加 `get_settlement_template_by_type` 方法
- 更新 `_init_jinja` 添加 settlement 目录
- 更新 `list_jinja_templates` 支持 settlement 类型

### 步骤 4：扩展 ContentGenerator 添加 generate_settlement 方法

- 添加 `generate_settlement` 异步方法
- 添加 `_build_settlement_prompt` 提示构建方法
- 更新 `_build_system_prompt` 添加 settlement 系统提示

### 步骤 5：扩展 QualityScorer 支持聚落质量评分

- 添加 `score_settlement` 方法
- 实现完整性、一致性、合理性评分维度

### 步骤 6：扩展 API 路由支持聚落生成

- 在 `routes.py` 添加聚落生成端点
- 更新 schemas 添加聚落相关请求/响应模型

### 步骤 7：编写测试用例

- 聚落模板管理测试
- 数据适配器测试
- 生成器集成测试
