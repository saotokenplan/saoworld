## 一、任务目标与背景

### 1.1 任务目标

完成 S1-08「声望解锁系统」客户端 UI 优化（步骤 7，原计划中标注为"留待后续迭代"）。将后端已经实现的声望解锁能力在客户端 UI 上完整呈现，让玩家能够直观看到声望锁、任务要求、对话门槛与解锁进度。本任务为 P1 收尾，4 个明确子目标：

1. **世界地图（WorldMap）**：在区域卡片上显示"声望未达标/未解锁"提示；详情面板展示解锁所需声望阈值与玩家当前声望进度
2. **任务面板（QuestPanel）**：在任务列表中按声望过滤；在任务详情面板显示声望要求（min_reputation / required_reputation_level）
3. **NPC 对话（NPCDialog）**：当 NPC 声望不足时显示"声望不足"提示并隐藏/灰化声望相关对话选项
4. **声望面板（ReputationPanel）**：在声望等级详情面板显示"距离下一等级还需多少声望"与"下一阈值可解锁的内容"进度提示

### 1.2 背景说明

S1-08 任务在 `auto-20260710-2200` 中完成了后端核心功能（player-service + world-service）和客户端核心逻辑（PlayerManager + WorldManager 的声望过滤和解锁判断方法），并通过 95 个测试。但步骤 7"客户端 UI 优化"被标记为"留待后续迭代，本期完成核心逻辑"，导致：

- 玩家在 WorldMap 上看到"已解锁"的区域，但不知道这个区域是按声望解锁的还是按状态解锁的
- 玩家在 QuestPanel 上看不到任务需要多少声望才能接取
- 玩家与 NPC 对话时，对话树在判定不可达时仍可能显示部分选项，没有友好的声望门槛提示
- 玩家在 ReputationPanel 上能看到当前声望等级和下一阈值，但没有提示"再获得 X 点声望可解锁 Y 区域/任务/NPC"

这些缺失导致 S1-08 的玩法价值对玩家不可见，属于"功能完成但体验未完成"。

### 1.3 现有基础

**客户端（已有方法，需要 UI 集成）：**

## 二、具体执行步骤

### 步骤 1：WorldManager 增强 - 区域解锁条件格式化方法
- 新增 `get_region_unlock_requirement_text(region_id) -> String`：返回形如"需要声望 3000（友好）"的人类可读解锁要求文本
- 新增 `get_region_reputation_progress(region_id) -> Dictionary`：返回 `{current: int, required: int, progress: float, unlocked: bool}`，区域解锁阈值下的进度信息
- 新增 `is_region_locked_by_reputation(region_id) -> bool`：判断区域是否因声望不足而锁定（区别于管理员锁定的区域）

### 步骤 2：WorldMap UI 增强
- `world_map.gd`：
  - 区域卡片渲染时调用 `is_region_locked_by_reputation` 判断，若锁定则在卡片文字后追加"🔒 需声望 3000"
  - `_show_region_detail` 中新增"解锁要求"标签：调用 `get_region_unlock_requirement_text` 显示要求；调用 `get_region_reputation_progress` 显示当前进度条
  - 监听 `PlayerManager.reputation_unlocked` 信号，触发局部刷新
- `WorldMap.tscn`：
  - 在 `RegionDetail` 面板下新增 `UnlockRequirement` 标签（解锁要求）
  - 在 `RegionDetail` 面板下新增 `UnlockProgress` 进度条（解锁进度）

### 步骤 3：QuestPanel UI 增强
- `quest_panel.gd`：
  - 任务列表渲染时调用 `WorldManager.is_quest_accessible` 判断，不可达的任务以"🔒"图标标记并降透明度
  - `_show_quest_detail` 中在状态/奖励之间新增"声望要求"标签，调用 `WorldManager.get_quest_min_reputation` 和 `PlayerManager.get_reputation_level` 渲染要求
  - 任务接取时若服务端返回 `REPUTATION_LOCKED` 错误码，友好提示"声望不足，无法接取"

### 步骤 4：NPCDialog UI 增强
- `npc_dialog.gd`：
  - `_show_tree_node` 中渲染对话选项前调用 `WorldManager.is_npc_accessible` 判断，若 NPC 不可达，在对话框顶部显示"🔒 此 NPC 需要声望 X（Y）才能完全互动"提示
  - 对话选项（choice）根据是否可达调整样式：可达 → 正常蓝色，不可达 → 灰色并禁用
  - `_show_quest_accepted_info` 中若任务声望不足，提示"接受后无法完成（声望不足）"

### 步骤 5：ReputationPanel UI 增强
- `reputation_panel.gd`：
  - `_render_detail` 中调用 `PlayerManager.get_next_unlock_threshold` 计算下一阈值与进度，新增"下一等级还需"文本与"可解锁内容"提示
  - 详情面板新增"可解锁内容"区域：调用 `PlayerManager.get_unlocked_regions_by_reputation` 和 `WorldManager.get_accessible_npcs/quests` 列出该区域在更高声望下可解锁的内容
  - 监听 `PlayerManager.reputation_unlocked` 信号自动刷新详情

### 步骤 6：WorldMap.tscn 场景更新
- 在 `RegionDetail` 面板下新增：
  - `UnlockRequirement` Label
  - `UnlockProgress` ProgressBar
- 调整 RegionDetail 面板的 offset_bottom 以容纳新增元素
