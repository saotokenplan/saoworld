## 二、具体执行步骤

### 步骤 1：贡献度数据模型与迁移脚本

在 `player-service` 中：

1. 为 `Player` 模型增加 `contribution_points` 字段（INTEGER，默认 0，>= 0）
2. 新增 `PlayerContribution` 流水表：
   - `contribution_id` UUID PK
   - `player_id` UUID FK 索引
   - `amount` INTEGER > 0
   - `source` VARCHAR(32)（quest、vote、building 等）
   - `source_id` VARCHAR(128) 可选
   - `description` TEXT 可选
   - `created_at` TIMESTAMPTZ
   - CHECK 约束限制 source 合法值
3. 创建 Alembic 迁移脚本

### 步骤 2：贡献度仓储层

新增 `services/player/app/repositories/contribution_repo.py`：

- `get_player_contribution(player_id) -> int`
- `add_contribution(player_id, amount, source, source_id, description) -> PlayerContribution`
- `list_contributions(player_id, limit, offset) -> list[PlayerContribution]`
- 增加贡献度时同步更新 `Player.contribution_points`

### 步骤 3：贡献度 API 与 Schema

1. 在 `services/player/app/schemas/player.py` 中新增：
   - `ContributionSource` 枚举
   - `ContributionResponse`
   - `ContributionListResponse`
   - `AddContributionRequest`
   - 扩展 `PlayerInfoResponse` 增加 `contribution_points`
2. 在 `services/player/app/api/routes.py` 中新增：
   - `GET /api/v1/player/contribution`（玩家查询自身贡献度与流水）
   - `POST /api/v1/ops/players/{player_id}/contribution`（运营增加贡献度）
3. 增加错误码：`CONTRIBUTION_NOT_FOUND`（玩家不存在时）、`INVALID_CONTRIBUTION_AMOUNT`

### 步骤 4：任务完成发放贡献度

在任务完成奖励逻辑中（`player-service` 任务完成 API 或 repository 层）：

- 根据任务奖励配置中的 `contribution_points` 字段（默认 0）发放贡献度
- 若任务奖励未配置该字段，则不发
- 记录贡献度流水，source = `quest`

### 步骤 5：贡献度→投票权重倍率工具

新增 `services/player/app/core/contribution.py`：

- `calculate_vote_weight_multiplier(contribution_points: int) -> float`
- 规则：`1.0 + min(contribution_points / 1000, 0.2)`，即最大 1.2
- 配置化阈值：每 1000 贡献度增加 0.1 倍率，上限 1.2

> 注：vote-service 侧的实际权重校验将在后续任务中实现，本轮仅提供计算工具与数据基础。

### 步骤 6：测试补充

新增 `services/player/tests/test_contribution.py`：

1. 玩家查询贡献度成功（envelope 格式）
2. 运营增加贡献度成功
3. 任务完成自动发放贡献度
4. 贡献度流水查询分页
5. 无效贡献度金额错误
6. 贡献度→权重倍率计算（边界值：0、500、1000、2000、10000）
7. 玩家不存在时查询返回 404
