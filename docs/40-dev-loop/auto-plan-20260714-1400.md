# 任务计划：S6-01 运营后台统一API

> 任务标识：auto-20260714-1400

## 任务目标与背景

### 目标

实现运营后台统一 API 层，在 ops-service 新增投票管理代理、内容管理代理、审核工作流代理，为运营后台 Web 界面提供统一入口。

### 背景

Sprint 5 社区基础功能阶段全部完成（S5-01~S5-05），项目进入 Sprint 6 运营工具阶段。ops-service 已有 dashboard、analytics、insights、requirements 等查询 API，但缺少运营操作类 API（投票周期管理、内容包管理、审核工作流）。S6-01 作为 P0 项，需要在 ops-service 实现运营操作的统一入口，将各分散的运营操作 API 聚合到 ops-service。

### 需求来源

`docs/10-requirements/需求迭代计划.md` Sprint 6 S6-01「运营后台Web界面」，验收标准：创建投票周期、管理内容包。

## 具体执行步骤

### 步骤 1：ops-service 新增投票管理代理 API

**目标**：在 ops-service 新增投票管理代理，转发运营操作到 vote-service。

**变更文件**：
- `services/ops/app/core/vote_service_client.py` - 新建文件，vote-service HTTP 客户端
- `services/ops/app/api/routes.py` - 新增投票管理端点
- `services/ops/app/schemas/ops.py` - 新增投票管理 Schema

**实现内容**：
1. 创建 VoteServiceClient，调用 vote-service 运营 API：
   - 创建投票周期（POST /api/v1/ops/vote-cycles）
   - 计划投票周期（POST /api/v1/ops/vote-cycles/{id}/schedule）
   - 开启投票（POST /api/v1/ops/vote-cycles/{id}/open）
   - 关闭投票（POST /api/v1/ops/vote-cycles/{id}/close）
   - 确认结果（POST /api/v1/ops/vote-cycles/{id}/finalize）
   - 查询投票周期列表
   - 查询投票周期详情
2. 新增 7 个 ops-service 端点代理到 vote-service
3. 新增 VoteCycleCreate/VoteCycleResponse Schema

### 步骤 2：ops-service 新增内容管理代理 API

**目标**：在 ops-service 新增内容管理代理，转发运营操作到 content-service。

**变更文件**：
- `services/ops/app/core/content_service_client.py` - 新建文件，content-service HTTP 客户端
- `services/ops/app/api/routes.py` - 新增内容管理端点
- `services/ops/app/schemas/ops.py` - 新增内容管理 Schema

**实现内容**：
1. 创建 ContentServiceClient，调用 content-service 运营 API：
   - 灰度发布（POST /api/v1/ops/content-packages/{id}/release）
   - 全量发布
   - 回滚（POST /api/v1/ops/content-packages/{id}/rollback）
   - 内容包列表
   - 内容包详情
2. 新增 5 个 ops-service 端点代理到 content-service
3. 新增 ContentPackageResponse/ReleaseRequest/RollbackRequest Schema

### 步骤 3：ops-service 新增审核工作流代理 API

**目标**：在 ops-service 新增审核工作流代理，转发运营操作到 review-service。

**变更文件**：
- `services/ops/app/core/review_service_client.py` - 新建文件，review-service HTTP 客户端
- `services/ops/app/api/routes.py` - 新增审核工作流端点
- `services/ops/app/schemas/ops.py` - 新增审核 Schema

**实现内容**：
1. 创建 ReviewServiceClient，调用 review-service API：
   - 审核列表
   - 批准内容（POST /api/v1/ops/review/{object_id}/approve）
   - 拒绝内容
   - 标记需修改
   - 审核统计
2. 新增 5 个 ops-service 端点
3. 新增 ReviewObjectResponse/ReviewStatsResponse Schema

### 步骤 4：新增错误码与业务指标

**目标**：补充运营操作相关的错误码和业务指标。

**变更文件**：
- `services/ops/app/core/errors.py` - 新增错误码
- `services/ops/app/core/metrics.py` - 新增业务指标

**实现内容**：
1. 新增错误码：
   - UPSTREAM_SERVICE_ERROR（上游服务调用失败）
   - VOTE_CYCLE_CREATE_FAILED（投票周期创建失败）
   - CONTENT_RELEASE_FAILED（内容发布失败）
   - REVIEW_APPROVE_FAILED（审核批准失败）
2. 新增业务指标：
   - ops_vote_cycle_ops_total（投票周期操作计数）
   - ops_content_ops_total（内容包操作计数）
   - ops_review_ops_total（审核操作计数）

### 步骤 5：新增审计动作常量

**目标**：为运营操作补充审计动作常量。

**变更文件**：
- `services/ops/app/repositories/audit_repo.py` - 新增审计动作常量

**实现内容**：
1. 新增审计动作常量：
   - ACTION_VOTE_CYCLE_CREATE/OPEN/CLOSE/FINALIZE
   - ACTION_CONTENT_RELEASE/ROLLBACK
   - ACTION_REVIEW_APPROVE/REJECT
2. 新增资源类型常量：
   - RESOURCE_VOTE_CYCLE/CONTENT_PACKAGE/REVIEW_OBJECT
