## 任务目标与背景

### 目标

实现投票异常检测与告警系统，在 vote-service 中新增异常行为检测规则、异常记录存储、告警指标和运营查询 API，为灰度发布后的运营安全提供保障。

### 背景

Sprint 5 社区基础功能阶段全部完成（S5-01~S5-05），Sprint 6 S6-01 运营后台统一API已完成，项目具备首期内容包灰度发布条件。S6-07 作为 P1 项，需要在 vote-service 实现投票异常行为检测与自动告警能力，包括：短时间内高频率投票检测、同一设备多账号投票检测、投票权重异常检测、投票时间分布异常检测等。检测到的异常需记录存储，并通过 Prometheus 指标暴露告警。

### 需求来源

`docs/10-requirements/需求迭代计划.md` Sprint 6 S6-07「异常检测告警」，验收标准：投票异常行为检测，自动告警。

## 具体执行步骤

### 步骤 1：新增异常检测数据模型

**目标**：在 vote-service 中新增投票异常记录表。

**变更文件**：
- `services/vote/app/domain/models.py` - 新增 VoteAnomaly 模型

**实现内容**：
1. 新增 `vote_anomalies` 表，字段包括：
   - anomaly_id（UUID 主键）
   - vote_cycle_id（投票周期ID，外键）
   - player_id（玩家ID）
   - vote_id（关联的投票ID，可为空）
   - anomaly_type（异常类型：frequency/device/weight/time_distribution/suspicious_pattern）
   - severity（严重程度：low/medium/high/critical）
   - status（状态：detected/reviewed/resolved/false_positive）
   - description（异常描述）
   - detail_jsonb（异常详情 JSONB）
   - detected_at（检测时间）
   - resolved_at（解决时间，可为空）
   - resolver_id（处理人ID，可为空）
   - created_at（创建时间）
2. CHECK 约束：anomaly_type、severity、status 合法值
3. 索引：vote_cycle_id、player_id、anomaly_type、severity、status、detected_at

### 步骤 2：实现异常检测规则引擎

**目标**：实现投票异常检测规则，在投票提交时自动检测。

**变更文件**：
- `services/vote/app/core/anomaly_detector.py` - 新建文件，异常检测引擎

**实现内容**：
1. 实现 AnomalyDetector 类
2. 检测规则：
   - 短时间高频投票检测（同一玩家 1 分钟内多次投票尝试）
   - 设备指纹重复检测（同一 device_fingerprint 多个不同玩家投票）
   - 投票权重异常检测（权重接近上限或异常倍率）
   - 时间分布异常检测（短时间内大量投票集中出现）
3. 每个检测规则返回 AnomalyDetectionResult
4. 检测阈值可配置（通过 settings）

### 步骤 3：新增异常仓储层

**目标**：实现异常记录的数据库操作。

**变更文件**：
- `services/vote/app/repositories/anomaly_repo.py` - 新建文件

**实现内容**：
1. AnomalyRepository 类
2. 方法：
   - create_anomaly：创建异常记录
   - get_anomaly_by_id：根据ID查询
   - list_anomalies：分页列表（支持按类型、严重程度、状态、周期过滤）
   - update_anomaly_status：更新异常状态
   - get_anomaly_stats：获取异常统计数据
   - count_recent_by_player：统计玩家近期异常数
   - count_recent_by_device：统计设备近期异常数

### 步骤 4：投票提交集成异常检测

**目标**：在投票提交流程中集成异常检测。

**变更文件**：
- `services/vote/app/api/routes.py` - 修改 submit_vote 接口

**实现内容**：
1. 投票提交前/后调用异常检测
2. 检测到异常时记录到 vote_anomalies 表
3. 严重异常（high/critical）仍允许投票，但记录告警
4. 审计日志记录异常检测结果

### 步骤 5：新增运营异常管理 API

**目标**：提供运营侧异常查询与管理接口。

**变更文件**：
- `services/vote/app/api/routes.py` - 新增运营异常管理端点
- `services/vote/app/schemas/vote.py` - 新增异常相关 Schema

**实现内容**：
1. GET /ops/anomalies - 异常记录列表（分页，支持过滤）
2. GET /ops/anomalies/{anomaly_id} - 异常详情
3. POST /ops/anomalies/{anomaly_id}/resolve - 标记已解决
4. POST /ops/anomalies/{anomaly_id}/false-positive - 标记误报
5. GET /ops/anomalies/stats - 异常统计数据（按类型、严重程度、时间分布）

### 步骤 6：新增错误码、业务指标与审计动作

**目标**：补充异常检测相关的错误码、指标和审计。

**变更文件**：
- `services/vote/app/core/errors.py` - 新增错误码
- `services/vote/app/core/metrics.py` - 新增业务指标
- `services/vote/app/repositories/audit_repo.py` - 新增审计动作常量

**实现内容**：
1. 错误码：
   - ANOMALY_NOT_FOUND（异常记录不存在）
   - INVALID_ANOMALY_STATUS（无效的异常状态）
2. 业务指标：
   - vote_anomalies_detected_total（检测到的异常总数，按类型和严重程度标签）
   - vote_anomalies_resolved_total（已解决异常数）
   - vote_anomaly_detection_duration_seconds（检测耗时直方图）
3. 审计动作：
   - ACTION_ANOMALY_DETECTED
   - ACTION_ANOMALY_RESOLVED
   - ACTION_ANOMALY_FALSE_POSITIVE
   - RESOURCE_VOTE_ANOMALY
