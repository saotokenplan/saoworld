## 任务目标与背景

### 目标

实现运营事件配置系统，在 ops-service 中新增运营事件的创建、管理、生效判定和奖励发放能力，为灰度发布后的运营活动提供基础支撑。

### 背景

Sprint 6 运营工具阶段，S6-01 运营后台统一API已完成，S6-07 异常检测告警已完成，项目具备首期内容包灰度发布条件。S6-06 作为 P1 项，需要实现运营事件配置能力，支持限时活动、双倍奖励、登录奖励等运营活动的配置和自动生效。

### 需求来源

`docs/10-requirements/需求迭代计划.md` Sprint 6 S6-06「运营事件配置」，验收标准：配置限时活动、双倍奖励。

## 具体执行步骤

### 步骤 1：新增运营事件数据模型

**目标**：在 ops-service 中新增运营事件配置表。

**变更文件**：
- `services/ops/app/domain/models.py` - 新增 OpsEvent 模型

**实现内容**：
1. 新增 `ops_events` 表，字段包括：
   - event_id（UUID 主键）
   - event_name（事件名称，唯一）
   - event_type（事件类型：double_reward/login_bonus/limited_time/sale/custom）
   - status（状态：draft/active/paused/ended/archived）
   - start_at（开始时间）
   - end_at（结束时间）
   - target_scope（目标范围：all/region/player_level/guild）
   - target_scope_jsonb（目标范围详细配置 JSONB）
   - reward_config_jsonb（奖励配置 JSONB，支持多种奖励类型）
   - multiplier_config_jsonb（倍率配置 JSONB，如经验倍率、贡献度倍率）
   - description（事件描述）
   - rules_jsonb（规则配置 JSONB）
   - created_by（创建人）
   - schema_version（schema 版本，默认 1）
   - created_at（创建时间）
   - updated_at（更新时间）
2. CHECK 约束：event_type、status 合法值
3. 索引：status、event_type、start_at、end_at、(status, start_at, end_at) 复合索引

### 步骤 2：实现事件配置仓储层

**目标**：实现运营事件的数据库操作。

**变更文件**：
- `services/ops/app/repositories/event_repo.py` - 新建文件

**实现内容**：
1. EventRepository 类
2. 方法：
   - create_event：创建事件
   - get_event_by_id：根据ID查询
   - get_event_by_name：根据名称查询
   - list_events：分页列表（支持按类型、状态过滤）
   - update_event：更新事件配置
   - update_event_status：更新事件状态
   - delete_event：删除事件（软删除/归档）
   - get_active_events：获取当前生效的事件列表
   - check_event_overlap：检查时间范围内是否有重叠事件

### 步骤 3：实现事件生效判定与奖励计算引擎

**目标**：实现事件生效判定逻辑和奖励倍率计算。

**变更文件**：
- `services/ops/app/core/event_engine.py` - 新建文件

**实现内容**：
1. EventEngine 类
2. 功能：
   - is_event_active：判断事件是否在生效时间内
   - get_applicable_events：获取玩家在指定场景下适用的所有事件
   - calculate_reward_multiplier：计算奖励倍率（经验、贡献度、声望等）
   - apply_event_rewards：应用事件奖励
   - validate_event_config：校验事件配置合法性

### 步骤 4：新增运营事件配置 API

**目标**：提供运营侧事件配置与管理接口。

**变更文件**：
- `services/ops/app/api/routes.py` - 新增事件管理端点
- `services/ops/app/schemas/ops.py` - 新增事件相关 Schema

**实现内容**：
1. POST /ops/events - 创建运营事件
2. GET /ops/events - 事件列表（分页，支持过滤）
3. GET /ops/events/{event_id} - 事件详情
4. PUT /ops/events/{event_id} - 更新事件配置
5. POST /ops/events/{event_id}/activate - 激活事件
6. POST /ops/events/{event_id}/pause - 暂停事件
7. POST /ops/events/{event_id}/end - 结束事件
8. DELETE /ops/events/{event_id} - 删除/归档事件
9. GET /ops/events/active - 获取当前生效事件
10. GET /player/events/active - 玩家查询当前生效事件（player scope）

### 步骤 5：新增错误码、业务指标与审计动作

**目标**：补充事件配置相关的错误码、指标和审计。

**变更文件**：
- `services/ops/app/core/errors.py` - 新增错误码
- `services/ops/app/core/metrics.py` - 新增业务指标
- `services/ops/app/repositories/audit_repo.py` - 新增审计动作常量

**实现内容**：
1. 错误码：
   - EVENT_NOT_FOUND（事件不存在）
   - EVENT_NAME_EXISTS（事件名称已存在）
   - INVALID_EVENT_STATUS（无效的事件状态）
   - EVENT_TIME_OVERLAP（事件时间重叠）
   - INVALID_EVENT_CONFIG（事件配置无效）
2. 业务指标：
   - ops_events_created_total（事件创建数）
   - ops_events_active_count（当前生效事件数 Gauge）
   - ops_event_triggers_total（事件触发次数，按类型标签）
3. 审计动作：
   - ACTION_EVENT_CREATE
   - ACTION_EVENT_UPDATE
   - ACTION_EVENT_ACTIVATE
   - ACTION_EVENT_PAUSE
   - ACTION_EVENT_END
   - ACTION_EVENT_DELETE
   - RESOURCE_OPS_EVENT
