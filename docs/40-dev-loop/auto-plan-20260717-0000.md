## 任务目标与背景

### 目标
完成 M2 里程碑经济系统完善的核心功能，包括：
1. 玩家间交易系统（点对点交易）
2. 拍卖行系统（挂单交易）
3. 货币流通平衡机制（钱包、手续费、税收）

### 背景
根据项目状态文档，Sprint 9 公测准备阶段已全部完成，M2-01 第三章区域内容和 M2-02 公会任务功能已完成。按照后续迭代规划，M2 里程碑剩余经济系统完善是下一个优先项。

经济系统是游戏内循环的核心支撑，缺少交易和拍卖行功能会导致：
- 玩家无法进行物品交换
- 稀有物品无法流通
- 货币价值无法体现
- 经济系统失衡

## 具体执行步骤

### 步骤 1：交易系统实现（player-service）

#### 1.1 数据模型定义
- 创建 `player_trades` 表：交易记录（trade_id、initiator_id、recipient_id、status、created_at、completed_at）
- 创建 `trade_items` 表：交易物品明细（trade_item_id、trade_id、from_player_id、item_key、quantity、item_type）
- 创建 `trade_coins` 表：交易金币明细（trade_coin_id、trade_id、from_player_id、amount）
- CHECK 约束：status IN ('pending', 'accepted', 'rejected', 'cancelled', 'completed')

#### 1.2 仓储层实现
- TradeRepository：创建交易、查询交易、接受交易、拒绝交易、取消交易、查询交易列表
- TradeItemRepository：添加交易物品、查询交易物品
- TradeCoinRepository：添加交易金币、查询交易金币

#### 1.3 API 端点
- `POST /api/v1/player/trades`：发起交易（玩家侧）
- `GET /api/v1/player/trades`：获取交易列表（玩家侧）
- `GET /api/v1/player/trades/{trade_id}`：获取交易详情（玩家侧）
- `POST /api/v1/player/trades/{trade_id}/accept`：接受交易（玩家侧）
- `POST /api/v1/player/trades/{trade_id}/reject`：拒绝交易（玩家侧）
- `POST /api/v1/player/trades/{trade_id}/cancel`：取消交易（发起方）

#### 1.4 错误码
- TRADE_NOT_FOUND
- TRADE_NOT_PENDING
- CANNOT_ACCEPT_OWN_TRADE
- CANNOT_CANCEL_ACCEPTED_TRADE
- INSUFFICIENT_INVENTORY
- INSUFFICIENT_COINS
- RECIPIENT_NOT_ONLINE

### 步骤 2：拍卖行系统实现（player-service）

#### 2.1 数据模型定义
- 创建 `auction_listings` 表：拍卖挂单（listing_id、seller_id、item_key、item_type、quantity、starting_price、current_price、buyout_price、status、created_at、expires_at、sold_at、buyer_id）
- CHECK 约束：status IN ('active', 'sold', 'expired', 'cancelled')

#### 2.2 仓储层实现
- AuctionRepository：创建拍卖、查询拍卖列表、查询拍卖详情、出价、一口价购买、取消拍卖、过期处理

#### 2.3 API 端点
- `POST /api/v1/player/auction/listings`：创建拍卖挂单（玩家侧）
- `GET /api/v1/player/auction/listings`：浏览拍卖列表（玩家侧）
- `GET /api/v1/player/auction/listings/{listing_id}`：拍卖详情（玩家侧）
- `POST /api/v1/player/auction/listings/{listing_id}/bid`：出价（玩家侧）
- `POST /api/v1/player/auction/listings/{listing_id}/buyout`：一口价购买（玩家侧）
- `POST /api/v1/player/auction/listings/{listing_id}/cancel`：取消拍卖（卖家侧）
- `GET /api/v1/player/auction/my-listings`：我的拍卖（玩家侧）
- `GET /api/v1/player/auction/my-bids`：我的出价（玩家侧）

#### 2.4 错误码
- AUCTION_NOT_FOUND
- AUCTION_NOT_ACTIVE
- BID_TOO_LOW
- ALREADY_HIGHEST_BIDDER
- CANNOT_BID_ON_OWN_AUCTION
- INSUFFICIENT_COINS_FOR_BID
- BUYOUT_PRICE_NOT_SET

### 步骤 3：货币流通平衡机制（player-service）

#### 3.1 钱包系统
- 扩展 Player 模型：添加 `gold_coins` 字段
- 创建 `player_wallet` 表：钱包流水（wallet_id、player_id、transaction_type、amount、balance_before、balance_after、description、created_at）
- TransactionType 枚举：earn、spend、trade_send、trade_receive、auction_sell、auction_buy、fee、tax、gift

#### 3.2 交易手续费
- 配置化手续费率（默认 5%）
- 交易完成时自动扣除手续费
- 手续费流向系统资金池

#### 3.3 税收机制
- 拍卖行成交税率（默认 10%）
- 金币交易税率（默认 2%）
- 税率配置化

#### 3.4 API 端点
- `GET /api/v1/player/wallet`：查询钱包余额（玩家侧）
- `GET /api/v1/player/wallet/transactions`：查询钱包流水（玩家侧）

#### 3.5 错误码
- INSUFFICIENT_GOLD
- MAX_GOLD_EXCEEDED

### 步骤 4：测试编写与验证
- 每个功能模块至少 10 个测试用例
- 覆盖成功路径和异常场景
- 验证交易状态机和数据一致性
