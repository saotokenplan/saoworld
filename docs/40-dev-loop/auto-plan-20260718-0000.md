## 任务目标与背景

### 目标
完成 M3 里程碑首个任务——为 M2 已落地的公会战系统（auto-20260717-0800）和好友协作任务系统（auto-20260717-0800）补齐客户端 UI 与 Manager API 封装，闭合端到端体验。

具体包括：
1. 扩展 `GuildManager` 自动加载单例，新增 9 个公会战 API 方法
2. 扩展 `FriendManager` 自动加载单例，新增 8 个协作任务 API 方法
3. 修复 `FriendManager` 未在 `project.godot` 注册为 autoload 的遗留 bug
4. 创建 `GuildWarPanel` 场景与脚本（公会战列表、详情、记分板、宣战、加入、完成）
5. 创建 `FriendCollabQuestPanel` 场景与脚本（协作任务列表、详情、进度、创建、接受、拒绝、完成）
6. 将 `GuildWarPanel` 集成到 `GuildPanel`（新增「战争」标签页）
7. 将 `FriendCollabQuestPanel` 集成到 `FriendPanel`（新增「协作」标签页）
8. 编写 GUT 测试用例

### 背景
M2 里程碑后端已全部完成（公会战 9 API + 好友协作任务 8 API 共 17 个端点在 auto-20260717-0800 落地），但客户端尚无对应 UI。参照 M2-02 公会任务的客户端落地模式（auto-20260716-1900 / auto-20260716-2000），后端能力落地后需要补齐客户端 Manager 方法和 UI 面板，玩家才能在客户端实际使用这些功能。

`FriendManager` 虽然存在于 `game/scripts/autoload/` 且被 `friend_panel.gd` 当作 autoload 单例使用，但未在 `project.godot` 的 `[autoload]` 段注册，属于遗留 bug，本任务一并修复。

## 具体执行步骤

### 步骤 1：扩展 GuildManager（公会战 API 方法）
- 新增信号：`guild_wars_loaded`、`guild_war_declared`、`guild_war_accepted`、`guild_war_cancelled`、`guild_war_joined`、`guild_war_completed`、`guild_war_scoreboard_loaded`、`guild_war_detail_loaded`
- 新增状态字段：`_active_wars`、`_war_history`、`_current_war_detail`、`_war_scoreboard`
- 新增 9 个 API 方法：
  - `declare_war(defender_guild_id, war_type, reward_config)` → POST /guild/wars
  - `accept_war(war_id)` → POST /guild/wars/{war_id}/accept
  - `cancel_war(war_id)` → POST /guild/wars/{war_id}/cancel
  - `fetch_active_wars()` → GET /guild/wars/active
  - `fetch_war_history(limit, offset)` → GET /guild/wars/history
  - `fetch_war_detail(war_id)` → GET /guild/wars/{war_id}
  - `join_war(war_id, guild_id)` → POST /guild/wars/{war_id}/join
  - `fetch_war_scoreboard(war_id)` → GET /guild/wars/{war_id}/scoreboard
  - `complete_war(war_id)` → POST /guild/wars/{war_id}/complete
- 新增 getter：`get_active_wars`、`get_war_history`、`get_war_detail`、`get_war_scoreboard`
- 扩展 `reset()` 清理新增字段

### 步骤 2：扩展 FriendManager（协作任务 API 方法）并注册 autoload
- 在 `project.godot` 的 `[autoload]` 段新增 `FriendManager="*res://scripts/autoload/FriendManager.gd"`
- 新增信号：`collab_quests_active_loaded`、`collab_quests_pending_loaded`、`collab_quests_history_loaded`、`collab_quest_created`、`collab_quest_accepted`、`collab_quest_rejected`、`collab_quest_progress_updated`、`collab_quest_completed`、`collab_quest_detail_loaded`
- 新增状态字段：`_active_collab_quests`、`_pending_collab_quests`、`_history_collab_quests`、`_current_collab_quest`
- 新增 8 个 API 方法：
  - `create_collab_quest(friend_id, quest_type, title, description, objectives, rewards, expires_at)` → POST /friend/collab-quests
  - `accept_collab_quest(quest_id)` → POST /friend/collab-quests/{quest_id}/accept
  - `reject_collab_quest(quest_id)` → POST /friend/collab-quests/{quest_id}/reject
  - `update_collab_quest_progress(quest_id, progress_data)` → POST /friend/collab-quests/{quest_id}/progress
  - `complete_collab_quest(quest_id)` → POST /friend/collab-quests/{quest_id}/complete
  - `fetch_active_collab_quests()` → GET /friend/collab-quests/active
  - `fetch_pending_collab_quests()` → GET /friend/collab-quests/pending
  - `fetch_collab_quest_history(limit, offset)` → GET /friend/collab-quests/history
- 新增 getter：`get_active_collab_quests`、`get_pending_collab_quests`、`get_history_collab_quests`
- 扩展 `reset()` 清理新增字段

### 步骤 3：创建 GuildWarPanel 场景与脚本
- 场景文件：`game/scenes/ui/social/GuildWarPanel.tscn`
- 脚本文件：`game/scripts/ui/social/guild_war_panel.gd`
- 布局：VBoxContainer 包含
  - 战争列表（ItemList，显示参战双方、状态、类型）
  - 战争详情（VBoxContainer：标题、状态、双方分数、奖励、参战/接受/取消/完成按钮）
  - 记分板（ItemList，显示双方成员击杀/死亡/贡献）
  - 刷新按钮
- 信号：`close_pressed`、`war_selected(war_id)`
- 状态机按钮逻辑：
  - declared（己方宣战）：显示「取消」按钮
  - declared（被宣战）：显示「接受」按钮
  - in_progress：显示「加入」+「完成」按钮
  - completed/cancelled：无操作按钮
- 类型/状态本地化映射

### 步骤 4：创建 FriendCollabQuestPanel 场景与脚本
- 场景文件：`game/scenes/ui/social/FriendCollabQuestPanel.tscn`
- 脚本文件：`game/scripts/ui/social/friend_collab_quest_panel.gd`
- 布局：VBoxContainer 包含
  - 标签切换（进行中 / 待处理 / 历史）
  - 任务列表（ItemList）
  - 任务详情（标题、类型、状态、描述、目标、进度、奖励）
  - 创建协作任务表单（好友ID、类型、标题、描述、按钮）
  - 操作按钮（接受 / 拒绝 / 更新进度 / 完成）
- 信号：`close_pressed`、`quest_selected(quest_id)`
- 状态机按钮逻辑：
  - pending_invite（被邀请）：显示「接受」+「拒绝」按钮
  - active：显示「更新进度」+「完成」按钮
  - completed/failed/expired：无操作按钮
- 类型/状态本地化映射
