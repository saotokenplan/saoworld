## 一、任务目标与背景

`docs/00-governance/project-status.md` 的「当前待办」明确记录：WP3 审核效率监控（M1–M6）已于 2026-07-26 落地（auto-20260726-0121），但**剩余一项**需分离推进：

> ops 看板三字段（auto_pass_rate / review_p95_minutes / manual_intervention_rate）增补待下一轮（services/ops 改造，分离推进，不阻塞本批）。

即：WP3 的核心埋点（review 服务侧 `reviews_total{result,review_type}`、`review_duration_seconds` Histogram、`review_rule_decisions_total`）已就位，但其派生出的三项「审核效率看板」指标尚未在 **ops 看板**（运营控制台）中对外暴露。本任务将这三项指标从 review 的 Prometheus 指标派生出来，并通过 ops 服务的审核统计面板 / 主看板对外提供，补全 WP3 在 ops 侧的最后一环。

三项指标与 `M4-审核效率看板指标定义.md` 口径一致：
- `auto_pass_rate`（K1 通过率 >70%）：自动审核通过率 = 自动审核通过数 / 自动审核总数
- `review_p95_minutes`（K2 耗时 P95 <30min）：审核耗时 P95（分钟），由 `review_duration_seconds` Histogram 近似估算
- `manual_intervention_rate`（K3 人工介入率）：人工审核数 / 审核总数

## 二、具体执行步骤（每步可独立验收）

### 步骤 1：review 服务派生指标纯函数与采集器
- 新增 `services/review/app/core/review_efficiency.py`：
  - `compute_review_efficiency(review_counts, duration)` 纯函数：输入 `(result, review_type)` 计数与耗时 Histogram 桶累计，输出三项指标（None 安全处理）。
  - `histogram_quantile(q, buckets, cumulative)`：基于 Histogram 桶线性插值近似分位数（Prometheus 口径）。
  - `collect_review_efficiency()`：读取 `prometheus_client.REGISTRY` 的 `reviews_total` 与 `review_duration_seconds` 样本，构造输入并调用纯函数。
- **验收**：纯函数单测覆盖 auto_pass_rate / manual_intervention_rate / P95 三类（含边界：无样本返回 None）。

### 步骤 2：review 服务 stats 端点 + schema
- `services/review/app/schemas/review.py` 新增 `ReviewEfficiencyResponse`（三项 + raw）。
- `services/review/app/api/routes.py` 新增 `GET /api/v1/review/stats`（公共路由 `router`，无鉴权，供 ops 内部调用），返回 `collect_review_efficiency()`。
- **验收**：端点集成测试（seed REGISTRY 后断言返回三项字段）。

### 步骤 3：ops 服务 schema 与代理端点接入
- `services/ops/app/schemas/ops.py`：
  - 新增 `ReviewEfficiencyMetrics`（三项，可选默认 None）。
  - `ReviewStatsResponse` 增加 `review_efficiency: ReviewEfficiencyMetrics | None = None`。
  - `DashboardMetrics` 增加 `review_efficiency: ReviewEfficiencyMetrics | None = None`（主看板模型支持）。
- `services/ops/app/api/routes.py` 的 `GET /ops/review/stats` 代理端点：从 review 返回的统计中映射三项字段到 `review_efficiency`。
- **验收**：ops 代理端点测试（mock 客户端返回三项字段 → 响应含 `review_efficiency`）。

### 步骤 4：ops 主看板尽力注入（失败降级）
- `services/ops/app/api/routes.py` 的 `GET /ops/dashboard`：构造 `DashboardMetrics` 后，尽力调用 `ReviewServiceClient().get_review_stats()` 注入 `review_efficiency`；任何异常（review 不可达）静默降级为 None，看板照常返回。
