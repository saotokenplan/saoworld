# Product Agent 技术规范

> 文档状态：draft
> 适用阶段：P2（多代理协同期）
> 维护要求：持续维护

## 职责定义

Product Agent 负责读取目标、玩家反馈和路线图，输出版本需求和优先级。

## 输入

| 输入来源 | 格式 | 说明 |
|---------|------|------|
| 愿景文档 | markdown | 项目长期愿景和目标 |
| 版本状态 | JSON | 当前版本状态和进度 |
| 玩家投票结果 | JSON | 玩家投票数据和结果 |
| 线上数据 | JSON | 玩家行为数据和指标 |
| 问题列表 | JSON | 待修复问题和改进建议 |

## 输出

| 输出产物 | 格式 | 说明 |
|---------|------|------|
| version_brief.md | markdown | 版本需求文档 |
| 优先级矩阵 | JSON | 任务优先级排序 |
| 里程碑计划 | JSON | 版本里程碑和时间线 |

## 核心流程

1. 收集输入数据（愿景、版本状态、投票结果、线上数据、问题列表）
2. 分析当前状态和玩家需求
3. 生成本轮迭代的 version_brief.md
4. 将需求拆分为可执行任务
5. 按优先级排序并生成里程碑计划

## 关键能力

- 需求分析和优先级评估
- 玩家反馈分析
- 版本规划和里程碑制定
- 跨团队协调

## 约束条件

- 输出必须符合项目规范格式
- 任务粒度控制在可执行范围内（每项 < 1 天规模）
- 必须考虑资源限制和依赖关系

## 验收标准

- version_brief.md 包含：本期目标、不做什么、核心指标、关键风险、验收口径
- 优先级矩阵合理，关键任务优先
- 里程碑计划可行，时间线合理
