# 投票功能验收标准

> 版本：v1.0.0
> 创建时间：2026-07-04

## 概述

投票功能验收标准定义了投票系统各功能模块的验收要求和测试用例，确保投票链路的完整性和正确性。

## 投票周期管理验收

### 创建投票周期

**验收要求**：
- 运营可以成功创建投票周期
- 创建时必须包含所有必填字段（chapter_id、starts_at、ends_at、created_by、created_reason）
- 创建后状态为 draft
- 创建成功后返回 vote_cycle_id
- 创建时自动记录审计日志

**测试用例**：
- 正常创建投票周期 ✓
- 创建时缺少必填字段应返回 400 错误 ✓
- 创建时 ends_at <= starts_at 应返回 400 错误 ✓
- 创建成功后审计日志记录正确 ✓

### 计划投票周期

**验收要求**：
- 运营可以将 draft 状态的投票周期计划为 scheduled
- 计划后状态为 scheduled
- 计划成功后记录审计日志

**测试用例**：
- 正常计划投票周期 ✓
- 非 draft 状态的投票周期计划应返回 409 错误 ✓
- 计划成功后审计日志记录正确 ✓

### 开放投票

**验收要求**：
- 运营可以将 scheduled 状态的投票周期开放为 open
- 同一章节下只能有一个 open 状态的投票周期
- 开放后玩家可以提交投票
- 开放成功后记录审计日志

**测试用例**：
- 正常开放投票周期 ✓
- 非 scheduled 状态的投票周期开放应返回 409 错误 ✓
- 同一章节下已有开放投票周期时开放应返回 409 错误 ✓
- 开放成功后玩家可以查询当前投票 ✓
- 开放成功后审计日志记录正确 ✓

### 关闭投票

**验收要求**：
- 运营可以将 open 状态的投票周期关闭为 closed
- 关闭后玩家不能提交投票
- 关闭成功后记录审计日志

**测试用例**：
- 正常关闭投票周期 ✓
- 非 open 状态的投票周期关闭应返回 409 错误 ✓
- 关闭后玩家提交投票应返回 409 错误 ✓
- 关闭成功后审计日志记录正确 ✓

### 结算投票

**验收要求**：
- 运营可以将 closed 状态的投票周期结算为 finalized
- 结算时自动计票并确定获胜候选项
- 获胜候选项状态更新为 selected
- 结算成功后记录审计日志

**测试用例**：
- 正常结算投票周期 ✓
- 非 closed 状态的投票周期结算应返回 409 错误 ✓
- 结算成功后获胜候选项状态为 selected ✓
- 结算成功后投票周期状态为 finalized ✓
- 结算成功后审计日志记录正确 ✓

## 投票提交验收

### 提交投票

**验收要求**：
- 玩家可以成功提交投票
- 提交时必须提供 Idempotency-Key
- 同一玩家在同一周期内只能投一票
- 提交成功后记录审计日志

**测试用例**：
- 正常提交投票 ✓
- 提交时缺少 Idempotency-Key 应返回 400 错误 ✓
- 同一玩家在同一周期内重复投票应返回 409 错误 ✓
- 使用相同 Idempotency-Key 重复提交应返回首次结果 ✓
- 提交成功后审计日志记录正确 ✓

### 投票资格校验

**验收要求**：
- 玩家必须满足投票资格才能提交投票
- 玩家必须存在
- 投票周期必须存在且状态为 open
- 候选项必须存在且状态为 active

**测试用例**：
- 投票周期不存在时提交应返回 404 错误 ✓
- 投票周期状态不为 open 时提交应返回 409 错误 ✓
- 候选项不存在时提交应返回 404 错误 ✓
- 候选项状态不为 active 时提交应返回 409 错误 ✓
- 玩家不存在时提交应返回 403 错误 ✓

### 投票权重

**验收要求**：
- 投票权重默认值为 1.0
- 投票权重范围为 0 < weight <= 10.0
- 权重超过范围时应返回错误

**测试用例**：
- 使用默认权重提交投票 ✓
- 使用合法权重（0.5-10.0）提交投票 ✓
- 权重 <= 0 时提交应返回 400 错误 ✓
- 权重 > 10.0 时提交应返回 400 错误 ✓

## 投票结算验收

### 计票逻辑

**验收要求**：
- 结算时正确统计每个候选项的投票数（考虑权重）
- 加权总分最高的候选项为获胜者
- 计票结果正确写入数据库

**测试用例**：
- 单个候选项投票统计正确 ✓
- 多个候选项投票统计正确 ✓
- 加权投票统计正确 ✓
- 获胜候选项确定正确 ✓

### 结算幂等性

**验收要求**：
- 同一投票周期多次结算只执行一次
- 已结算的投票周期再次结算应返回已有结果

**测试用例**：
- 同一投票周期多次调用结算接口只执行一次 ✓
- 已 finalized 状态的投票周期再次结算应返回已有结果 ✓

## 性能验收

### 响应时间

**验收要求**：
- 投票提交接口 p95 响应时间 < 300ms
- 投票查询接口 p95 响应时间 < 100ms
- 结算操作响应时间 < 5 秒

**测试用例**：
- 投票提交接口响应时间测试 ✓
- 投票查询接口响应时间测试 ✓
- 结算操作响应时间测试 ✓

### 并发处理

**验收要求**：
- 支持高并发投票（建议 > 1000 QPS）
- 大量投票记录时结算性能正常

**测试用例**：
- 高并发投票测试 ✓
- 大量投票记录结算测试 ✓

- 权限不足请求应返回 403 错误
- Token 过期请求应返回 401 错误

**测试用例**：
- 未认证请求返回 401 错误 ✓
- 权限不足请求返回 403 错误 ✓
- Token 过期请求返回 401 错误 ✓

### 幂等性

**验收要求**：
- 同一 Idempotency-Key 重复提交只执行一次
- 幂等键全局唯一

**测试用例**：
- 同一 Idempotency-Key 重复提交只执行一次 ✓
- 不同 Idempotency-Key 可以正常提交 ✓

### 风控

**验收要求**：
- 设备指纹校验正常
- 频率限制正常

**测试用例**：

- 频率限制测试 ✓

## 状态机验收

### 投票周期状态迁移

**验收要求**：
- 状态迁移必须遵循合法路径
- 非法状态迁移应返回 409 错误

**测试用例**：
- draft → scheduled 合法 ✓
- scheduled → open 合法 ✓
- open → closed 合法 ✓
- closed → finalized 合法 ✓
- draft → open 非法 ✓
- open → draft 非法 ✓
- finalized → closed 非法 ✓

### 候选项状态迁移

**验收要求**：
- 状态迁移必须遵循合法路径
- 非法状态迁移应返回 409 错误

**测试用例**：
- active → selected 合法 ✓
- active → withdrawn 合法 ✓
- selected → active 非法 ✓

## 数据一致性验收

### 唯一性约束

**验收要求**：
- 同一章节下同时只能有一个 open 状态的投票周期
- 同一玩家在同一周期内只能投一票
- 幂等键全局唯一

**测试用例**：
- 同一章节下创建多个 open 状态投票周期应失败 ✓
- 同一玩家在同一周期内投多票应失败 ✓
- 使用相同幂等键提交多次应失败 ✓

### 外键约束

**验收要求**：
- 投票记录的 player_id 必须存在
- 投票记录的 candidate_id 必须存在
- 投票记录的 vote_cycle_id 必须存在

**测试用例**：
- 使用不存在的 player_id 投票应失败 ✓
- 使用不存在的 candidate_id 投票应失败 ✓
- 使用不存在的 vote_cycle_id 投票应失败 ✓
