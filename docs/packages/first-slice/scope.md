# 需求范围界定

> 版本：v1.0.0
> 创建时间：2026-07-04

## 包含功能

### 投票周期管理
- 创建投票周期（draft）
- 计划投票周期（scheduled）
- 开放投票（open）
- 关闭投票（closed）
- 确认结果（finalized）
- 投票周期状态迁移校验

### 投票提交
- 查询当前开放的投票周期与候选项
- 玩家提交投票
- 投票资格校验
- 重复投票保护（一人一票）
- 幂等键处理
- 设备指纹与风控

### 投票结算
- 关闭投票时自动计票
- 加权总分计算
- 确定获胜候选项
- 标记当选候选项

### 投票结果展示
- 查询当前投票周期状态
- 查询历史投票结果
- 展示总票数与各候选项占比
- 展示上一轮投票结果的实际落地情况

### 审计日志
- 投票提交审计记录
- 投票周期创建审计记录
- 投票周期状态迁移审计记录
- 投票结算审计记录

## 不包含功能

以下功能不属于本需求包范围，将在后续版本中逐步纳入：

- 世界区域管理
- 任务系统
- AI 内容生成
- 内容审核
- 内容发布与回滚
- 玩家角色管理
- 声望系统
- 经济系统
- 战斗系统

## 产品边界约束

### 投票规则约束
- 每期候选项数量为 3-5 个
- 票权修正倍率不得超过 1.2
- 投票周期建议按周或双周
- 同一章节下同时只能有一个开放的投票周期

### MVP 范围约束
- 首期只包含 1 个核心常驻区域
- 首期只包含 1 个扩展区域
- 首期只包含 1 条主线骨架
- 首期只包含 3 个候选剧情方向

### 非目标
- 不支持玩家自由输入任意内容后直接生成上线
- 不追求首期就实现真正无限地图
- 不把主线终局、底层经济和核心战斗规则交给 AI 自由生成
- 不把投票系统做成脱离主玩法的独立运营活动

## 服务边界约束

- `vote-service` 不直接修改世界状态，只输出结果
- 客户端不得直接访问生成和审核内部接口
- 内容发布只能由 `content-service` 执行

## 数据边界约束

- `votes` 表为 append-only，不允许 UPDATE 和 DELETE
- 幂等键（`idempotency_key`）必须全局唯一
- 所有写操作必须携带 `trace_id`
- 审计日志表按月做范围分区，应用账号只授予 INSERT/SELECT 权限
